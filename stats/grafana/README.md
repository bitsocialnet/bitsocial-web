## Bitsocial Grafana

This directory contains the Grafana dashboards and provisioning files for `stats.bitsocial.net`.

### Dashboards

- **Bitsocial Stats** (`bitsocial-stats.json`, served at `/`): network overview with headline numbers across 5chan and Seedit, activity per client, the peer map, Bitsocial service uptime, and the client infrastructure used in pure P2P mode (HTTP routers and Ethereum name-resolution RPCs). Response times and the gateway-mode fallback providers sit in collapsed rows.
- **5chan Stats** (`5chan-stats.json`, served at `/5chan`) and **Seedit Stats** (`seedit-stats.json`, served at `/seedit`): per-client views with a sortable table of every default community, activity charts, a collapsed availability history, and one collapsed row per community with its own availability, posts, active users, and pubsub peers.

"Total posts" and "Current users" use the 5chan homepage definitions: posts plus replies, and addresses that posted in the last 7 days summed per community. A text panel at the top of each dashboard links the shared views. The peer map draws countries from the GeoJSON bundled with Grafana, so it needs no third-party map tiles or API key.

### Regenerating dashboards

The checked-in dashboards are generated by [`scripts/build-dashboards.mjs`](./scripts/build-dashboards.mjs) from the current default community lists and the monitor configuration in [`stats/monitor/config.js`](../monitor/config.js):

```bash
yarn build:stats-dashboards
```

The generation step fetches the active 5chan directory files and defaults from `https://github.com/bitsocialnet/lists/tree/master/5chan-directories` (skipping hidden files such as `/trash/`) and Seedit's `seedit-default-subscriptions.json` from the same repo, refreshes the monitor snapshots in `stats/monitor/data/` from those responses, and rebuilds the dashboard JSON so community names, community counts, and service/provider lists stay aligned with what the monitor checks. Edit the generator rather than the generated JSON.

The `upstream/` directory keeps the exported plebbit reference dashboards the original port was based on. The generator no longer reads them.

### Running locally

Start the full local stack with Docker running (on macOS it starts Docker Desktop if needed):

```bash
yarn start:stats
```

It creates `stats/.env` from `stats/.env.example` when missing, starts the containers, waits for Grafana to publish the shared dashboards, and opens `https://stats.bitsocial.localhost` (branch-scoped in worktrees) through Portless. That URL applies the same `/`, `/5chan`, and `/seedit` redirects as the production Caddyfile. Ctrl+C stops the containers; their data stays in the Docker volumes. Set `PORTLESS=0` to skip Portless, or use `yarn stats:up` / `yarn stats:down` to manage the Compose stack directly.

Useful local URLs:

- Grafana login: `http://127.0.0.1:3300/login`
- Public summary dashboard: `http://127.0.0.1:3300/public-dashboards/e9277bcc0c421ddcacd29f591466678c`
- Public 5chan dashboard: `http://127.0.0.1:3300/public-dashboards/fa6f2225e0ea98e116fb6f85d84e0186`
- Public Seedit dashboard: `http://127.0.0.1:3300/public-dashboards/c770d7565c18df52dd26461c9191e05d`
- Prometheus targets: `http://127.0.0.1:9091/targets`
- Monitor JSON API: `http://127.0.0.1:3301/`

Local Grafana admin credentials come from `stats/.env` and are reused by the `grafana-bootstrap` job.
