# Bitsocial และ Urbit

[Urbit](https://urbit.org/) คือเครือข่ายของเซิร์ฟเวอร์ส่วนตัว ผู้ใช้แต่ละคนมีคอมพิวเตอร์ที่เปิดอยู่ตลอดเวลาซึ่งเรียกว่า ยาน
(ship) ยานแต่ละลำรันระบบปฏิบัติการของ Urbit เอง (Arvo) ที่เขียนด้วยภาษาของ Urbit เอง (Nock และ Hoon)
และระบุตัวตนด้วย Urbit ID แอปโซเชียลหลักของ Urbit คือ [Tlon Messenger](https://tlon.io/) ซึ่งสร้างโดย Tlon
บริษัทที่ก่อตั้งขึ้นในปี 2013 เพื่อพัฒนา Urbit

Urbit ตั้งเป้าจะแทนที่สแตกการประมวลผลทั้งหมด จึงเป็นโปรเจกต์ที่กว้างกว่า Bitsocial มาก แต่ชั้นโซเชียลของ Urbit
ใช้โมเดลที่ใกล้เคียงกับของ Bitsocial คือชุมชนอยู่บนโหนดของเจ้าของ และโหนดนั้นเป็นผู้ตัดสินว่าอะไรจะเข้ามาได้
ทั้งสองต่างกันในเรื่องที่ว่าใครต้องรันเซิร์ฟเวอร์ และกันสแปมออกไปด้วยวิธีใด

## Urbit ทำงานอย่างไร

- **Urbit ID** ยานทุกลำมี Urbit ID ซึ่งเป็นตัวเลขที่แสดงเป็นชื่อที่ออกเสียงได้ เช่น `~sampel-palnet` ID บนเลเยอร์ 1
  เป็น NFT ที่บันทึกความเป็นเจ้าของและกุญแจสาธารณะสำหรับเครือข่ายไว้ในสัญญา Azimuth บน Ethereum ส่วน ID บนเลเยอร์ 2
  ซึ่งเพิ่มเข้ามาในปี 2021 เพื่อลดค่าธรรมเนียม ใช้ "naive rollup" คือธุรกรรมของ ID เหล่านี้ถูกโพสต์ขึ้น Ethereum เป็นชุด
  แต่ความเป็นเจ้าของไม่ได้จัดเก็บไว้ในสัญญา Azimuth และยานแต่ละลำคำนวณความเป็นเจ้าของนั้นเองภายในเครื่อง Tlon รัน
  roller ที่เปิดให้ทุกคนใช้ได้ฟรี ตาม [เอกสาร Urbit ID](https://docs.urbit.org/urbit-id/what-is-urbit-id)
  และคู่มือ [Get on Urbit](https://docs.urbit.org/get-on-urbit)
- **ลำดับชั้นที่ตายตัว** พื้นที่ที่อยู่มีกาแล็กซี 256 แห่ง ดาวฤกษ์ 65,536 ดวง และดาวเคราะห์ราว 4
  พันล้านดวงสำหรับใช้งานประจำวัน กาแล็กซีออกดาวฤกษ์ ดาวฤกษ์ออกดาวเคราะห์
  และดาวเคราะห์แต่ละดวงออกดวงจันทร์ให้อุปกรณ์ของตนเองได้ ดาวหางคือ ID
  ฟรีที่ยานสร้างขึ้นเองสำหรับตัวเองและไม่เคยแตะบล็อกเชนเลย เจ้าของกาแล็กซีรวมกันเป็น Galactic Senate
  ซึ่งลงคะแนนเรื่องการอัปเกรดสัญญา Azimuth และเลือกคณะกรรมการของ Urbit Foundation
- **เครือข่าย** ยานแลกเปลี่ยนแพ็กเก็ตที่เข้ารหัสกันแบบเพียร์ทูเพียร์ ตั้งแต่เดือนกรกฎาคม 2026 โปรโตคอลเครือข่ายคือ
  [Directed Messaging](https://urbit.org/blog/directed-messaging) ซึ่งเป็นการเขียนโปรโตคอล Ames
  รุ่นเก่าขึ้นใหม่โดยยึดเนื้อหาเป็นศูนย์กลาง กาแล็กซีทำหน้าที่ค้นหาเพียร์ โดยแต่ละกาแล็กซีคอยติดตามว่ายานที่อยู่ใต้ตนอยู่ที่ใด
  และส่งต่อแพ็กเก็ตไปให้จนกว่ายานทั้งสองลำจะติดต่อกันได้โดยตรง หรือตลอดช่วงที่ไฟร์วอลล์ยังขวางไว้ ตาม
  [บทความเรื่อง Directed Messaging](https://urbitsystems.tech/article/v03-i01/directed-messaging)
- **กลุ่ม** ใน Tlon Messenger กลุ่มจะถูกโฮสต์บนยานของผู้สร้างกลุ่ม สมาชิกส่งข้อความไปยังโฮสต์
  ซึ่งกระจายข้อความไปยังยานของสมาชิกทุกคน และยานของสมาชิกแต่ละคนเก็บสำเนาของตนเองไว้ ตาม
  [FAQ ของ Tlon](https://tlon.io/posts/faq) โฮสต์ควบคุมบทบาท แชนเนล และการรับสมาชิก กลุ่มเป็นแบบสาธารณะ
  ส่วนตัว หรือลับก็ได้ และสามารถ
  [แบนยานทีละลำหรือแบน ID ทั้งระดับชั้น](https://github.com/tloncorp/tlon-apps/blob/develop/desk/sur/groups.hoon)
  แชนเนลอาจเป็นแชต สมุดบันทึก หรือคอลเลกชันรูปภาพและลิงก์
- **การโฮสต์** การสมัครกับ Tlon จะทำให้ผู้ใช้ใหม่ได้ยานที่ Tlon เป็นผู้รัน โดย Tlon เป็นผู้ดูแลเก็บรักษากุญแจไว้ให้
  ผู้ใช้สามารถส่งออกยานพร้อม master ticket (กุญแจหลัก) ของยานไปรันที่อื่นได้ ไม่ว่าจะบนอุปกรณ์ของ
  [Native Planet](https://www.nativeplanet.io/) หรือด้วยรันไทม์ Vere บน Linux, macOS หรือ Windows
  ยานยังจัดเก็บไฟล์ขนาดใหญ่โดยตรงไม่ได้ Tlon Messenger จึงเก็บรูปภาพและสื่ออื่น ๆ ไว้ในคลาวด์สตอเรจที่รองรับ S3

## จุดที่ต่างกัน

### ใครต้องรันเซิร์ฟเวอร์

บน Urbit ผู้เข้าร่วมทุกคนคือเซิร์ฟเวอร์ แอปของ Tlon เป็นฟรอนต์เอนด์ของยานของผู้ใช้เอง แม้แต่การอ่านกลุ่มก็ต้องผ่านยานลำนั้น
คนที่ไม่ได้รันยานเองจะเช่ายานมาใช้ ซึ่งทำให้ผู้ให้บริการโฮสติ้งกลับเข้ามาอยู่ในภาพอีกครั้ง Tlon ถือกุญแจของผู้ใช้ที่ตนโฮสต์ให้
และคงสิทธิ์เข้าถึงแบบจำกัดไว้เพื่อการบำรุงรักษา แม้ว่าผู้ใช้จะย้ายออกไปพร้อมยานทั้งลำได้ก็ตาม

บน Bitsocial มีเพียงเจ้าของชุมชนที่ต้องมีโหนดที่เปิดอยู่ตลอดเวลา ผู้อ่านและผู้โพสต์รันโหนดเพียร์ทูเพียร์ภายในแท็บเบราว์เซอร์ได้
และบัญชีของพวกเขาคือคู่กุญแจที่แอปเก็บไว้ ดู [เพียร์ทูเพียร์ในเบราว์เซอร์](/browser-p2p/) แม้ในกรณีที่มีคนใช้โหนดที่โฮสต์ไว้ให้
การออกแบบของ Bitsocial ก็มุ่งให้พวกเขามอบหมายเรื่องการออนไลน์ตลอดเวลาให้ผู้อื่นได้
โดยไม่ต้องยกการครอบครองตัวตนให้ไปด้วย ดู [อัตลักษณ์และความเป็นเจ้าของชุมชน](/identity-and-ownership/)

### โฮสต์ของชุมชน

นี่คือจุดที่ทั้งสองใกล้เคียงกันที่สุด ทั้งกลุ่มของ Tlon และชุมชนของ Bitsocial ต่างอยู่บนโหนดของเจ้าของ
โฮสต์เป็นผู้ตัดสินว่าใครโพสต์ได้ บังคับใช้การกลั่นกรอง และกระจายผลลัพธ์ออกไป และไม่มีโปรโตคอลใดวางผู้ดูแลไว้เหนือโฮสต์
ทั้งสองระบบต้องให้โฮสต์ออนไลน์อยู่ FAQ ของ Tlon ระบุว่าหากโฮสต์ออฟไลน์ "กลุ่มก็จะล่มไปพร้อมกับพวกเขา" และชุมชนของ
Bitsocial ก็รับโพสต์ใหม่ไม่ได้ในขณะที่โหนดของชุมชนออฟไลน์

ทั้งสองจัดเก็บเนื้อหาต่างกัน ยานของสมาชิกทุกคนเก็บสำเนาประวัติของกลุ่มไว้ สมาชิกจึงยังอ่านสิ่งที่ได้รับมาแล้วได้ในขณะที่โฮสต์ล่ม
ผู้อ่าน Bitsocial ดึงสถานะล่าสุดของชุมชนจากโหนดของชุมชนหรือจากเพียร์ที่ซีดชุมชนนั้น
ชุมชนที่ออฟไลน์จึงยังอ่านได้ตราบที่เพียร์ยังมีข้อมูลอยู่ แต่เครือข่ายเก็บไว้เฉพาะสถานะล่าสุด

กลุ่มของ Tlon ยังมีรายชื่อสมาชิก และโฮสต์ตั้งให้กลุ่มเข้าได้เฉพาะผู้ได้รับเชิญได้ ชุมชนของ Bitsocial ไม่มีระบบสมาชิก
ใครก็อ่านได้ และใครก็ลองโพสต์ได้ โดยต้องผ่านชาเลนจ์ของชุมชนนั้น

### สแปมและตัวตน

Urbit ต่อสู้กับสแปมด้วยการทำให้ตัวตนเป็นของหายาก จำนวนดาวเคราะห์ถูกกำหนดไว้ตายตัว และดาวเคราะห์ทุกดวงออกโดยดาวฤกษ์
ดาวหางที่ได้ฟรีทำให้เลี่ยงความขาดแคลนนี้ได้ กลุ่มที่ต้องการให้ความขาดแคลนนี้ยังได้ผลจึงไม่รับดาวหาง เอกสารของ Urbit
ระบุว่าบางกลุ่มปฏิเสธดาวหาง และกลุ่มของ Tlon แบนดาวหางทั้งระดับชั้นได้ด้วยการตั้งค่าเพียงรายการเดียว
เมื่อกันดาวหางออกไปแล้ว ผู้ใช้ที่ถูกแบนต้องได้ดาวเคราะห์ดวงอื่นจากเจ้าของดาวฤกษ์จึงจะกลับมาได้
ชื่อเสียงก็ไหลตามลำดับชั้นได้เช่นกัน โดย Azimuth มีสัญญา Censures ที่ให้กาแล็กซีและดาวฤกษ์ติดธง ID ได้
เนื่องจากความขาดแคลนถูกสร้างไว้ในพื้นที่ที่อยู่ตั้งแต่ต้น มันจึงทำงานแบบเดียวกันในทุกกลุ่มที่ไม่รับดาวหาง

ตัวตนของ Bitsocial คือคู่กุญแจที่ได้ฟรี แต่ละชุมชนเลือกชาเลนจ์ของตนเองก่อนจะยอมรับโพสต์ เช่น แคปต์ชา การชำระเงิน
ยอดคงเหลือโทเค็น หรือรายการที่อนุญาต และชุมชนอื่นก็เลือกต่างออกไปได้ ดู
[ความท้าทายในการต่อต้านสแปมแบบกำหนดเอง](/custom-challenges/)

### บล็อกเชนและการกำกับดูแล

ชั้นตัวตนของ Urbit พึ่งพา Ethereum สัญญา Azimuth บันทึกความเป็นเจ้าของและกุญแจเครือข่ายของเลเยอร์ 1 ธุรกรรมเลเยอร์ 2
ถูกโพสต์ขึ้น Ethereum เป็นชุด และ Galactic Senate อัปเกรดสัญญาที่ควบคุม Azimuth ได้ กาแล็กซี 256
แห่งชุดเดียวกันนี้ยังทำหน้าที่ค้นหาเพียร์และส่งต่อแพ็กเก็ตด้วย
ชุดตัวตนที่ตายตัวชุดหนึ่งจึงรับทั้งการกำกับดูแลและส่วนหนึ่งของการกำหนดเส้นทางในเครือข่าย

ตัวตนของ Bitsocial คือคู่กุญแจที่ไม่ต้องลงทะเบียน ชื่อ `.bso` และ `.eth` เป็นชื่อแทนแบบเลือกได้ที่ชี้ไปยังคู่กุญแจเหล่านั้น
การค้นหาเพียร์ทำผ่านเราเตอร์ HTTP ที่ส่งคืนเพียงที่อยู่ของผู้ให้บริการ ใครก็รันเราเตอร์ได้
และไคลเอนต์เปลี่ยนเราเตอร์ได้ด้วยการแก้ไขการตั้งค่าของตน

### ขอบเขต

Urbit คือคอมพิวเตอร์อเนกประสงค์ ยานหนึ่งลำโฮสต์ Git remote ฐานความรู้ส่วนตัว หรือเอเจนต์ AI ได้ และ Tlon Messenger
เป็นเพียงหนึ่งในโปรแกรมมากมาย การพัฒนาสำหรับ Urbit ส่วนใหญ่หมายถึงการเขียนแอป Hoon สำหรับ Arvo ส่วน Bitsocial
เป็นโปรโตคอลสำหรับชุมชนสาธารณะ มีแอปอย่าง [5chan](/apps/5chan/) และ [Seedit](/apps/seedit/) Bitsocial
ทำงานบนสแตกที่มีอยู่แล้ว (libp2p, IPFS และเบราว์เซอร์) โดยไม่ได้เข้าไปแทนที่สแตกนั้น
และไคลเอนต์ของมันสร้างด้วยเครื่องมือเว็บทั่วไป ดู [สร้างไคลเอนต์ของคุณเอง](/build-your-own-client/)

### ข้อความส่วนตัว

นี่คือจุดที่ Urbit แข็งแกร่งกว่า ข้อความส่วนตัว (DM) ส่งจากยานลำหนึ่งตรงไปยังอีกลำ ทราฟฟิกทั้งหมดระหว่างยานถูกเข้ารหัส
และกลุ่มเป็นแบบส่วนตัวหรือลับได้ Tlon ระบุว่าข้อความถูกเข้ารหัสระหว่างการส่ง แต่จัดเก็บบนยานแบบไม่เข้ารหัส Bitsocial
มุ่งเน้นชุมชนสาธารณะ และยังไม่มีข้อความส่วนตัวในตัว

## สถานะของโปรเจกต์

Urbit ผ่านความปั่นป่วนมาแล้ว ในเดือนสิงหาคม 2024 Urbit Foundation องค์กรไม่แสวงกำไรที่กำกับทิศทางการพัฒนาแกนหลัก
ได้ไล่ผู้อำนวยการบริหารออก ผู้ก่อตั้ง Curtis Yarvin กลับมานำด้านกลยุทธ์โดยไม่มีตำแหน่งอย่างเป็นทางการ
นักพัฒนาแกนหลักหลายคนลาออก และเงินทุนของมูลนิธิเหลือพอใช้ได้อีกเพียงไม่กี่เดือน ตามที่
[CoinDesk รายงาน](https://www.coindesk.com/tech/2024/08/21/wartime-ceo-urbits-founder-returns-in-shakeup-at-moonshot-software-project)
