# Bitsocial และ Lapis Net

[Lapis Net](https://net.lapisproject.dev/) คือโปรโตคอลโซเชียลเน็ตเวิร์กแบบเพียร์ทูเพียร์ที่เขียนด้วย
Kotlin สำหรับ JVM โปรเจกต์นี้ได้รากฐานที่ใกล้เคียงกับ Bitsocial มาโดยอิสระ ได้แก่ ตัวตนแบบคู่กุญแจ
การจัดเก็บเนื้อหาแบบ IPFS และ libp2p gossipsub
ทั้งสองต่างกันตรงที่วางการกรองสแปมและการคัดสรรเนื้อหาไว้คนละจุด Lapis
ให้ผู้อ่านแต่ละคนมีกราฟความน่าเชื่อถือส่วนตัว และให้การชำระเงินด้วย Bitcoin และ Lightning
ช่วยเพิ่มการมองเห็นได้ ส่วน Bitsocial ให้แต่ละชุมชนตัดสินใจเองว่าอะไรเผยแพร่ได้

Lapis เป็นต้นแบบที่ใช้งานได้ ตาม
[รีโพซิทอรีของโปรเจกต์](https://github.com/lapisproject-dev/Lapis-Net) ในเดือนตุลาคม 2026 Lapis
ยังไม่มีเครือข่ายสาธารณะ และการเชื่อมต่อสองโหนดเข้าด้วยกันยังต้องทำเอง

## Lapis ทำงานอย่างไร

- **ตัวตน** ตัวตนแต่ละรายการคือคู่กุญแจ secp256k1 ที่เข้ากันได้กับกุญแจของ Bitcoin โดยมีกุญแจ
  Ed25519 ผูกไว้สำหรับ peer ID ของ libp2p
- **การจัดเก็บและการเผยแพร่** เนื้อหาจัดเก็บด้วย Nabu ซึ่งเป็นอิมพลีเมนเทชันของ IPFS บน libp2p (DHT
  และ Bitswap) และกระจายด้วย libp2p gossipsub
- **การให้คะแนน** มีคะแนนเสริมสี่ตัวที่อยู่บนแกนกลางซึ่งเป็นกลางในเรื่องการคัดสรรเนื้อหา:
  - Veritas เครือข่ายความน่าเชื่อถือที่คำนวณจากกราฟความน่าเชื่อถือของผู้อ่านแต่ละคนเอง
  - Virtus การมองเห็นที่หนุนด้วยหลักฐานการชำระเงินบนเชนหรือผ่าน Lightning ซึ่งลดค่าลงตามเวลา
  - Karma ไลก์ฟรีที่ถ่วงน้ำหนักด้วย Veritas
  - Madli คะแนนชื่อเสียงที่โหนดบันทึกเกี่ยวกับพฤติกรรมของกันและกัน
- **การรับส่งข้อความ** ข้อความส่วนตัวที่เข้ารหัสแบบต้นทางถึงปลายทาง การโทรด้วยเสียงแบบตัวต่อตัว
  และระบบข้อความแบบอะซิงโครนัสคล้ายอีเมล เป็นส่วนหนึ่งของโปรเจกต์
- **ไคลเอนต์** ผู้ใช้แต่ละคนรันโหนด JVM
  ไคลเอนต์อ้างอิงคือเว็บอินเทอร์เฟซที่โหนดในเครื่องนั้นให้บริการ

## จุดที่ต่างกัน

### ใครเป็นผู้กรองสแปม

Lapis กรองที่ฝั่งผู้อ่าน เนื้อหาถูกกระจายออกไปก่อน จากนั้นกราฟความน่าเชื่อถือของผู้อ่านแต่ละคน
และกฎการชำระเงินของแอปที่ผู้อ่านใช้ เป็นตัวตัดสินว่าอะไรจะปรากฏขึ้นมา Bitsocial กรองที่ชุมชน
โพสต์ต้องผ่านชาเลนจ์ของชุมชนก่อนที่โหนดของชุมชนจะยอมรับ
สแปมที่ถูกปฏิเสธจึงไม่มีวันกลายเป็นส่วนหนึ่งของชุมชน ดู
[ความท้าทายในการต่อต้านสแปมแบบกำหนดเอง](/custom-challenges/)

### ใครถืออำนาจ

ใน Lapis ผู้อ่านแต่ละคนตัดสินใจเองว่าจะเชื่อถือใคร
และผู้ดำเนินการแต่ละแอปตัดสินใจว่าการมองเห็นแบบเสียเงินทำงานอย่างไรในแอปนั้น ใน Bitsocial
เจ้าของชุมชนกำหนดกฎสำหรับชุมชนนั้นเพียงชุมชนเดียว และแอปเลือกเองว่าจะแสดงอะไร
ทั้งสองระบบไม่มีผู้ดูแลระบบระดับโปรโตคอล

### เศรษฐศาสตร์

Lapis ฝังหลักฐานการชำระเงินด้วย Bitcoin และ Lightning ไว้ในคะแนนการมองเห็น Bitsocial
ไม่มีชั้นการชำระเงินในโปรโตคอล แต่ชุมชนกำหนดให้ต้องชำระเงินหรือถือโทเค็นผ่านชาเลนจ์ของตนได้

### เบราว์เซอร์

แอป Bitsocial รันโหนดเพียร์ทูเพียร์ภายในแท็บเบราว์เซอร์ปกติได้ ดู
[เพียร์ทูเพียร์ในเบราว์เซอร์](/browser-p2p/) ส่วนอินเทอร์เฟซเบราว์เซอร์ของ Lapis
คือหน้าเว็บในเครื่องที่โหนด JVM ของผู้ใช้ให้บริการ

### ขอบเขต

Lapis รวมข้อความส่วนตัว การโทรด้วยเสียง และอีเมลไว้ด้วยกัน Bitsocial มุ่งเน้นชุมชนสาธารณะ
และยังไม่มีข้อความส่วนตัวในตัว

## ทั้งสองทำงานร่วมกันได้หรือไม่

ชาเลนจ์ของ Bitsocial เป็นโค้ดอะไรก็ได้ คะแนนความน่าเชื่อถือแบบ Lapis จึงกลายเป็นชาเลนจ์ตัวหนึ่งได้
ชาเลนจ์ `whitelist` ที่มีมาในตัวอ่านรายการที่อยู่ที่ได้รับอนุญาตจาก URL ได้อยู่แล้ว
บริการที่เผยแพร่ที่อยู่ Bitsocial ซึ่งกราฟ Veritas เชื่อถือ อาจช่วยให้ผู้เขียนเหล่านั้นข้าม CAPTCHA
ในชุมชนได้ แต่สิ่งนี้ต้องมีวิธีเชื่อมตัวตน Lapis เข้ากับที่อยู่ Bitsocial
ซึ่งวันนี้ยังไม่มีสิ่งใดแบบนั้น
