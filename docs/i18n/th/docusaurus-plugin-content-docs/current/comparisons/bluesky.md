# Bitsocial และ Bluesky

[Bluesky](https://bsky.app/) คือแอปไมโครบล็อกที่สร้างบน [AT Protocol](https://atproto.com/) ซึ่ง
Bluesky Social PBC เป็นผู้ออกแบบ โปรโตคอลนี้แบ่งโซเชียลเน็ตเวิร์กออกเป็นบริการแยกกัน ได้แก่
เซิร์ฟเวอร์ข้อมูลส่วนบุคคลที่โฮสต์บัญชี รีเลย์ที่รวบรวมบัญชีเหล่านั้นเป็นสตรีมเดียว และ AppView
ที่ทำดัชนีสตรีมนั้นให้กลายเป็นไทม์ไลน์และเธรดที่ผู้คนเห็น
เอกสารของโปรโตคอลอธิบายว่าข้อมูลบัญชีถูกจัดเก็บบนเซิร์ฟเวอร์โฮสต์ “ซึ่งต่างจากโมเดลเพียร์ทูเพียร์”
([ภาพรวม](https://atproto.com/guides/overview))

## AT Protocol ทำงานอย่างไร

- **รีโพซิทอรีบนเซิร์ฟเวอร์** ทุกโพสต์ ไลก์
  หรือการติดตามคือเรคคอร์ดในรีโพซิทอรีที่ลงลายเซ็นของผู้เขียน
  ซึ่งโฮสต์อยู่บนเซิร์ฟเวอร์ข้อมูลส่วนบุคคล (PDS) Bluesky เป็นผู้รันเซิร์ฟเวอร์ค่าเริ่มต้น
  และใครก็โฮสต์เซิร์ฟเวอร์ของตัวเองได้
- **รีเลย์** รีเลย์สมัครรับข้อมูลจาก PDS ทุกตัว แล้วกระจายการเปลี่ยนแปลงต่อเป็นสตรีมเดียวที่เรียกว่า
  firehose นับตั้งแต่การอัปเดตโปรโตคอลในปี 2025 รีเลย์ไม่ได้เก็บถาวรทุกรีโพซิทอรีอีกต่อไป
  ทำให้ต้นทุนการรันลดลงมาก ([Sync v1.1](https://atproto.com/blog/relay-updates-sync-v1-1))
- **AppView** AppView ทำดัชนี firehose ทั้งหมด และให้บริการไทม์ไลน์ เธรดการตอบกลับแบบครบถ้วน
  ตัวเลขนับ และการค้นหา นี่คือส่วนที่ใช้ทรัพยากรมากที่สุดของเครือข่าย
- **ตัวตน** บัญชีคือ DID ซึ่งปกติเป็น `did:plc` ที่ลงทะเบียนในไดเรกทอรีระดับโลกแห่งเดียว หรือ
  `did:web` ที่ผูกกับโดเมน เอกสาร DID ระบุแฮนเดิล กุญแจลงลายเซ็น และเซิร์ฟเวอร์ปัจจุบันของบัญชี PDS
  เป็นผู้ถือกุญแจลงลายเซ็น ส่วน `did:plc` ยังให้ผู้ใช้ถือกุญแจหมุนเวียนเองได้
  เพื่อย้ายออกได้โดยไม่ต้องพึ่งโฮสต์เดิม ([คู่มือตัวตน](https://atproto.com/guides/identity))
- **แฮนเดิล** แฮนเดิลคือชื่อ DNS เช่น `alice.bsky.social` หรือโดเมนที่ผู้ใช้เป็นเจ้าของ
  ซึ่งตรวจสอบกับ DID
- **การกลั่นกรอง** การโฮสต์และการเข้าถึงผู้ชมเป็นชั้นที่แยกจากกัน ใครก็รันบริการติดป้ายกำกับ
  (labeler) ได้ และผู้ใช้ซ้อนบริการหลายตัวเข้าด้วยกันได้
  ([คู่มือการกลั่นกรอง](https://atproto.com/guides/moderation)) แต่แอป Bluesky ใช้การกลั่นกรองของ
  Bluesky เองเสมอ ผู้เขียนจำกัดได้ว่าใครตอบกลับโพสต์ของตนได้ และซ่อนการตอบกลับได้

## จุดที่ต่างกัน

### เซิร์ฟเวอร์หรือเพียร์

ข้อมูลของ Bluesky อยู่บนเซิร์ฟเวอร์ โดย PDS โฮสต์แต่ละบัญชี รีเลย์ส่งต่อ firehose และ AppView
ให้บริการสิ่งที่ไคลเอนต์แสดง เบราว์เซอร์เป็นไคลเอนต์ HTTP ของบริการเหล่านั้น ไม่เคยเป็นเพียร์ ใน
Bitsocial โหนดของชุมชนและเพียร์ที่อ่านชุมชนนั้นเป็นผู้ให้บริการเนื้อหา
และเว็บแอปก็รันโหนดเพียร์ทูเพียร์ของตัวเองได้ ดู [เพียร์ทูเพียร์ในเบราว์เซอร์](/browser-p2p/)

### มุมมองระดับโลกหรือชุมชน

AT Protocol ออกแบบมาเพื่อมุมมองระดับโลกเพียงหนึ่งเดียว AppView เห็นทุกการตอบกลับ
เธรดและการค้นหาจึงครบถ้วน Bitsocial ไม่มีดัชนีระดับโลก แต่ละชุมชนเผยแพร่สถานะของตัวเอง
และแอปสร้างระบบค้นพบไว้ด้านบน ดู [การค้นพบเนื้อหา](/content-discovery/)

ปัจจุบัน Bluesky ยังไม่มีออบเจ็กต์ชุมชนสำหรับโพสต์สาธารณะ ในเดือนมิถุนายน 2026 Bluesky
[ประกาศชุมชนแบบเนทีฟ](https://bsky.app/profile/alexbenzer.com/post/3mnxh6mmlxk2k)
ซึ่งการโพสต์ต้องได้รับอนุมัติในระดับความเป็นส่วนตัวบางระดับ แต่จนถึงเดือนตุลาคม 2026 ก็ยังไม่เปิดตัว
ใน Bitsocial ชุมชนคือออบเจ็กต์หลัก และโหนดของชุมชนเป็นผู้ยอมรับหรือปฏิเสธโพสต์

### การควบคุมสแปม

Bluesky จัดการสแปมด้วยการจำกัดอัตราบนเซิร์ฟเวอร์ของตน การจำกัดโฮสต์ใหม่ที่รีเลย์ การตรวจจับอัตโนมัติ
การตรวจสอบโดยมนุษย์ และป้ายกำกับ และผู้เขียนจำกัดการตอบกลับได้
ไม่มีด่านระดับชุมชนที่ตัดสินว่าโพสต์ต้องผ่านอะไรบ้างก่อนจะถูกยอมรับ ใน Bitsocial
แต่ละชุมชนเลือกชาเลนจ์ของตัวเอง ดู [ความท้าทายในการต่อต้านสแปมแบบกำหนดเอง](/custom-challenges/)

### ใครถือกุญแจ

บัญชีบนเซิร์ฟเวอร์ของ Bluesky เองล็อกอินด้วยรหัสผ่าน
และเซิร์ฟเวอร์เหล่านั้นถือกุญแจลงลายเซ็นของบัญชีไว้แบบคัสโตเดียล
([Kleppmann et al.](https://arxiv.org/abs/2402.03239)) วิศวกรโปรโตคอลคนหนึ่งของ Bluesky ระบุว่า
[บัญชีส่วนใหญ่ไม่มีกุญแจหมุนเวียนที่ควบคุมได้อย่างอิสระ](https://whtwnd.com/bnewbold.net/3lbvbtqrg5t2t)
ตัวตนใน Bitsocial คือคู่กุญแจที่แอปของผู้ใช้สร้างและถือไว้

### การดูแลโครงสร้างพื้นฐาน

เซิร์ฟเวอร์ส่วนบุคคลมีต้นทุนต่ำ [PDS อ้างอิง](https://github.com/bluesky-social/pds) แนะนำ RAM 1 GB
สำหรับผู้ใช้สูงสุด 20 คน ส่วน AppView อิสระที่ครอบคลุมทั้งเครือข่ายเป็นโครงการใหญ่ AppView
ตัวหนึ่งที่สร้างในปี 2025
[มีค่าใช้จ่ายราว 200 ดอลลาร์ต่อเดือน](https://whtwnd.com/futur.blue/3ls7sbvpsqc2w)
ส่วนใหญ่เป็นค่าพื้นที่จัดเก็บ 16 TB Bitsocial ไม่มีดัชนีระดับโลกที่ต้องทำสำเนา
และโหนดชุมชนรันบนฮาร์ดแวร์ระดับผู้บริโภคได้

| ------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| ประเภท              | เซิร์ฟเวอร์แบบเฟเดอเรชันที่มีดัชนีระดับโลก                                     | เครือข่ายชุมชนแบบเพียร์ทูเพียร์                                          |
| ตัวตน               | DID ซึ่งกุญแจลงลายเซ็นมักอยู่กับเซิร์ฟเวอร์                                    | คู่กุญแจ Ed25519 สำหรับผู้ใช้และชุมชน                                    |
| โพสต์อยู่ที่ไหน     | รีโพซิทอรีของผู้เขียนบนเซิร์ฟเวอร์ข้อมูลส่วนบุคคล                              | โหนดของเจ้าของชุมชน และเพียร์ที่อ่านและซีดชุมชนนั้น                      |
| ใครทำให้ออนไลน์อยู่ | โฮสต์ PDS รีเลย์ และ AppView ซึ่งโดยค่าเริ่มต้น Bluesky เป็นผู้รัน             | โหนดของเจ้าของชุมชน พร้อมซีดเดอร์ที่ช่วยกระจาย                           |
| ชุมชน               | ยังไม่มีสำหรับโพสต์สาธารณะ (ประกาศในปี 2026)                                   | ออบเจ็กต์ระดับพื้นฐานที่มีโหนดของตัวเองคอยยอมรับหรือปฏิเสธโพสต์          |
| การควบคุมสแปม       | การจำกัดอัตราบนเซิร์ฟเวอร์ การตรวจจับอัตโนมัติ ป้ายกำกับ การควบคุมการตอบกลับ   | ชาเลนจ์ของแต่ละชุมชนก่อนที่โพสต์จะถูกยอมรับ                              |
| การกลั่นกรอง        | บริการติดป้ายกำกับที่ซ้อนกันได้ และแอป Bluesky ใช้การกลั่นกรองของ Bluesky เสมอ | เจ้าของชุมชนกลั่นกรองชุมชนของตน ส่วนแอปเลือกเองว่าจะแสดงอะไร             |
| ชื่อ                | แฮนเดิล DNS ที่ตรวจสอบกับ DID                                                  | ชื่อ `.bso` และ `.eth` ที่ชี้ไปยังกุญแจ                                  |
| เบราว์เซอร์         | ไคลเอนต์ HTTP ของ PDS และ AppView                                              | โหนดเพียร์ทูเพียร์ภายในแท็บเบราว์เซอร์ปกติ                               |
| ข้อแลกเปลี่ยนหลัก   | เธรดและการค้นหาระดับโลกที่ครบถ้วน แต่การรวบรวมข้อมูลต้องใช้เซิร์ฟเวอร์หนัก ๆ   | ไม่มีดัชนีระดับโลกที่หนักอึ้ง แต่ก็ไม่มีมุมมองที่ครบถ้วนของทั้งเครือข่าย |
