# สกิลและเครื่องมือ

สกิลที่ใช้ร่วมกันอยู่ใน `.agents/skills/` ให้แก้ไขซอร์สเหล่านี้ แล้วรัน `yarn ai-workflow:sync` เพื่อสร้าง `.claude/skills/` สำหรับ Claude Code ส่วน Codex และ Cursor ค้นพบ `.agents/skills/` ได้โดยตรง อย่านำ root ที่ซ้ำซ้อนอย่าง `.codex/skills/` หรือ `.cursor/skills/` กลับมา

พรอมต์ของบทบาทที่ใช้ร่วมกันอยู่ใน `.agents/roles/*.md` นี่เป็นรูปแบบซอร์สเฉพาะของ repo นี้ ไม่ใช่พาธการค้นพบเอเจนต์แบบเนทีฟ `scripts/ai-workflow-files.mjs` แปลงซอร์สเหล่านี้เป็นไฟล์เฉพาะของแต่ละแอปด้านล่าง และ `yarn ai-workflow:sync` เป็นผู้เขียนไฟล์เหล่านั้น ให้คอมมิตไฟล์ที่สร้างขึ้นไปพร้อมกับซอร์สของมัน เพื่อให้การ checkout ใหม่มีการกำหนดค่าแบบเนทีฟพร้อมใช้โดยไม่ต้องรันตัวสร้างก่อน หลังลบซอร์สใด ให้ลบเอาต์พุตที่สร้างจากซอร์สนั้นซึ่งล้าสมัยแล้วอย่างชัดแจ้ง ตัวตรวจสอบจะรายงานไฟล์เหล่านั้นแทนการลบไฟล์ทิ้งอย่างเงียบ ๆ

## พาธการค้นพบแบบเนทีฟ

ตรวจสอบกับเอกสารทางการเมื่อ 2026-09-12:

| แอป         | คำสั่งระดับโปรเจกต์                                                              | สกิลที่ repo นี้ใช้                           | เอเจนต์แบบกำหนดเองที่ repo นี้ใช้        |
| ----------- | -------------------------------------------------------------------------------- | --------------------------------------------- | ---------------------------------------- |
| Codex       | `AGENTS.md`                                                                      | `.agents/skills/<name>/SKILL.md`              | `.codex/agents/<name>.toml` ที่สร้างขึ้น |
| Cursor      | `AGENTS.md` และ `.cursor/rules/*.mdc` ยังใช้ได้สำหรับกฎแบบมีเงื่อนไขเฉพาะ Cursor | `.agents/skills/<name>/SKILL.md`              | `.cursor/agents/<name>.md` ที่สร้างขึ้น  |
| Claude Code | `CLAUDE.md` นำเข้า `@AGENTS.md`                                                  | `.claude/skills/<name>/SKILL.md` ที่สร้างขึ้น | `.claude/agents/<name>.md` ที่สร้างขึ้น  |

แหล่งที่มา: [สกิลของ Codex](https://learn.chatgpt.com/docs/build-skills), [ซับเอเจนต์ของ Codex](https://learn.chatgpt.com/docs/agent-configuration/subagents), [กฎของ Cursor](https://cursor.com/docs/rules), [สกิลของ Cursor](https://cursor.com/docs/skills), [ซับเอเจนต์ของ Cursor](https://cursor.com/docs/subagents), [หน่วยความจำของ Claude](https://code.claude.com/docs/en/memory), [สกิลของ Claude](https://code.claude.com/docs/en/skills), [ซับเอเจนต์ของ Claude](https://code.claude.com/docs/en/sub-agents)

อย่าแทนที่ไดเรกทอรีเอเจนต์แบบเนทีฟด้วย `.agents/roles` หรือสันนิษฐานว่า Claude ค้นพบ `.agents/skills` ได้ Claude ยังอ่านไฟล์ที่ถูกอ้างถึงในนั้นได้ในฐานะคอนเท็กซ์ทั่วไปของโปรเจกต์ Cursor ยังค้นพบ `.claude/skills` เพื่อความเข้ากันได้ด้วย สำเนาต่าง ๆ ยังคงซิงก์กันอยู่ แต่คู่มือสกิลที่ Cursor เผยแพร่ไม่ได้ระบุถึงการตัดรายการซ้ำข้าม root เหล่านี้ ให้ตรวจแค็ตตาล็อกสกิลของแอปที่ติดตั้งอยู่ แทนการรับประกันว่ารายการซ้ำจะไม่ปรากฏ

ไดเรกทอรี AI ใช้การขึ้นบรรทัดใหม่แบบ LF ผ่าน `.gitattributes` เพื่อให้ข้อความที่สร้างขึ้นเหมือนกันทุกแพลตฟอร์ม ไฟล์ประกอบของสกิลจะถูกคัดลอกแบบไบต์ต่อไบต์

## บทบาทและโมเดล

คงบทบาทแบบกำหนดเองไว้สำหรับ `browser-check`, `profiler`, `test-apk`, `translator` และ `reviewer` ใช้บทบาท worker/general-purpose หรือ explorer ที่มีมาในตัวของ harness สำหรับการอิมพลีเมนต์และการค้นหาโค้ดทั่วไป เอเจนต์แม่เป็นผู้กำหนดเกณฑ์การยอมรับและความเป็นเจ้าของ และมีเจ้าของเพียงรายเดียวที่รันการตรวจที่หนัก

ไฟล์เอเจนต์ของ Codex มี `name`, `description` และ `developer_instructions` ส่วน `.codex/config.toml` จำกัดเอเจนต์ลูกที่ทำงานพร้อมกันไว้ที่สี่ตัวด้วย `max_concurrent_threads_per_session` เมทาดาทาของบทบาทที่ใช้ร่วมกันประกอบด้วยชื่อ คำอธิบาย และโหมด sandbox ที่ระบุหรือไม่ก็ได้ และจงใจไม่มีฟิลด์โมเดล

อย่าใส่ฟิลด์โมเดลและ reasoning ในสกิลและเอเจนต์แบบกำหนดเองที่คอมมิตไว้ในทั้งสามแอป วิธีนี้เปิดให้ใช้ตัวเลือกตอนเรียกใช้ขณะรันไทม์ ค่าเริ่มต้นของผู้ใช้ และการสืบทอดจากเอเจนต์แม่ ตามลำดับความสำคัญที่แต่ละแอประบุไว้ในเอกสาร alias ระดับตระกูลโมเดลของ Claude ช่วยลดภาระการดูแลเวอร์ชัน แต่ก็ยังเป็นการเลือกตระกูลอยู่ดี ส่วนโมเดลของ Cursor ที่ระบุเวอร์ชันจะต้องอัปเดตในอนาคต เก็บตัวเลือกเหล่านี้ไว้ในการตั้งค่าของผู้ใช้/เซสชันเมื่อจำเป็น การสืบทอดไม่ได้รับประกันว่าจะเลือกโมเดลที่ดีที่สุดในปัจจุบันให้โดยอัตโนมัติ อย่าคิด alias `latest` ขึ้นเอง หรือเพิ่มการค้นคว้าแค็ตตาล็อกโมเดลเข้าไปในงานประจำ ดู [การเลือกโมเดลของ Codex](https://learn.chatgpt.com/docs/agent-configuration/subagents), [การเลือกโมเดลของ Claude](https://code.claude.com/docs/en/sub-agents#choose-a-model) และ [การเลือกโมเดลของ Cursor](https://cursor.com/docs/subagents#model-configuration)

`sandbox-mode: read-only` แมปไปยัง sandbox ของ Codex และ `readonly` ของ Cursor ส่วนใน Claude รายการเครื่องมือและคำสั่งของบทบาทจะจำกัดเวิร์กโฟลว์การรีวิว แต่การเข้าถึง Bash ไม่ใช่ sandbox ระดับระบบปฏิบัติการ

frontmatter ของสกิลที่ใช้ร่วมกันใช้ `disable-model-invocation: true` สำหรับเวิร์กโฟลว์ที่ผู้ใช้เป็นผู้เรียกใช้ในกรณีที่ใช้ได้ การตั้งค่าที่สอดคล้องกันของ Codex อยู่ใน `agents/openai.yaml` ในรูป `policy.allow_implicit_invocation: false` และตัวตรวจสอบกำหนดให้ต้องมีทั้งสองอย่าง เมทาดาทาการเรียกใช้เป็นส่วนเสริมของกฎการอนุญาตที่ชัดแจ้ง คำขอให้รีวิวไม่ได้อนุญาตให้เผยแพร่เพียงเพราะสกิลมีขั้นตอนการเผยแพร่อยู่

## การตรวจและการค้นพบ

- `yarn ai-workflow:sync` สร้างเอาต์พุตเพื่อความเข้ากันได้ใหม่โดยใช้ `js-yaml` และ `smol-toml` ที่ติดตั้งไว้
- `yarn ai-workflow:check` พาร์สซอร์ส/frontmatter/คอนฟิก และตรวจเอาต์พุตที่สร้างขึ้น เมทาดาทาการเรียกใช้ ตำแหน่งของฟิลด์โมเดล และการเชื่อมต่อ hook ที่ทำหน้าที่จัดรูปแบบเท่านั้น มันไม่ได้ตรวจตัวระบุโมเดลกับแค็ตตาล็อกของผู้ให้บริการ
- `yarn ai-workflow:test` รันฟิกซ์เจอร์ Node แบบแยกส่วนสำหรับเพย์โหลดของ hook และการสร้าง/ตรวจสอบเวิร์กโฟลว์
- หลังอัปเกรดแอปพลิเคชันเอเจนต์ ให้ยืนยันการค้นพบสกิล/บทบาทในแอปพลิเคชันนั้น การตรวจไวยากรณ์/ความสอดคล้องกันไม่ได้มาแทนการตรวจตัวโหลด ให้รีโหลดแอปพลิเคชันหากเซสชันที่มีอยู่ยังคงใช้แค็ตตาล็อกเก่า
- Hooks ต้องผ่านการให้ความเชื่อถือโปรเจกต์และการรีวิว hook ของ harness อย่าข้ามการตรวจความเชื่อถือเพื่อให้การตรวจผ่าน ดู [hooks-setup.md](hooks-setup.md)

## การดูแลคำสั่งให้มีประโยชน์

ปฏิบัติตาม [แนวทางเรื่องสกิลและพรอมต์ของ OpenAI](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) (ทบทวนเมื่อ 2026-09-12) คือเขียนคำอธิบายให้แม่นยำ โหลดรายละเอียดเฉพาะเมื่อเกี่ยวข้อง และรักษาขอบเขตที่ผู้ใช้ร้องขอ สกิลที่ใช้ร่วมกันรองรับโมเดลที่แตกต่างกัน จึงควรคงข้อกำหนดตายตัวเฉพาะของโปรเจกต์ไว้ ขณะที่เปิดให้เลือกวิธีอิมพลีเมนต์ทั่วไปได้เอง

เก็บจุดประสงค์ ขอบเขตการตัดสินใจ และข้อจำกัดที่จำเป็นของสกิลไว้ใน `SKILL.md` ลิงก์คำสั่งหรือตัวอย่างเฉพาะโหมดที่มีเนื้อหามากเป็นเอกสารอ้างอิงเสริม วางเงื่อนไขการทริกเกอร์ไว้ช่วงต้นของคำอธิบายสั้น ๆ คีย์เวิร์ดที่ตรงกันเพียงอย่างเดียวไม่ควรขยายขอบเขตงาน รักษาเมทาดาทาการเรียกใช้ที่มีอยู่ไว้ เว้นแต่ตั้งใจเปลี่ยนพฤติกรรมของมัน

หลังเปลี่ยนคำสั่งอย่างมีนัยสำคัญ ให้ลองใช้คำขอตัวอย่างทั้งขนาดเล็กและขนาดใหญ่สักสองสามรายการ ตรวจว่าสกิล/เอกสารอ้างอิงใดถูกเลือก การกระทำอยู่ในขอบเขตหรือไม่ การตรวจสอบสอดคล้องกับการเปลี่ยนแปลงหรือไม่ และงานที่ได้รับอนุญาตเสร็จสมบูรณ์หรือไม่ การทดสอบ schema และฟิกซ์เจอร์ยืนยันความถูกต้องของเครื่องมือ ไม่ใช่คุณภาพการตัดสินใจของเอเจนต์

## เครื่องมือและความเป็นเจ้าของเบราว์เซอร์

ใช้แค็ตตาล็อกสกิล/เครื่องมือที่มีอยู่และ CLI ของโปรเจกต์ที่ติดตั้งไว้เป็นหลัก ใช้ `gh` สำหรับ GitHub ใช้ `playwright-cli` สำหรับการตรวจสอบผ่านเบราว์เซอร์ และใช้เอกสารทางการ/เฉพาะเวอร์ชันเมื่อพฤติกรรมของไลบรารีมีความสำคัญ หลีกเลี่ยงการติดตั้งสกิลซ้ำซ้อน หรือการดึงแพ็กเกจที่ไม่ได้ปักหมุดเวอร์ชันมาเพียงเพื่อรันตัวจัดรูปแบบที่มีอยู่แล้ว

โอเวอร์เฮดของ MCP ขึ้นอยู่กับ harness การโหลดเครื่องมือแบบหน่วงไว้ช่วยเลี่ยงการโหลด schema ทั้งหมดตั้งแต่ต้นได้ ให้คงไว้เฉพาะการผสานรวมที่เกี่ยวข้อง แทนที่จะมองว่า MCP เองล้าสมัย ตัวเลือก CLI ที่มีอยู่ยังคงมีประโยชน์ในด้านการทำซ้ำผลลัพธ์และการควบคุมทรัพยากร

เซสชันเบราว์เซอร์ทั้งหมดใช้ `./scripts/pw-session.sh` ซึ่งบังคับให้ทั้งเครื่องมีเบราว์เซอร์ทำงานอยู่ได้เพียงตัวเดียว ใช้เซสชันใหม่ที่แยกออกจากกันเป็นค่าเริ่มต้น การเข้าถึงเบราว์เซอร์ส่วนตัวที่ใช้งานอยู่ต้องได้รับอนุญาตอย่างชัดแจ้ง และใช้การอนุญาตนั้นซ้ำในขั้นตอนถัด ๆ ไป เลือกเบราว์เซอร์/วิวพอร์ตตามพฤติกรรมที่ได้รับผลกระทบ รันเอนจินที่เลือกทีละตัว ปิดเซสชันตามชื่อที่แน่ชัดในขั้นตอนเก็บกวาด และห้ามใช้ `close-all`/`kill-all` เด็ดขาด ดูสกิล `playwright-cli` และ [verification.md](https://github.com/bitsocialnet/bitsocial-web/blob/master/docs/agent-playbooks/verification.md)
