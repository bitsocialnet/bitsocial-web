# งานของเอเจนต์ที่ใช้เวลานาน

ใช้สถานะงานแบบถาวรเมื่องานต้องกลับมาทำต่อหรือต้องส่งมอบต่อ หรือเมื่อการรันครั้งเดียวยาวพอที่การบีบอัดคอนเท็กซ์อาจทำให้หลงลืมงานที่เหลืออยู่ งานเล็กไม่จำเป็นต้องมีบอร์ดหรือไฟล์ความคืบหน้า สำหรับงานที่ทำร่วมกัน ให้เก็บ `feature-list.json` และ `progress.md` แบบกระชับไว้ใน `docs/agent-runs/<slug>/` ที่เป็นของงานนั้นโดยเฉพาะ และใช้เทมเพลตที่มีอยู่เมื่อเป็นประโยชน์

บันทึกผลลัพธ์ที่ได้รับการร้องขอ สาขา/worktree ปัจจุบัน ความเป็นเจ้าของไฟล์ การเปลี่ยนแปลงที่เสร็จแล้ว การตรวจพร้อมผลลัพธ์ โปรเซส/เซสชันที่ตนเป็นเจ้าของ และขั้นตอนถัดไปที่ยังค้างอยู่ อย่าเก็บข้อมูลรับรองการเข้าถึงหรือการดัมพ์ซอร์สโค้ดตามอำเภอใจ ทำเครื่องหมายฟีเจอร์ว่าเสร็จก็ต่อเมื่อยืนยันเกณฑ์การยอมรับของมันแล้วเท่านั้น

เมื่อกลับมาทำงานต่อ ให้ตรวจสถานะ Git ความคืบหน้าล่าสุด และซอร์สที่เกี่ยวข้องก่อนแก้ไข ใช้ทรัพยากรที่ตนเป็นเจ้าของและเข้ากันได้ซ้ำ และเริ่มเซิร์ฟเวอร์ dev เฉพาะเมื่อการตรวจขั้นถัดไปต้องใช้ เลือกการตรวจตามผลกระทบโดยใช้ [verification.md](https://github.com/bitsocialnet/bitsocial-web/blob/master/docs/agent-playbooks/verification.md) แทนการรันรอบเต็มซ้ำทั้งที่ไม่มีอะไรเปลี่ยน

ให้งานที่มอบหมายต่อซึ่งเกี่ยวข้องกันมีขอบเขตชัดเจนและไม่ทับซ้อนกัน เอเจนต์เพียงตัวเดียวเป็นเจ้าของการตรวจที่หนักและเซสชันเบราว์เซอร์ อัปเดตสถานะถาวรเมื่องานส่วนที่เสร็จแล้ว อุปสรรคที่ขวางงาน หรือการส่งมอบ ทำให้สิ่งที่ผู้ร่วมงานคนถัดไปต้องรู้เปลี่ยนไป อย่าบันทึกทุกคำสั่งไปแบบกลไก
