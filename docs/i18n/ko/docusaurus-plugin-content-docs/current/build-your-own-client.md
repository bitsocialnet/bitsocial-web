# 나만의 Bitsocial 클라이언트 만들기

Bitsocial은 모든 용도를 커버하는 공식 앱 하나로 승부하지 않습니다. 여러 클라이언트가 같은
프로토콜을 공유하면서 인터페이스, 문화, 탐색 방식, 기본값, 수익 모델로 경쟁할 때 비로소
힘을 얻습니다.

5chan과 Seedit은 초기 사례일 뿐 한계선이 아닙니다. 누구든 플랫폼 소유자의 허락을 구하지 않고
새로운 이미지보드, 포럼, 프로필 클라이언트, 모바일 우선 소셜 앱, 틈새 커뮤니티 도구, 심지어
내부적으로 Bitsocial을 사용하는 중앙형 클라이언트까지 출시할 수 있어야 합니다.

## 개발자가 바꿀 수 있는 것

Bitsocial 클라이언트는 네트워크 전체를 포크하지 않고도 제품 결정만으로 경쟁할 수 있습니다.

- 인터페이스와 시각 언어
- 온보딩 흐름
- 커뮤니티 기본값
- 모더레이션 화면
- 탐색 모델
- 미디어 경험
- 모바일, 데스크톱, 저대역폭 환경의 제약
- 수익화와 비즈니스 모델

공통 계층은 프로토콜입니다. 제품 계층은 경쟁에 열려 있습니다.

## 가장 빠르게 익히는 방법

이미 존재하는 앱부터 써 보세요.

- 익명 이미지보드 커뮤니티는 [5chan](https://5chan.app)에서 경험해 보세요.
- Reddit 방식의 토론은 [Seedit](https://seedit.app)에서 경험해 보세요.
- 클라이언트 측 통합은 [Bitsocial React 훅](https://hooks.bitsocial.net/docs/quickstart/) 문서를 읽어보세요.
- 노드와 커뮤니티 운영은 [Bitsocial CLI](/developer-tools/cli/) 문서를 읽어보세요.

빠르게 움직이고 싶다면 먼저 기존 앱에 기여하세요. 원하는 인터페이스, 문화, 커뮤니티 모델이
그 앱에 맞지 않는다면 그때 별도의 클라이언트를 만드세요.

## 좁은 범위의 첫 버전을 고르세요

가장 좋은 첫 버전은 만능 소셜 앱이 아닙니다. 대상 사용자가 하나로 뚜렷하고, 존재해야 할 이유가
하나로 분명한 클라이언트입니다.

좋은 출발점의 예는 다음과 같습니다.

- 특정 문화에 맞춘 더 깔끔한 이미지보드 클라이언트
- 모바일 우선 포럼 클라이언트
- 엄격한 기본값을 가진 단일 커뮤니티 앱
- 크리에이터 커뮤니티 클라이언트
- 읽기 전용 탐색 클라이언트
- 모더레이션 또는 운영자용 콘솔
- 특정 언어, 지역, 기기 등급에 최적화된 클라이언트

작은 클라이언트도 충분히 쓸모가 있습니다. Bitsocial은 사용자를 비공개 데이터베이스에 가두는
대신, 그런 클라이언트도 같은 네트워크 안에서 성장할 수 있게 해주기 때문입니다.

## 구현 경로

현실적인 경로는 세 가지입니다.

1. 아이디어가 5chan이나 Seedit에 가깝다면 기존 클라이언트를 포크합니다.
2. [Bitsocial React 훅](https://hooks.bitsocial.net/)으로 새로운 React 클라이언트를 만듭니다.
3. 노드 API와 공개 RPC 인프라 위에 직접 통합을 구축합니다.

공개 RPC는 세 번째 경로를 훨씬 더 현실적으로 만들어 줍니다. 사용자는 호스팅형 비수탁 RPC
제공자로 시작한 뒤, 나중에 자체 호스팅이나 다른 제공자로 옮겨갈 수 있습니다.

## 설계 원칙

당신의 커뮤니티에 마땅히 있어야 할 클라이언트를 만들고, 호환되는 클라이언트끼리 공개적으로
경쟁하게 하세요.
