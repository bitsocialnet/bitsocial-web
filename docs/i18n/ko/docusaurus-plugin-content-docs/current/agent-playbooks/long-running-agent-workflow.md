# 장기 실행 에이전트 작업

작업을 나중에 재개하거나 다른 사람에게 인계해야 할 때, 또는 한 번의 실행이 길어서 컨텍스트 압축 과정에서 남은 작업을 놓칠 수 있을 때는 지속되는 작업 상태를 사용하세요. 작은 작업에는 보드나 진행 파일이 필요 없습니다. 공유 작업이라면 작업별 `docs/agent-runs/<slug>/`에 간결한 `feature-list.json`과 `progress.md`를 두고, 도움이 된다면 기존 템플릿을 활용하세요.

요청된 결과, 현재 브랜치/워크트리, 파일 소유권, 완료된 변경, 실행한 검사와 그 결과, 소유한 프로세스/세션, 그리고 아직 해결되지 않은 다음 단계를 기록하세요. 자격 증명이나 임의의 소스 덤프는 저장하지 마세요. 기능은 수락 기준이 검증되었을 때만 완료로 표시하세요.

작업을 재개할 때는 편집하기 전에 Git 상태, 최신 진행 상황, 관련 소스를 확인하세요. 호환되는 소유 리소스는 재사용하고, 개발 서버는 다음 검사에 필요할 때만 시작하세요. 바뀐 것이 없는 전체 검사를 반복하지 말고 [verification.md](https://github.com/bitsocialnet/bitsocial-web/blob/master/docs/agent-playbooks/verification.md)에 따라 영향 범위에 맞는 검사를 고르세요.

관련된 위임 작업은 범위를 분명히 하고 서로 겹치지 않게 나누세요. 무거운 검사와 브라우저 세션은 에이전트 하나가 맡습니다. 완료된 작업 단위나 차단 요인, 인계 사항 때문에 다음 기여자가 알아야 할 내용이 달라질 때 지속 상태를 갱신하세요. 모든 명령을 기계적으로 기록하지는 마세요.
