# Bitsocial과 Farcaster

[Farcaster](https://docs.farcaster.xyz/)는 신원은 블록체인에 두고 소셜 데이터는 블록체인 밖에
둡니다. 계정, 앱 키, 스토리지 결제는 이더리움 레이어 2인 OP Mainnet의 컨트랙트에 있습니다.
캐스트(cast)라고 부르는 게시물은 팔로우, 반응과 함께 서명된 메시지이며,
[Snapchain](https://snapchain.farcaster.xyz/)이 저장합니다. Snapchain은 블록체인과 비슷한
네트워크로, 2025년에 Farcaster의 기존 Hub 네트워크를 대체했습니다.

## Farcaster의 동작 방식

- **계정.** 계정은 숫자로 된 Farcaster ID이며 이더리움 주소가 소유합니다. 이 주소는 복구 주소를
  지정할 수도 있습니다. 앱은 온체인에 등록된 위임 앱 키로 게시하며, 앱 키로는 계정을 탈취할 수
  없습니다.
- **스토리지 임대료.** 모든 계정은 스토리지 단위를 임대하며, 현재 가격은 단위당 연 0.20달러입니다.
  2025년 7월 이후 임대한 단위 하나에는 캐스트 100개가 들어가고, 이를 넘으면 가장 오래된 캐스트부터
  정리됩니다. 속도 제한은 임대한 스토리지에 따라 커집니다.
- **Snapchain.** 검증자는 Tendermint 방식의 합의로 메시지를 블록에 정렬하고, 모든 풀 노드는 네트워크
  전체의 데이터를 보관합니다. [노드 가이드](https://snapchain.farcaster.xyz/getting-started)에
  따르면 노드에는 RAM 약 16GB와 스토리지 2TB가 필요합니다.
- **이름.** fname이라고 부르는 기본 사용자 이름은 무료이며 Farcaster 자체 네임 서버가 발급하는데, 이
  서버는 [fname을 회수할 수 있습니다](https://docs.farcaster.xyz/learn/what-is-farcaster/usernames).
  대신 이더리움에 등록한 `.eth` 이름을 쓸 수도 있습니다.
- **채널.** 주제별 채널은 Farcaster 클라이언트의 실험적 기능입니다. 채널 안의 캐스트는 프로토콜
  데이터이지만, 채널 메타데이터, 팔로우, 모더레이션은
  [클라이언트에 저장됩니다](https://docs.farcaster.xyz/learn/what-is-farcaster/channels).
- **읽기.** 앱은 직접 운영하는 Snapchain 노드나 관리형 공급자(보통 Neynar)를 통해 데이터를 읽습니다.

## 차이점

### 블록체인과 검증자

Farcaster는 계정과 결제를 OP Mainnet에, 모든 소셜 데이터의 순서 결정을 블록체인과 비슷한 네트워크인
Snapchain에 의존합니다. Snapchain의 검증자 집합은 허가형입니다. 백서는 전 세계에 분산된 검증자가
10개 정도 있으면 검열이 어려워진다고 하지만, 2026년 10월 기준
[검증자 목록](https://snapchain.farcaster.xyz/validators)은 그보다 적었고 키 대부분은 Neynar의
것이었습니다. Neynar는 2026년 1월
[Farcaster를 인수](https://neynar.com/blog/neynar-is-acquiring-farcaster)했습니다. Bitsocial에는
체인도, 검증자도, 합의도 없습니다.

### 게시하려면 돈을 내야 한다

모든 Farcaster 계정은 스토리지 임대료를 내며, 네트워크가 계정 기록을 얼마나 보관할지는 스토리지가
상한을 정합니다. Bitsocial에서는 프로토콜 차원에서 게시에 비용이 들지 않습니다. 캡차, 결제, 토큰,
또는 그 밖의 무엇을 요구할지는 각 커뮤니티가 정합니다.
[맞춤형 스팸 방지 챌린지](/custom-challenges/)를 참고하세요.

### 커뮤니티

Farcaster 채널은 클라이언트 기능입니다. 클라이언트가 채널 메타데이터를 저장하고 채널 모더레이션을
집행하므로, 어떤 채널에서 차단된 캐스트도 네트워크에서는 유효한 채로 다른 앱에 보일 수 있습니다.
Bitsocial에서 커뮤니티는 자체 키페어를 가진 프로토콜 객체이며, 커뮤니티의 노드가 게시물을 수락하거나
거부합니다.

### 인프라 운영

Farcaster 노드는 네트워크 전체를 보관하므로, 저장 공간이 모든 활동과 함께 늘어납니다. Farcaster는 그
증가가 가장 큰 클라우드 디스크에 근접할 것으로 전망합니다. Bitsocial 커뮤니티 노드는 자기 커뮤니티만
보관하며 일반 소비자용 하드웨어에서 돌아갑니다.

### 브라우저

Farcaster 브라우저 앱은 노드나 공급자의 HTTP 클라이언트입니다. Bitsocial 웹 앱은 탭 안에서 P2P
노드를 실행할 수 있습니다. [브라우저 피어 투 피어](/browser-p2p/)를 참고하세요.

## 비교

| 질문             | Farcaster                                                         | Bitsocial                                                                          |
| ---------------- | ----------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 분류             | 온체인 신원과 검증자가 순서를 정하는 소셜 데이터                  | P2P 커뮤니티 네트워크                                                              |
| 신원             | 이더리움 주소가 소유하는 Farcaster ID와 위임 앱 키                | 사용자와 커뮤니티를 위한 Ed25519 키페어                                            |
| 게시물 저장 위치 | Snapchain, 모든 풀 노드에 복제되며 유료 스토리지 한도 안에서 보관 | 커뮤니티 소유자의 노드와, 그 커뮤니티를 읽고 시드하는 피어                         |
| 온라인 유지 주체 | Snapchain 검증자와 노드 운영자                                    | 커뮤니티 소유자 노드와 보조 시더                                                   |
| 커뮤니티         | Farcaster 클라이언트가 관리하는 실험적 채널                       | 자체 노드가 게시물을 수락하거나 거부하는 일급 객체                                 |
| 스팸 방지        | 스토리지 임대료와 속도 제한, 그리고 앱 수준의 스팸 라벨           | 게시물이 받아들여지기 전에 거치는 커뮤니티별 챌린지                                |
| 모더레이션       | 클라이언트 안의 채널 호스트, 앱 필터, 검증자 수준의 검열 위험     | 커뮤니티 소유자가 자기 커뮤니티를 모더레이션하고, 무엇을 보여줄지는 앱이 선택      |
| 이름             | Farcaster가 회수할 수 있는 무료 fname, 또는 `.eth` 이름           | 키로 해석되는 `.bso` 및 `.eth` 이름                                                |
| 브라우저         | 노드나 공급자의 HTTP 클라이언트                                   | 일반 브라우저 탭 안에서 동작하는 P2P 노드                                          |
| 주요 절충        | 일관된 하나의 전역 데이터셋, 그러나 임대료, 체인, 소수의 검증자   | 수수료도 체인도 없지만 전역 데이터셋이 없고 오래된 콘텐츠가 영구히 보장되지는 않음 |
