# दीर्घकाळ चालणारे एजंट काम

काम नंतर पुन्हा सुरू करावे लागणार असेल किंवा हँडऑफ करायचा असेल, किंवा एकच रन इतका लांब असेल की कॉन्टेक्स्ट कॉम्पॅक्शनमुळे उरलेल्या कामाचा माग सुटू शकतो, तेव्हा टिकाऊ टास्क स्टेट वापरा. लहान टास्कसाठी बोर्ड किंवा प्रोग्रेस फाइलची गरज नाही. सामायिक कामासाठी टास्क-विशिष्ट `docs/agent-runs/<slug>/` मध्ये संक्षिप्त `feature-list.json` आणि `progress.md` ठेवा, आणि उपयुक्त असेल तिथे विद्यमान टेम्पलेट्स वापरा.

विनंती केलेला परिणाम, सध्याची ब्रांच/वर्कट्री, फाइल्सची मालकी, पूर्ण झालेले बदल, निकालांसह तपासण्या, मालकीच्या प्रक्रिया/सेशन्स, आणि पुढची न सुटलेली पायरी नोंदवा. क्रेडेन्शियल्स किंवा अनावश्यक सोर्स डंप साठवू नका. एखादे फीचर त्याचे स्वीकृती निकष पडताळल्यानंतरच पूर्ण म्हणून चिन्हांकित करा.

पुन्हा सुरू करताना, संपादन करण्यापूर्वी Git स्थिती, नवीनतम प्रगती आणि संबंधित सोर्स तपासा. सुसंगत असलेली मालकीची संसाधने पुन्हा वापरा; पुढच्या तपासणीला गरज असेल तेव्हाच डेव्ह सर्व्हर सुरू करा. न बदललेला संपूर्ण पास पुन्हा चालवण्याऐवजी [verification.md](https://github.com/bitsocialnet/bitsocial-web/blob/master/docs/agent-playbooks/verification.md) वापरून बदलाच्या परिणामानुसार तपासण्या निवडा.

संबंधित सोपवलेले काम मर्यादित व्याप्तीचे आणि एकमेकांवर न येणारे ठेवा. जड तपासण्या आणि ब्राउझर सेशन्सची मालकी एकाच एजंटकडे असते. पूर्ण झालेला टप्पा, एखादा अडथळा किंवा हँडऑफ यांमुळे पुढच्या योगदानकर्त्याला काय माहीत असणे आवश्यक आहे ते बदलत असेल, तेव्हा टिकाऊ स्टेट अद्ययावत करा; प्रत्येक कमांड यांत्रिकपणे लॉग करू नका.
