# स्किल्स आणि टूल्स

सामायिक स्किल्स `.agents/skills/` मध्ये असतात. हेच सोर्स संपादित करा, आणि मग Claude Code साठी `.claude/skills/` तयार करण्यासाठी `yarn ai-workflow:sync` चालवा. Codex आणि Cursor `.agents/skills/` थेट शोधतात; डुप्लिकेट `.codex/skills/` किंवा `.cursor/skills/` रूट्स पुन्हा आणू नका.

सामायिक रोल प्रॉम्प्ट्स `.agents/roles/*.md` मध्ये असतात. हा रिपॉझिटरी-विशिष्ट सोर्स फॉरमॅट आहे, नेटिव्ह एजंट डिस्कव्हरी पथ नव्हे. `scripts/ai-workflow-files.mjs` हे सोर्स खालील ॲप-विशिष्ट फाइल्समध्ये रूपांतरित करते; `yarn ai-workflow:sync` त्या लिहिते. जनरेट केलेल्या फाइल्स त्यांच्या सोर्ससोबतच कमिट करा, जेणेकरून नवीन चेकआउटमध्ये आधी जनरेटर न चालवताही नेटिव्ह कॉन्फिगरेशन उपलब्ध असेल. एखादा सोर्स काढल्यानंतर त्याचे कालबाह्य झालेले जनरेट केलेले आउटपुट स्पष्टपणे काढून टाका; व्हॅलिडेटर फाइल्स गुपचूप डिलीट न करता त्यांची नोंद करतो.

## रोल्स आणि मॉडेल्स

`browser-check`, `profiler`, `test-apk`, `translator`, आणि `reviewer` साठी कस्टम रोल्स ठेवा. सामान्य अंमलबजावणी आणि कोड शोधण्यासाठी हार्नेसचा अंगभूत worker/general-purpose किंवा explorer रोल वापरा. पॅरेंट स्वीकृती निकष आणि मालकी ठरवून देतो; जड तपासण्या एकच मालक चालवतो.

Codex एजंट फाइल्समध्ये `name`, `description`, आणि `developer_instructions` असतात. `.codex/config.toml` हे `max_concurrent_threads_per_session` वापरून एकाच वेळी चालणाऱ्या चाइल्ड एजंटची संख्या चारपर्यंत मर्यादित करते. सामायिक रोल मेटाडेटामध्ये नाव, वर्णन आणि पर्यायी सँडबॉक्स मोड असतो; त्यात मुद्दाम कोणतेही मॉडेल फील्ड ठेवलेले नाहीत.

तिन्ही ॲप्समधील कमिट केलेल्या स्किल्स आणि कस्टम एजंट्समधून मॉडेल आणि रीझनिंग फील्ड वगळा. त्यामुळे प्रत्येक ॲपच्या दस्तऐवजीकृत प्राधान्यक्रमानुसार रनटाइमवेळच्या इन्व्होकेशन निवडी, वापरकर्त्याचे डीफॉल्ट आणि पॅरेंटकडून मिळणारा वारसा लागू होऊ शकतात. Claude फॅमिली अलायसमुळे आवृत्त्यांची देखभाल कमी होते, पण ते तरीही एक फॅमिली निवडतात; आवृत्ती-निश्चित Cursor मॉडेल भविष्यात अद्ययावत करावे लागते. गरज असल्यास अशा निवडी वापरकर्ता/सेशन सेटिंग्जमध्ये ठेवा. वारशामुळे सध्याचे सर्वोत्तम मॉडेल आपोआप निवडले जाईल असे आश्वासन मिळत नाही. `latest` अलायस स्वतःहून तयार करू नका, किंवा नेहमीच्या टास्कमध्ये मॉडेल-कॅटलॉगचे संशोधन जोडू नका. [Codex मधील निवड](https://learn.chatgpt.com/docs/agent-configuration/subagents), [Claude मधील निवड](https://code.claude.com/docs/en/sub-agents#choose-a-model), आणि [Cursor मधील निवड](https://cursor.com/docs/subagents#model-configuration) पाहा.

`sandbox-mode: read-only` हे Codex च्या सँडबॉक्सशी आणि Cursor च्या `readonly` शी जुळते; Claude ची टूल यादी आणि रोलच्या सूचना त्याच्या रिव्ह्यू वर्कफ्लोवर मर्यादा घालतात, पण Bash ॲक्सेस हा OS-स्तरीय सँडबॉक्स नाही.

लागू असेल तिथे, वापरकर्त्याने सुरू करायच्या वर्कफ्लोसाठी सामायिक स्किल फ्रंटमॅटर `disable-model-invocation: true` वापरते. Codex चे संबंधित सेटिंग `agents/openai.yaml` मध्ये `policy.allow_implicit_invocation: false` असे असते; व्हॅलिडेटरला दोन्ही आवश्यक असतात. इन्व्होकेशन मेटाडेटा स्पष्ट अधिकृततेच्या नियमांना पूरक असतो; एखाद्या स्किलमध्ये प्रकाशनाच्या पायऱ्या आहेत एवढ्यावरून रिव्ह्यूची विनंती कधीही प्रकाशनाची परवानगी ठरत नाही.

## तपासण्या आणि डिस्कव्हरी

- `yarn ai-workflow:sync` इन्स्टॉल केलेल्या `js-yaml` आणि `smol-toml` वापरून सुसंगतता आउटपुट पुन्हा तयार करते.
- `yarn ai-workflow:check` सोर्स/फ्रंटमॅटर/कॉन्फिग्ज पार्स करते, आणि जनरेट केलेले आउटपुट, इन्व्होकेशन मेटाडेटा, मॉडेल फील्ड्सचे स्थान, आणि फक्त-फॉरमॅटर हुक वायरिंग तपासते. ते मॉडेल आयडेंटिफायर्स प्रदात्याच्या कॅटलॉगशी जुळवून पाहत नाही.
- `yarn ai-workflow:test` हुक पेलोड आणि वर्कफ्लो जनरेशन/व्हॅलिडेशनसाठी स्वतंत्र Node फिक्स्चर्स चालवते.
- एजंट ॲप्लिकेशन अपग्रेड केल्यानंतर त्या ॲप्लिकेशनमध्ये स्किल/रोल डिस्कव्हरीची पडताळणी करा. सिंटॅक्स/पॅरिटी तपासण्या लोडर तपासणीची जागा घेत नाहीत. चालू सेशनमध्ये जुना कॅटलॉग राहिला असल्यास ॲप्लिकेशन रीलोड करा.
- हुक्ससाठी हार्नेसचा प्रोजेक्ट ट्रस्ट आणि हुक रिव्ह्यू आवश्यक असतो; तपासणी पास व्हावी म्हणून ट्रस्टला बगल देऊ नका. [hooks-setup.md](hooks-setup.md) पाहा.

## उपयुक्त सूचनांची देखभाल

[OpenAI चे स्किल्स आणि प्रॉम्प्ट्सविषयीचे मार्गदर्शन](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) (2026-09-12 रोजी आढावा घेतलेले) पाळा: वर्णने नेमकी ठेवा, तपशील फक्त संबंधित असतील तेव्हाच लोड करा, आणि वापरकर्त्याने विनंती केलेली व्याप्ती जपा. सामायिक स्किल्स वेगवेगळ्या मॉडेल्सना सेवा देतात; प्रोजेक्ट-विशिष्ट अपरिवर्तनीय नियम कायम ठेवा, आणि नेहमीच्या अंमलबजावणीच्या निवडींना मोकळीक द्या.

स्किलचा उद्देश, निर्णयाच्या सीमा आणि आवश्यक मर्यादा `SKILL.md` मध्ये ठेवा. मोठ्या प्रमाणातील मोड-विशिष्ट कमांड्स किंवा उदाहरणे पर्यायी संदर्भ म्हणून लिंक करा. लहान वर्णनांमध्ये ट्रिगरच्या अटी सुरुवातीलाच द्या; फक्त एखादा जुळणारा कीवर्ड आढळल्याने टास्कची व्याप्ती वाढू नये. वर्तन जाणीवपूर्वक बदलले जात नसेल तर विद्यमान इन्व्होकेशन मेटाडेटा जसा आहे तसा ठेवा.

सूचनांमध्ये मोठा बदल केल्यानंतर काही प्रातिनिधिक लहान आणि मोठ्या विनंत्या चालवून पाहा. कोणती स्किल्स/संदर्भ निवडले गेले, कृती व्याप्तीतच राहिल्या का, पडताळणी बदलाशी जुळली का, आणि अधिकृत काम पूर्ण झाले का ते तपासा. स्कीमा आणि फिक्स्चर चाचण्या टूलिंगची अचूकता सिद्ध करतात, एजंटच्या निर्णयांची गुणवत्ता नव्हे.

## टूल्स आणि ब्राउझरची मालकी

विद्यमान स्किल/टूल कॅटलॉग आणि इन्स्टॉल केलेल्या प्रोजेक्ट CLI ना प्राधान्य द्या. GitHub साठी `gh`, ब्राउझर पडताळणीसाठी `playwright-cli`, आणि लायब्ररीचे वर्तन महत्त्वाचे असेल तेव्हा अधिकृत/आवृत्ती-विशिष्ट दस्तऐवज वापरा. डुप्लिकेट स्किल्स इन्स्टॉल करणे, किंवा फक्त विद्यमान फॉरमॅटर चालवण्यासाठी पिन न केलेले पॅकेज आणणे टाळा.

MCP चा ओव्हरहेड हार्नेसवर अवलंबून असतो: डिफर्ड टूल लोडिंगमुळे प्रत्येक स्कीमा सुरुवातीलाच लोड करणे टाळता येते. MCP लाच कालबाह्य मानण्याऐवजी इंटिग्रेशन्स संबंधित तेवढीच ठेवा. पुनरुत्पादनक्षमता आणि संसाधनांवरील नियंत्रणासाठी विद्यमान CLI पर्याय अजूनही उपयुक्त आहेत.

सर्व ब्राउझर सेशन्स `./scripts/pw-session.sh` वापरतात, जे संपूर्ण मशीनवर एका वेळी एकच सक्रिय ब्राउझर असल्याची खात्री करते. डीफॉल्टनुसार नवीन, स्वतंत्र सेशन वापरा. सध्याच्या वैयक्तिक ब्राउझरच्या ॲक्सेससाठी स्पष्ट परवानगी आवश्यक आहे; पुढील पायऱ्यांमध्ये तीच परवानगी पुन्हा वापरा. बाधित वर्तनानुसार ब्राउझर/व्ह्यूपोर्ट निवडा, निवडलेली एंजिन्स एकामागोमाग एक चालवा, क्लीनअपमध्ये नेमके त्या नावाचे सेशन बंद करा, आणि `close-all`/`kill-all` कधीही वापरू नका. `playwright-cli` स्किल आणि [verification.md](https://github.com/bitsocialnet/bitsocial-web/blob/master/docs/agent-playbooks/verification.md) पाहा.
