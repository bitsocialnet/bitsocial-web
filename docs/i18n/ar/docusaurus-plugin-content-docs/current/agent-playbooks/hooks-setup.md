# خطافات الوكلاء

لا تفعل خطافات دورة الحياة المُودَعة في المستودع سوى تنسيق ملفات JavaScript/TypeScript التي عُدّلت بنجاح، عبر oxfmt المثبَّت. ويوجد المنطق المشترك في `scripts/agent-hooks/format.mjs`؛ ويفوّض كل غلاف أصلي العمل إليه.

| التطبيق | الإعداد الأصلي | الحدث |
|---|---|---|
| Codex | `.codex/hooks.json` | `PostToolUse`, `apply_patch` |
| Claude Code | `.claude/settings.json` | `PostToolUse`, `Edit|Write|MultiEdit` |
| Cursor | `.cursor/hooks.json` | `afterFileEdit` |

لا يقرأ Claude ملف `.claude/hooks.json` مستقلًا. ويظل كل تطبيق متحكمًا في الثقة بالمشروع وفي تفعيل الخطافات من عدمه؛ فافحص إعداداته الحالية بدلًا من تجاوز الثقة. أما `.codex/config.toml` فهو إعداد للمستودع، وليس سجلًّا لأوامر الخطافات.

تتحقق أداة التنسيق من الحدث والحمولة، ومن نجاح التعديل، ومن امتداد الملف، ومن وقوع الملف داخل المستودع، بما في ذلك عبر الروابط الرمزية. وعند غياب التبعيات أو عدم ملاءمة المدخلات لا يُنفَّذ أي عمل. وتستخدم الأوامر مصفوفة وسائط مع تعطيل وصول Corepack إلى الشبكة؛ ولا تثبّت الخطافات تبعيات، ولا تشغّل عمليات بناء أو مراجعات، ولا تعدّل حالة Git.

شغّل الفحوص صراحةً وفقًا لـ [verification.md](https://github.com/bitsocialnet/bitsocial-web/blob/master/docs/agent-playbooks/verification.md). وشغّل `yarn ai-workflow:sync` و`yarn ai-workflow:check` و`yarn ai-workflow:test` بعد تغيير سير العمل. وتستخدم تجهيزات الاختبار ملفات مؤقتة واستدعاءات وهمية لأداة التنسيق؛ وهي لا تثبت أن كل تطبيق قد حمّل إعداداته. أعد تحميل التطبيق وافحص فهرسه بعد الترقيات.

تظل مهارة التصميم Impeccable ومساعداتها التنفيذية متاحة عند الطلب تحت `.agents/skills/impeccable`. وكان خطافها السابق في Codex يشير إلى مجلد غير موجود؛ وصار سير عمل التصميم يعمل الآن عند اختيار مهارته، دون أي خطاف تصميم يعمل باستمرار. ولا يجوز للمهارة أن تعيد ضبط خطافات المشروع كخطوة عَرَضية من خطوات التصميم.
