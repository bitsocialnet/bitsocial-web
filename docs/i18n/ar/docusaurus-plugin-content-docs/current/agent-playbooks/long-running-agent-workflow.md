# عمل الوكلاء طويل الأمد

استخدم حالة مهمة دائمة عندما يحتاج العمل إلى استئناف أو تسليم، أو عندما يطول التشغيل الواحد بما يكفي لأن يؤدي ضغط السياق إلى فقدان تتبّع العمل المتبقي. ولا تحتاج المهام الصغيرة إلى لوحة أو ملف تقدّم. وفي العمل المشترك، احتفظ بملفي `feature-list.json` و`progress.md` موجزين في مجلد `docs/agent-runs/<slug>/` خاص بالمهمة، مستعينًا بالقوالب الموجودة حيثما يفيد ذلك.

سجّل النتيجة المطلوبة، والفرع وشجرة العمل الحاليين، وملكية الملفات، والتغييرات المكتملة، والفحوص مع نتائجها، والعمليات والجلسات المملوكة، والخطوة التالية التي لم تُحسم بعد. لا تخزّن بيانات اعتماد ولا مقتطفات عشوائية من الشيفرة المصدرية. ولا تَعُدّ ميزةً مكتملة إلا بعد التحقق من معايير قبولها.

عند الاستئناف، افحص حالة Git وآخر تقدّم مسجَّل والشيفرة المصدرية ذات الصلة قبل التعديل. أعد استخدام الموارد المملوكة المتوافقة؛ ولا تبدأ خادم تطوير إلا عندما يحتاجه الفحص التالي. واختر الفحوص بحسب الأثر مستعينًا بـ [verification.md](https://github.com/bitsocialnet/bitsocial-web/blob/master/docs/agent-playbooks/verification.md)، بدلًا من تكرار تمريرة كاملة لم يتغيّر ما يستدعيها.

أبقِ العمل المفوَّض المترابط محدد النطاق وغير متداخل. يتولى وكيل واحد الفحوص الثقيلة وجلسات المتصفح. وحدّث الحالة الدائمة عندما يغيّر جزءٌ مكتمل أو عائقٌ أو تسليمٌ ما يحتاج المساهم التالي إلى معرفته؛ ولا تسجّل كل أمر تسجيلًا آليًا.
