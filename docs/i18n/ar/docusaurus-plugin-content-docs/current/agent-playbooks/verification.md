# التحقق

اختر الفحوص بناءً على السلوك الذي تغيّر وعلى ما تبقّى من عدم يقين. أعد استخدام الأدلة الناجحة ما دامت تخص الحالة النهائية نفسها، وأعد التشغيل بعد التعديلات أو الإخفاقات ذات الصلة. وتظل متطلبات CI أو الإصدار أو المستخدم الصريحة سارية.

| التغيير                                                      | الفحوص المناسبة                                                                                                        |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| النصوص أو التعليقات أو التنسيق فقط                           | فرق التغييرات، والمراجع، والمولّدات ذات الصلة؛ دون بناء التطبيق                                                        |
| مصادر سير عمل الذكاء الاصطناعي أو إعداداته                   | `yarn ai-workflow:sync` و`yarn ai-workflow:check` و`yarn ai-workflow:test`؛ وأعد توليد فهارس LLM عندما يتغيّر السياق   |
| مساعد أو سكربت معزول                                         | استدعاء مركّز أو تجهيزات اختبار، مع فحوص الصياغة أو الأنواع أو الفحص اللغوي للشيفرة المتأثرة                           |
| تغيير مشترك في بيئة التشغيل أو التبعيات أو البناء أو التكامل | فحوص مركّزة على ما تأثر، إضافةً إلى فحوص البناء أو الأنواع أو الفحص اللغوي ذات الصلة الواردة أدناه                     |
| CSS أو السمات أو التخطيط فقط                                 | المسارات ونوافذ العرض والسمات المتأثرة في المتصفحات المختارة؛ والبناء عندما تتغيّر الاستيرادات أو الأصول أو معالجة CSS |
| حالة React أو التأثيرات أو الأداء                            | السلوك المتأثر وإرشادات React المنطبقة؛ وDoctor عندما تحسم تشخيصاته مسألة ملموسة                                       |

## فحوص المشروع

- يختار `yarn build:verify` مساحة العمل المتأثرة. وعندما يكون النطاق معروفًا استخدم `yarn build:about` أو `yarn build:chain` أو `yarn build:stats-monitor` أو `yarn docs:build:verify`.
- يشغّل `yarn build` عمدًا بناء الإنتاج الكامل لموقع about والتوثيق، بما في ذلك جميع لغات التوثيق. استخدمه للتحقق على مستوى الإصدار كله أو للتغييرات التي تستدعي هذا النطاق.
- تغطي `yarn lint` و`yarn typecheck` و`yarn format:check` بوابات المستودع القائمة؛ وعند تعديل محدود على سكربت، استخدم أولًا فحوص الصياغة أو تجهيزات الاختبار أو التنسيق المركّزة الخاصة به.
- تتطلب تغييرات ملف البيان أو ملف القفل تشغيل `corepack yarn install` و`yarn deps:check-pinned` و`yarn deps:check-hardened`. أما `yarn knip` فاسترشادي فيما يخص التبعيات والاستيرادات.
- فحوص ترجمة التوثيق موجودة في [translations.md](translations.md)؛ ولا تشغّل أداة الكتابة الجماعية للترجمات من أجل تغيير مركّز في التوثيق.

## أدلة المتصفح والملكية

استخدم Chrome للتغييرات الصغيرة المعزولة في المتصفح. وأضف Firefox وWebKit عند تغييرات CSS أو التخطيط أو التجاوب المشتركة، أو واجهات البرمجة الحساسة لنوع المتصفح، أو التفاعلات الواسعة، أو الإصدارات، أو عند وجود معايير صريحة لتعدد المتصفحات. وضمّن تخطيطات الهاتف وسلوك اللمس المتأثرة. فتغيير حجم نافذة العرض وحده ليس محاكاةً للمس. واختر المسارات والمحتوى الفعلية من الشيفرة المصدرية بدلًا من افتراض أن الأمثلة متاحة.

استخدم `playwright-cli` عبر `./scripts/pw-session.sh`. فلا يكون إلا متصفح واحد نشطًا على مستوى الجهاز كله؛ وتعمل المحركات المختارة بالتتابع، وتُغلَق كل جلسة مملوكة باسمها الدقيق حتى بعد الإخفاق. أعد استخدام جلسة مصرَّح بها يملكها المستدعي دون إغلاقها. ولا تستخدم أبدًا التنظيف الشامل للمتصفحات، ولا توقف خادمًا ملكيته غير واضحة. ولا حاجة إلى متصفح أو خادم في الأعمال المقتصرة على التوثيق.

في أعمال الأداء، قارن المسار نفسه بإعدادات متكافئة لنافذة العرض والمحتوى والشبكة والمعالج ووضع البناء وعبء القياس. وميّز بين الملاحظات والأسباب المشتبه بها. واستخدم مهارة التنميط عندما تجيب هذه القياسات عن الطلب الفعلي.

## الأدلة النهائية

يتولى وكيل واحد التحقق الثقيل. افحص أعباء العمل النشطة، ونفّذ بالتتابع عمليات التثبيت، والبناء والمجموعات الكاملة من الاختبارات، وDoctor، وأعمال Android/Electron، وتنميط المتصفح. أبلغ عن الأوامر ونتائجها وعن القيود المحددة؛ فالبيانات الناقصة أو المحرك الذي جرى تخطيه ليسا نتيجة ناجحة. وتتحقق تجهيزات اختبار الأدوات من الصيغ والآليات، لا من الاكتشاف الفعلي داخل التطبيقات من طرف إلى طرف ولا من جودة قرارات النموذج.

## فحوص React التلقائية

يشغّل `yarn agent:verify` عمليات البناء المختارة ثم `yarn doctor:check` و`yarn perf:check`. ويتضمن `perf:check` فحص التوافق مع أداة الجمع والاختبار الذاتي للانحدار المتعمَّد، فلا يحتاج CI ولا مسار تحقق الوكيل إلى تمريرة `perf:test` منفصلة. ثبّت أدوات المتصفح بإصداراتها المحدّدة مرة واحدة عبر `yarn perf:install` (مع `--with-deps` في CI على Linux). واستخدم مرشحات الهدف أو السيناريو لإعادة التشغيل المركّزة بعد التمريرة الكاملة ذات الصلة. وميزانيات السيناريوهات محددة صراحةً في `scripts/react-perf/config.mjs`؛ فاحفظ الأدلة وأصلح الانحدار قبل التفكير في تغيير مبرَّر لخط الأساس. ولا تتضمن عمليات بناء الإنتاج العادية Bippy؛ إذ توفّر أوامر `build:profile:*` المنفصلة أدوات التنميط الرسمية لـ React.

ينتظر سيناريو `apps-search` في موقع about بعد كل حرف حتى تُطبَّق القيمة في URL وحقل الإدخال قبل كتابة الحرف التالي. ونتيجته الناجحة تغطي تسلسل الاستعلامات المطبَّقة ذاك، لا سرعة الاستجابة عند الكتابة السريعة. استخدم إعادة إنتاج منفصلة للإدخال السريع عند تقييم فقدان الأحرف أو سرعة استجابة الإدخال.
