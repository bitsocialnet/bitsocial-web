# طویل عرصے تک چلنے والا ایجنٹ کا کام

پائیدار ٹاسک اسٹیٹ اُس وقت استعمال کریں جب کام کو دوبارہ شروع کرنے یا ہینڈ آف کی ضرورت ہو، یا جب ایک ہی رن اتنا لمبا ہو کہ کانٹیکسٹ کمپیکشن کی وجہ سے باقی کام کا سراغ گم ہو سکے۔ چھوٹے کاموں کے لیے کسی بورڈ یا پیش رفت فائل کی ضرورت نہیں۔ مشترکہ کام کے لیے ٹاسک سے مخصوص `docs/agent-runs/<slug>/` میں ایک مختصر `feature-list.json` اور `progress.md` رکھیں، اور جہاں مفید ہو موجودہ ٹیمپلیٹس استعمال کریں۔

مطلوبہ نتیجہ، موجودہ برانچ/ورک ٹری، فائلوں کی ملکیت، مکمل شدہ تبدیلیاں، نتائج سمیت جانچیں، اپنی ملکیت والے پراسیسز/سیشنز، اور اگلا حل طلب قدم درج کریں۔ کریڈینشلز یا سورس کوڈ کے من مانے ڈمپ محفوظ نہ کریں۔ کسی فیچر کو صرف اُس وقت مکمل نشان زد کریں جب اس کے قبولیت کے معیارات کی تصدیق ہو چکی ہو۔

کام دوبارہ شروع کرتے وقت ترمیم سے پہلے Git کی حالت، تازہ ترین پیش رفت اور متعلقہ سورس کا معائنہ کریں۔ اپنی ملکیت والے ہم آہنگ وسائل دوبارہ استعمال کریں؛ ڈیو سرور صرف اُس وقت شروع کریں جب اگلی جانچ کو اس کی ضرورت ہو۔ کسی غیر تبدیل شدہ مکمل پاس کو دہرانے کے بجائے [verification.md](https://github.com/bitsocialnet/bitsocial-web/blob/master/docs/agent-playbooks/verification.md) کی مدد سے اثر کے لحاظ سے جانچیں منتخب کریں۔

متعلقہ سونپا گیا کام محدود دائرے میں اور ایک دوسرے سے غیر متداخل رکھیں۔ بھاری جانچوں اور براؤزر سیشنز کا ذمہ ایک ہی ایجنٹ کے پاس ہوتا ہے۔ پائیدار حالت اُس وقت اپ ڈیٹ کریں جب کوئی مکمل شدہ سلائس، رکاوٹ یا ہینڈ آف یہ بدل دے کہ اگلے معاون کو کیا جاننے کی ضرورت ہے؛ ہر کمانڈ کو مشینی انداز میں لاگ نہ کریں۔
