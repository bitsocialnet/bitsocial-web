# تصدیق

جانچیں بدلے ہوئے رویے اور باقی رہ جانے والی غیر یقینی کی بنیاد پر منتخب کریں۔ اسی حتمی حالت کے لیے کامیاب شواہد دوبارہ استعمال کریں؛ متعلقہ ترامیم یا ناکامیوں کے بعد جانچیں دوبارہ چلائیں۔ CI/ریلیز/صارف کی صراحتاً بیان کردہ شرائط بدستور لاگو رہتی ہیں۔

| تبدیلی                                             | مناسب جانچیں                                                                                                            |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| صرف نثر/تبصرے/فارمیٹنگ                             | ڈِف، حوالہ جات، متعلقہ جنریٹرز؛ ایپ بلڈ نہیں                                                                            |
| AI ورک فلو کے سورسز/کنفیگریشن                      | `yarn ai-workflow:sync`، `yarn ai-workflow:check`، `yarn ai-workflow:test`؛ کانٹیکسٹ بدلنے پر LLM انڈیکسز دوبارہ بنائیں |
| الگ تھلگ ہیلپر یا اسکرپٹ                           | متاثرہ کوڈ کے لیے مرکوز کال/فکسچرز اور سنٹیکس یا ٹائپ/لِنٹ جانچیں                                                       |
| مشترکہ رن ٹائم، انحصار، بلڈ یا انٹیگریشن کی تبدیلی | متاثرہ حصے کی مرکوز جانچیں، نیز نیچے دی گئی متعلقہ بلڈ/ٹائپ/لِنٹ جانچیں                                                 |
| صرف CSS/تھیم/لے آؤٹ                                | منتخب براؤزرز میں متاثرہ روٹس/ویو پورٹس/تھیمز؛ امپورٹس، اثاثے یا CSS پروسیسنگ بدلنے پر بلڈ                              |
| React اسٹیٹ/ایفیکٹس/کارکردگی                       | متاثرہ رویہ اور قابلِ اطلاق React رہنمائی؛ Doctor اُس وقت جب اس کی تشخیصات کسی ٹھوس خدشے کا فیصلہ کریں                  |

## پروجیکٹ کی جانچیں

- `yarn build:verify` متاثرہ ورک اسپیس خود منتخب کرتا ہے۔ معلوم دائرے کے لیے `yarn build:about`، `yarn build:chain`، `yarn build:stats-monitor` یا `yarn docs:build:verify` استعمال کریں۔
- `yarn build` جان بوجھ کر اباؤٹ سائٹ اور دستاویزات کا مکمل پروڈکشن بلڈ چلاتا ہے، جس میں دستاویزات کے تمام لوکیلز شامل ہیں۔ اسے پوری ریلیز کی توثیق یا ایسی تبدیلیوں کے لیے استعمال کریں جو اتنے بڑے دائرے کی متقاضی ہوں۔
- `yarn lint`، `yarn typecheck` اور `yarn format:check` ریپوزٹری کے موجودہ گیٹس کا احاطہ کرتے ہیں؛ کسی اسکرپٹ میں محدود ترمیم کے لیے پہلے اس کی مرکوز سنٹیکس/فکسچر/فارمیٹ جانچیں استعمال کریں۔
- مینی فیسٹ/لاک فائل کی تبدیلیوں کے لیے `corepack yarn install`، `yarn deps:check-pinned` اور `yarn deps:check-hardened` لازمی ہیں۔ انحصارات/امپورٹس کے لیے `yarn knip` محض مشاورتی ہے۔
- دستاویزات کے ترجمے کی جانچیں [translations.md](translations.md) میں درج ہیں؛ دستاویزات کی کسی مرکوز تبدیلی کے لیے بلک ترجمہ رائٹر نہ چلائیں۔

## براؤزر شواہد اور ملکیت

براؤزر کی چھوٹی، الگ تھلگ تبدیلیوں کے لیے Chrome استعمال کریں۔ مشترکہ CSS/لے آؤٹ/ریسپانسیونس، براؤزر کے لحاظ سے حساس APIs، وسیع تعاملات، ریلیزز، یا صراحتاً طے شدہ کراس براؤزر معیارات کے لیے Firefox اور WebKit بھی شامل کریں۔ متاثرہ موبائل لے آؤٹس/ٹچ رویہ بھی شامل کریں۔ محض ویو پورٹ کا سائز بدلنا ٹچ ایمولیشن نہیں ہے۔ یہ فرض کرنے کے بجائے کہ مثالیں دستیاب ہوں گی، اصل روٹس اور مواد سورس سے منتخب کریں۔

`playwright-cli` کو `./scripts/pw-session.sh` کے ذریعے استعمال کریں۔ پوری مشین پر ایک وقت میں ایک ہی براؤزر فعال رہتا ہے؛ منتخب انجن یکے بعد دیگرے چلتے ہیں اور اپنی ملکیت والا ہر مخصوص سیشن ناکامی کے بعد بھی بند کیا جاتا ہے۔ کال کرنے والے کی ملکیت والا مجاز سیشن بند کیے بغیر دوبارہ استعمال کریں۔ براؤزر کی عالمی صفائی کبھی استعمال نہ کریں اور نہ ایسا سرور بند کریں جس کی ملکیت غیر واضح ہو۔ صرف دستاویزات کے کام کے لیے کسی براؤزر/سرور کی ضرورت نہیں۔

کارکردگی کے کام میں ایک ہی فلو کا موازنہ یکساں ویو پورٹ، مواد، نیٹ ورک/CPU ترتیبات، بلڈ موڈ اور پیمائش کے اضافی بوجھ کے ساتھ کریں۔ مشاہدات کو مشتبہ وجوہات سے الگ رکھیں۔ پروفائل اسکل اُس وقت استعمال کریں جب یہ پیمائشیں اصل درخواست کا جواب دیتی ہوں۔

## حتمی شواہد

بھاری تصدیق کا ذمہ ایک ہی ایجنٹ کے پاس ہوتا ہے۔ فعال ورک لوڈز کا معائنہ کریں اور انسٹالز، بلڈز/مکمل سویٹس، Doctor، Android/Electron کے کام اور براؤزر پروفائلنگ کو یکے بعد دیگرے چلائیں۔ کمانڈز/نتائج اور مخصوص حدود رپورٹ کریں؛ غائب ڈیٹا یا چھوڑا گیا انجن کامیاب نتیجہ نہیں ہے۔ ٹولنگ کے فکسچرز فارمیٹس اور طریقۂ کار کی تصدیق کرتے ہیں، ایپ کی شروع سے آخر تک دریافت یا ماڈل کے فیصلوں کے معیار کی نہیں۔

## خودکار React جانچیں

`yarn agent:verify` منتخب بلڈز چلاتا ہے اور ان کے بعد `yarn doctor:check` اور `yarn perf:check`۔ `perf:check` میں کلیکٹر کی مطابقت اور جان بوجھ کر پیدا کیے گئے ریگریشن کا سیلف ٹیسٹ شامل ہے، اس لیے نہ CI کو اور نہ ایجنٹ کی تصدیق کے راستے کو الگ سے `perf:test` پاس کی ضرورت ہے۔ پن کی گئی براؤزر ٹولنگ ایک بار `yarn perf:install` سے انسٹال کریں (Linux CI میں `--with-deps`)۔ مکمل متعلقہ پاس کے بعد مرکوز دوبارہ رنز کے لیے ہدف/منظرنامے کے فلٹرز استعمال کریں۔ منظرناموں کے بجٹ `scripts/react-perf/config.mjs` میں صراحت سے درج ہیں؛ کسی جائز بیس لائن تبدیلی پر غور کرنے سے پہلے شواہد محفوظ رکھیں اور ریگریشن ٹھیک کریں۔ عام پروڈکشن بلڈز میں Bippy شامل نہیں ہوتا؛ الگ `build:profile:*` کمانڈز React کی سرکاری پروفائلنگ انسٹرومنٹیشن فراہم کرتی ہیں۔

اباؤٹ سائٹ کا `apps-search` منظرنامہ ہر حرف کے لیے کمٹ شدہ URL/ان پٹ ویلیوز کی رفتار سے چلتا ہے۔ اس کا کامیاب نتیجہ اسی کمٹ شدہ استفسار کی ترتیب کا احاطہ کرتا ہے، تیز ٹائپنگ پر ردعمل کا نہیں۔ حروف کے ضائع ہونے یا ان پٹ کے ردعمل کا جائزہ لیتے وقت تیز ان پٹ کی الگ ری پروڈکشن استعمال کریں۔
