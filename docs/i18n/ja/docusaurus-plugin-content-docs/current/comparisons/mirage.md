# Bitsocial と Mirage

[Mirage](https://mirage.foundation/) は、コミュニティ、スレッド形式の投稿、投票を備えた Reddit 型のディスカッションネットワークです。企業のデータベースではなく、CometBFT コンセンサスを使う Cosmos SDK チェーンという独自のブロックチェーン上で動いています。Bitsocial で最も近いプロダクトは、Bitsocial ネットワーク上の Reddit 型アプリである [Seedit](/apps/seedit/) です。そのため、この比較は主に、それぞれがコミュニティをどうホストし、所有し、モデレートするかについてのものになります。

## Mirage の仕組み

- **ノード。** Mirage のノードは 1 つの Docker コンテナで、バリデーター、PostgreSQL データベース、インデクサー、HTTP API、Web フロントエンドを含んでいます。すべてのノードはバリデーターでもあります。[デプロイガイド](https://github.com/MirageFoundation/mirage-node/blob/dev/docs/guides/deploy.md) によれば、ノードを動かすには amd64 の Ubuntu サーバーと、運用者のアカウントにある 10,000,000 MIRAGE トークンが必要です。
- **投稿。** ブラウザは利用者の secp256k1 鍵で各操作に署名し、無料利用者は小さなプルーフオブワークの計算も行います。ノードはその操作をチェーンのトランザクションに包み、手数料を支払います。
- **読み取り。** 各ノードのインデクサーはチェーンのデータを自分のデータベースにコピーし、HTTP API でフィードを配信します。ノードが保持するブロックは約 1 週間分なので、長期的な投稿履歴は各ノードのデータベースにあり、新しいノードは同期ポイントより前の履歴を持たない状態から始まります。
- **アカウント。** アカウントは 12 単語のシードフレーズから導出される鍵で、同じシードがどのノードでも使えます。ユーザー名はチェーン上に記録され、ネットワーク全体で一意です。
- **コミュニティ。** 有効な名前はすべて最初からコミュニティであり、誰もそれを所有しません。最大 10 人の利用者から成る有料のキュレーターチームが、それぞれコミュニティのモデレート済みビューを維持します。閲覧者は、いずれかのチームのビュー、ノードのデフォルト、検閲なしのビューのどれかを選びます。[Mirage の FAQ](https://mirage.talk/faq) を参照してください。
- **トークン。** MIRAGE トークンは、サブスクリプションの支払い、投稿者とノードへの報酬、バリデーターのガバナンス上の重みに使われます。サブスクライバーはプルーフオブワークが不要で、上限も高くなります。

## どこが違うのか

### 誰がコミュニティを所有するか

Seedit では、コミュニティの作成者がその鍵ペアを保持し、ノードを自分で動かすか委任し、モデレーションを行います。Mirage では、誰もコミュニティを所有しません。競合するキュレーターチームが同じ名前のモデレート済みビューを提供し、デフォルトのビューは、最も多くの有料サブスクライバーに選ばれたチームのものになります。

### スパム対策

Mirage はネットワーク全体に 1 つのルールを適用します。無料利用者はプルーフオブワークで支払い、その難易度は流入量に応じて調整され、サブスクライバーはそれを免除されます。Bitsocial では、CAPTCHA から許可リスト、支払いまで、各コミュニティが独自のチャレンジを選びます。[カスタムのスパム対策チャレンジ](/custom-challenges/) を参照してください。

### インフラ

Mirage にはブロックチェーンが必要です。バリデーターはすべての操作についてコンセンサスを取り、各ノードは完全なサーバースタックを動かしたうえで、大量のトークンをステークしておかなければなりません。Bitsocial にはチェーンがありません。コミュニティノードはデスクトップアプリや `bitsocial-cli` から一般向けのハードウェアで動き、閲覧者もコンテンツの共有を手伝えます。

### ネットワーク全体への支配力

Mirage には、バリデーターのステークで重み付けされたオンチェーンのガバナンスがあります。ガバナンスは難易度、価格、トークンの発行量を変更し、トークンをミントまたはバーンし、管理者を任命できます。その管理者による削除は、リファレンスインデクサーがどの投稿にも適用します。チェーンのコードでは、ガバナンスが [アカウントを削除する](https://github.com/MirageFoundation/mirage-node/blob/142a2e4e2542b6a3c9cc6d71591c282e5e5a9503/blockchain/x/core/module/module.go#L2572-L2573) ことや [任意のアドレスからトークンを送る](https://github.com/MirageFoundation/mirage-node/blob/142a2e4e2542b6a3c9cc6d71591c282e5e5a9503/blockchain/x/core/module/module.go#L2656) ことも可能です。2026 年 10 月の時点では 4 つのバリデーターがチェーンのブロックを生成しており、その 4 つすべてをプロジェクト自身のランブックが管理していました。

Bitsocial にはプロトコルレベルの管理者がいません。コミュニティ所有者が自分のコミュニティをモデレートし、何を表示するかはアプリが選びます。[グローバルな禁止ではなくローカルなモデレーション](/local-moderation/) を参照してください。

### ブラウザ

Mirage の Web クライアントはノードの HTTP クライアントです。ブラウザは操作に署名しますが、ピアツーピアネットワークには参加しません。Bitsocial のアプリは、ブラウザタブの中でピアツーピアノードを動かせます。[ブラウザ ピアツーピア](/browser-p2p/) を参照してください。

## 比較

| 論点                 | Mirage                                                                                                                | Bitsocial                                                                                |
| -------------------- | --------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 分類                 | 独自のブロックチェーン (Cosmos SDK) 上のフォーラム                                                                    | ピアツーピアのコミュニティネットワーク                                                   |
| アイデンティティ     | 12 単語のシードから導出される secp256k1 鍵と、オンチェーンのユーザー名                                                | 利用者とコミュニティの Ed25519 鍵ペア                                                    |
| 投稿の保存場所       | チェーンのトランザクション、その後は各ノードの PostgreSQL データベース                                                | コミュニティ所有者のノードと、そのコミュニティを読んでシードするピア                     |
| 誰が公開を維持するか | それぞれ 10,000,000 MIRAGE を保有するバリデーターノード                                                               | コミュニティ所有者のノードと補助のシーダー                                               |
| コミュニティ         | 有料のキュレーターチームが競合する、所有者のいない名前                                                                | 鍵ペアが所有し、所有者のノードが投稿を受理または拒否                                     |
| スパム対策           | ネットワーク全体のプルーフオブワーク。サブスクライバーは免除                                                          | 投稿が受理される前に課される、各コミュニティのチャレンジ                                 |
| モデレーション       | キュレーターチームのビュー、個人のフィルター、ガバナンスが任命する管理者                                              | コミュニティ所有者が自分のコミュニティをモデレートし、何を表示するかはアプリが選ぶ       |
| 経済                 | サブスクリプション、報酬、バリデーターのステークに使う MIRAGE トークン                                                | プロトコルにはない。チャレンジで支払いやトークンを求めることは可能                       |
| ブラウザ             | ノードの HTTP クライアント                                                                                            | 通常のブラウザタブ内で動くピアツーピアノード                                             |
| 主なトレードオフ     | 共有された順序付きの 1 つの状態と手軽な登録があるが、バリデーターが少なく、ネットワーク全体に及ぶガバナンス権限がある | チェーンもステークも不要だが、グローバルな順序はなく、古いコンテンツが永続する保証もない |
