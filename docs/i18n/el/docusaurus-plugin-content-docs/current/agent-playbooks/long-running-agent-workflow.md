# Μακροχρόνια εργασία πρακτόρων

Χρησιμοποιήστε μόνιμη κατάσταση εργασίας όταν η δουλειά χρειάζεται να συνεχιστεί αργότερα ή να παραδοθεί σε άλλον, ή όταν μια μεμονωμένη εκτέλεση είναι τόσο μεγάλη ώστε η συμπίεση του context θα μπορούσε να χάσει τα ίχνη της εργασίας που απομένει. Οι μικρές εργασίες δεν χρειάζονται πίνακα εργασιών ή αρχείο προόδου. Για κοινή εργασία, κρατήστε ένα σύντομο `feature-list.json` και ένα `progress.md` σε έναν φάκελο `docs/agent-runs/<slug>/` ειδικά για την εργασία, χρησιμοποιώντας τα υπάρχοντα πρότυπα όπου βοηθούν.

Καταγράψτε το ζητούμενο αποτέλεσμα, τον τρέχοντα κλάδο/worktree, ποιος έχει την ευθύνη για ποια αρχεία, τις αλλαγές που ολοκληρώθηκαν, τους ελέγχους μαζί με τα αποτελέσματά τους, τις διεργασίες/συνεδρίες που σας ανήκουν και το επόμενο ανοιχτό βήμα. Μην αποθηκεύετε διαπιστευτήρια ή αυθαίρετα αντίγραφα πηγαίου κώδικα. Επισημάνετε μια λειτουργία ως ολοκληρωμένη μόνο όταν έχουν επαληθευτεί τα κριτήρια αποδοχής της.

Όταν συνεχίζετε, εξετάστε την κατάσταση του Git, την πιο πρόσφατη πρόοδο και τον σχετικό πηγαίο κώδικα πριν κάνετε αλλαγές. Επαναχρησιμοποιήστε συμβατούς πόρους που σας ανήκουν· ξεκινήστε dev server μόνο όταν τον χρειάζεται ο επόμενος έλεγχος. Επιλέξτε ελέγχους ανάλογα με τον αντίκτυπο, με βάση το [verification.md](https://github.com/bitsocialnet/bitsocial-web/blob/master/docs/agent-playbooks/verification.md), αντί να επαναλαμβάνετε ένα πλήρες πέρασμα ενώ τίποτα δεν έχει αλλάξει.

Κρατήστε τη σχετική εργασία που ανατίθεται σε άλλους πράκτορες οριοθετημένη και χωρίς επικαλύψεις. Ένας μόνο πράκτορας έχει την ευθύνη των βαριών ελέγχων και των συνεδριών προγράμματος περιήγησης. Ενημερώστε τη μόνιμη κατάσταση όταν ένα ολοκληρωμένο τμήμα, ένα εμπόδιο ή μια παράδοση αλλάζει όσα χρειάζεται να γνωρίζει ο επόμενος συνεργάτης· μην καταγράφετε μηχανικά κάθε εντολή.
