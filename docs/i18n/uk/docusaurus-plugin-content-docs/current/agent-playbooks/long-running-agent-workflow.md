# Тривала робота агентів

Використовуйте довговічний стан завдання, коли роботу треба буде відновити чи передати або коли один запуск триває так довго, що через стискання контексту можна втратити з поля зору решту роботи. Невеликим завданням не потрібні ні дошка, ні файл прогресу. Для спільної роботи тримайте стислі `feature-list.json` і `progress.md` в окремому для завдання каталозі `docs/agent-runs/<slug>/`, за потреби використовуючи наявні шаблони.

Записуйте запитаний результат, поточну гілку/робоче дерево, володіння файлами, виконані зміни, перевірки з їхніми результатами, власні процеси/сесії та наступний невирішений крок. Не зберігайте облікових даних чи довільних дампів вихідного коду. Позначайте функцію виконаною лише тоді, коли перевірено її критерії приймання.

Під час відновлення перевірте стан Git, останній запис прогресу та відповідний вихідний код, перш ніж щось редагувати. Повторно використовуйте сумісні власні ресурси; запускайте dev-сервер лише тоді, коли він потрібен для наступної перевірки. Добирайте перевірки за впливом, користуючись [verification.md](https://github.com/bitsocialnet/bitsocial-web/blob/master/docs/agent-playbooks/verification.md), а не повторюйте повний прохід без змін.

Тримайте пов’язану делеговану роботу чітко окресленою й без перетинів. Важкі перевірки та браузерні сесії належать одному агентові. Оновлюйте довговічний стан, коли завершений фрагмент, блокер чи передача змінюють те, що потрібно знати наступному учасникові; не записуйте механічно кожну команду.
