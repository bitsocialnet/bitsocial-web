# Переклади

Сайт about використовує JSON-файли i18next у `about/public/translations/{lang}/default.json`. Переклади вихідних файлів Docusaurus зберігаються окремо в `docs/i18n/`.

## Ключі сайту about

Використовуйте `.agents/skills/translate/SKILL.md`. Визначайте поточні локалі з диска та зберігайте заповнювачі, розмітку, технічні терміни й назви брендів. Для більших запитів дочірні агенти можуть генерувати незалежні словники, але всі записи в локалі послідовно застосовує один батьківський агент; скрипт оновлення не має блокування для записувачів.

Використовуйте унікальний шлях до словника, що належить цьому завданню. Перегляньте результат через `node scripts/update-translations.js --key <key> --map <map.json> --include-en --dry`, а потім застосуйте з тими самими аргументами та `--write`. Після запису перевірте покриття/значення й видаліть лише тимчасові словники, що належать цьому завданню.

Для запитаних видалень використовуйте `--delete`. Перегляньте знахідки `--audit --dry`, перш ніж виконувати дозволений `--audit --write`; динамічні ключі перекладу потребують ручної перевірки вихідного коду. Копіюйте англійський текст у кожну локаль лише для технічного терміна, бренду чи заповнювача.

## Сторінки Docusaurus

`scripts/translate-docs.py` — це скрипт масового запису для всіх сторінок і локалей без фільтра для окремих файлів; не використовуйте його для вузької правки перекладу. `scripts/check-docs-translations.py` — це верифікатор лише для читання, який підтримує `--locales` і `--paths`.

Тримайте блоки коду, посилання, вбудований код, адреси контрактів, заголовки, таблиці та блоки приміток узгодженими з англійським джерелом. Усувайте помилки верифікатора; попередження `frontmatter-untranslated` для назв брендів можуть бути очікуваними. Дотримуйтеся `docs/AGENTS.md` і виконуйте збірку з кореня, коли змінюєте тему чи поведінку i18n документації, щоб статичний вивід і Pagefind залишалися узгодженими.

## Необов’язкове семантичне рецензування

Для вибраних ключів i18next використовуйте `scripts/jev/translation-README.md`. Для сторінок документації спершу запустіть `node scripts/jev/docs-translations.mjs --locales it,de --paths browser-p2p.md`. Ця команда вимагає явного вибору локалі/сторінки, запускає структурний верифікатор і позначає семантичне рецензування як неперевірене, доки не ввімкнено живий інференс. Додавайте `--live` лише тоді, коли завдання має дозвіл на використання постачальника та бюджет; спільна приватна конфігурація машини надає облікові дані й закріплену модель. Змінні середовища та `--model` можуть перевизначити це налаштування. Команда ніколи не редагує переклади.

Адаптер сторінок зберігає контекст усієї сторінки й обмежує кожну сторінку 24 КБ, а кожен запуск — 30 парами. Для більших сторінок підготуйте явно вирівняні пари абзаців джерела й перекладу для `translations.mjs --pairs`; не створюйте пари абзаців автоматично за індексом. Семантичні результати мають дорадчий характер: переглядайте виявлені проблеми й невизначеність і зберігайте детерміновані перевірки коду/посилань/адрес.
