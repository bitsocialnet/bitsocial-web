# Хуки агентів

Закомічені хуки життєвого циклу лише форматують успішно відредаговані файли JavaScript/TypeScript через установлений oxfmt. Спільна логіка міститься в `scripts/agent-hooks/format.mjs`; кожна нативна обгортка делегує роботу їй.

| Застосунок | Нативна конфігурація | Подія |
|---|---|---|
| Codex | `.codex/hooks.json` | `PostToolUse`, `apply_patch` |
| Claude Code | `.claude/settings.json` | `PostToolUse`, `Edit|Write|MultiEdit` |
| Cursor | `.cursor/hooks.json` | `afterFileEdit` |

Claude не читає окремий `.claude/hooks.json`. Кожен застосунок і далі сам контролює довіру до проєкту та те, чи ввімкнено хуки; перевіряйте його поточні налаштування, а не обходьте довіру. `.codex/config.toml` — це конфігурація репозиторію, а не реєстр команд хуків.

Форматувальник перевіряє подію/корисне навантаження, успішність правки, розширення файлу та належність файлу до репозиторію, зокрема з урахуванням символьних посилань. Якщо бракує залежностей або вхідні дані нерелевантні, нічого не виконується. Команди використовують масив аргументів із вимкненим мережевим доступом Corepack; хуки не встановлюють залежностей, не запускають збірок чи рев’ю і не змінюють стан Git.

Запускайте перевірки явно відповідно до [verification.md](https://github.com/bitsocialnet/bitsocial-web/blob/master/docs/agent-playbooks/verification.md). Після зміни робочого процесу запускайте `yarn ai-workflow:sync`, `yarn ai-workflow:check` і `yarn ai-workflow:test`. Фікстури використовують одноразові файли та фіктивні виклики форматувальника; вони не доводять, що кожен застосунок завантажив свою конфігурацію. Після оновлень перезавантажте застосунок і перевірте його каталог.

Навичка дизайну Impeccable та її виконувані допоміжні скрипти й далі доступні на вимогу в `.agents/skills/impeccable`. Її колишній хук Codex вказував на відсутній каталог; тепер дизайнерський робочий процес запускається, коли обрано його навичку, без постійно ввімкненого дизайнерського хука. Навичка не повинна переналаштовувати хуки проєкту як побічний крок дизайну.
