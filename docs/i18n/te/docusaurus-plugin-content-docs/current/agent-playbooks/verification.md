# ధృవీకరణ

మారిన ప్రవర్తన, ఇంకా మిగిలి ఉన్న అనిశ్చితిని బట్టి తనిఖీలను ఎంచుకోండి. అదే తుది స్థితి కోసం ఇప్పటికే విజయవంతమైన ఆధారాలను తిరిగి వాడండి; సంబంధిత సవరణలు లేదా వైఫల్యాల తర్వాత మళ్లీ నడపండి. స్పష్టమైన CI/రిలీజ్/వినియోగదారు అవసరాలు ఇప్పటికీ వర్తిస్తాయి.

## ప్రాజెక్ట్ తనిఖీలు

- `yarn build:verify` ప్రభావిత వర్క్‌స్పేస్‌ను ఎంచుకుంటుంది. పరిధి ముందే తెలిసినప్పుడు `yarn build:about`, `yarn build:chain`, `yarn build:stats-monitor` లేదా `yarn docs:build:verify` వాడండి.
- `yarn build` ఉద్దేశపూర్వకంగానే అన్ని డాక్స్ లొకేల్‌లతో సహా పూర్తి ప్రొడక్షన్ about/డాక్స్ బిల్డ్‌ను నడుపుతుంది. రిలీజ్-వ్యాప్త ధృవీకరణ కోసం లేదా ఆ పరిధి అవసరమైన మార్పుల కోసం దీన్ని వాడండి.
- `yarn lint`, `yarn typecheck`, `yarn format:check` ఇప్పటికే ఉన్న రిపాజిటరీ గేట్‌లను కవర్ చేస్తాయి; ఒక చిన్న స్క్రిప్ట్ సవరణ కోసం ముందుగా దాని లక్ష్యిత సింటాక్స్/ఫిక్స్చర్/ఫార్మాట్ తనిఖీలను వాడండి.
- మానిఫెస్ట్/లాక్ మార్పులకు `corepack yarn install`, `yarn deps:check-pinned`, `yarn deps:check-hardened` అవసరం. డిపెండెన్సీలు/ఇంపోర్ట్‌ల విషయంలో `yarn knip` సలహా మాత్రమే.
- డాక్స్ అనువాద తనిఖీలు [translations.md](translations.md)లో ఉన్నాయి; ఒక లక్ష్యిత డాక్స్ మార్పు కోసం బల్క్ అనువాద రైటర్‌ను నడపవద్దు.

## బ్రౌజర్ ఆధారాలు మరియు యాజమాన్యం

చిన్న, వేరుగా ఉండే బ్రౌజర్ మార్పుల కోసం Chrome వాడండి. భాగస్వామ్య CSS/లేఅవుట్/రెస్పాన్సివ్‌నెస్, బ్రౌజర్‌పై ఆధారపడే APIలు, విస్తృత ఇంటరాక్షన్‌లు, రిలీజ్‌లు లేదా స్పష్టమైన క్రాస్-బ్రౌజర్ ప్రమాణాల కోసం Firefox, WebKitలను కూడా చేర్చండి. ప్రభావిత మొబైల్ లేఅవుట్‌లు/టచ్ ప్రవర్తనను కూడా కలపండి. కేవలం వ్యూపోర్ట్ పరిమాణం మార్చడం టచ్ ఎమ్యులేషన్ కాదు. ఉదాహరణలు అందుబాటులో ఉన్నాయని ఊహించుకోకుండా, అసలు మార్గాలను, కంటెంట్‌ను సోర్స్ నుండి ఎంచుకోండి.

`./scripts/pw-session.sh` ద్వారా `playwright-cli` వాడండి. యంత్రం మొత్తంలో ఒకేసారి ఒకే బ్రౌజర్ చురుకుగా ఉంటుంది; ఎంచుకున్న ఇంజిన్‌లు ఒకదాని తర్వాత ఒకటి నడుస్తాయి, వైఫల్యం తర్వాత కూడా తన యాజమాన్యంలోని ప్రతి కచ్చితమైన సెషన్ మూసివేయబడుతుంది. అనుమతి ఉన్న, కాలర్ యాజమాన్యంలోని సెషన్‌ను మూసివేయకుండానే తిరిగి వాడండి. గ్లోబల్ బ్రౌజర్ క్లీనప్‌ను ఎప్పుడూ వాడవద్దు, యాజమాన్యం స్పష్టంగా లేని సర్వర్‌ను ఆపవద్దు. డాక్యుమెంటేషన్-మాత్రమే పనికి బ్రౌజర్/సర్వర్ అవసరం లేదు.

పనితీరు పనిలో, సమానమైన వ్యూపోర్ట్, కంటెంట్, నెట్‌వర్క్/CPU సెట్టింగ్‌లు, బిల్డ్ మోడ్, కొలత ఓవర్‌హెడ్‌తో అదే ఫ్లోను పోల్చండి. పరిశీలనలను అనుమానిత కారణాల నుండి వేరు చేయండి. ఈ కొలతలు అసలు అభ్యర్థనకు సమాధానం ఇచ్చేటప్పుడు ప్రొఫైలింగ్ నైపుణ్యాన్ని వాడండి.

## తుది ఆధారాలు

భారీ ధృవీకరణ బాధ్యత ఒకే ఏజెంట్‌ది. చురుకుగా ఉన్న వర్క్‌లోడ్‌లను పరిశీలించి, ఇన్‌స్టాల్‌లు, బిల్డ్‌లు/పూర్తి సూట్‌లు, Doctor, Android/Electron పని, బ్రౌజర్ ప్రొఫైలింగ్‌లను ఒకదాని తర్వాత ఒకటిగా నడపండి. ఆదేశాలు/ఫలితాలను, నిర్దిష్ట పరిమితులను నివేదించండి; తప్పిపోయిన డేటా లేదా వదిలేసిన ఇంజిన్ ఉత్తీర్ణ ఫలితం కాదు. టూలింగ్ ఫిక్స్చర్‌లు ఫార్మాట్‌లను, పని తీరును ధృవీకరిస్తాయి; ఎండ్-టు-ఎండ్ యాప్ డిస్కవరీని గానీ మోడల్ నిర్ణయాల నాణ్యతను గానీ కాదు.

## ఆటోమేటిక్ React తనిఖీలు

`yarn agent:verify` ఎంచుకున్న బిల్డ్‌లను నడిపి, ఆ తర్వాత `yarn doctor:check`, `yarn perf:check`లను నడుపుతుంది. `perf:check`లో కలెక్టర్ అనుకూలత, ఉద్దేశపూర్వక-రిగ్రెషన్ సెల్ఫ్‌టెస్ట్ ఉంటాయి, కాబట్టి CIకి గానీ ఏజెంట్ ధృవీకరణ మార్గానికి గానీ వేరే `perf:test` పాస్ అవసరం లేదు. పిన్ చేసిన బ్రౌజర్ టూలింగ్‌ను `yarn perf:install`తో ఒకసారి ఇన్‌స్టాల్ చేయండి (Linux CIలో `--with-deps`). పూర్తి సంబంధిత పాస్ తర్వాత లక్ష్యిత రీరన్‌ల కోసం టార్గెట్/సినారియో ఫిల్టర్‌లను వాడండి. సినారియో బడ్జెట్‌లు `scripts/react-perf/config.mjs`లో స్పష్టంగా ఉన్నాయి; సమర్థించదగిన బేస్‌లైన్ మార్పును పరిగణించే ముందు ఆధారాలను భద్రపరచి, రిగ్రెషన్‌ను సరిచేయండి. సాధారణ ప్రొడక్షన్ బిల్డ్‌లు Bippyని వదిలేస్తాయి; ప్రత్యేకమైన `build:profile:*` ఆదేశాలు అధికారిక React ప్రొఫైలింగ్ ఇన్‌స్ట్రుమెంటేషన్‌ను అందిస్తాయి.

about `apps-search` సినారియో ప్రతి అక్షరానికి URL/ఇన్‌పుట్ విలువలు కమిట్ అయ్యే వేగంతో సాగుతుంది. దాని ఉత్తీర్ణ ఫలితం ఆ కమిట్ అయిన-క్వెరీ క్రమాన్ని కవర్ చేస్తుంది, వేగంగా టైప్ చేసేటప్పుడు ప్రతిస్పందనను కాదు. అక్షరాలు కోల్పోవడాన్ని లేదా ఇన్‌పుట్ ప్రతిస్పందనను అంచనా వేసేటప్పుడు ప్రత్యేకమైన వేగవంతమైన-ఇన్‌పుట్ పునరుత్పత్తిని వాడండి.
