# నైపుణ్యాలు మరియు సాధనాలు

భాగస్వామ్య నైపుణ్యాలు `.agents/skills/`లో ఉంటాయి. ఈ సోర్స్‌లను సవరించి, ఆ తర్వాత Claude Code కోసం `.claude/skills/`ను రూపొందించడానికి `yarn ai-workflow:sync` నడపండి. Codex, Cursor `.agents/skills/`ను నేరుగా కనుగొంటాయి; నకిలీ `.codex/skills/` లేదా `.cursor/skills/` రూట్ డైరెక్టరీలను తిరిగి తీసుకురావద్దు.

భాగస్వామ్య రోల్ ప్రాంప్ట్‌లు `.agents/roles/*.md`లో ఉంటాయి. ఇది ఈ రిపాజిటరీకి ప్రత్యేకమైన సోర్స్ ఫార్మాట్, నేటివ్ ఏజెంట్ డిస్కవరీ మార్గం కాదు. `scripts/ai-workflow-files.mjs` ఈ సోర్స్‌లను కింద ఉన్న యాప్-నిర్దిష్ట ఫైల్‌లుగా మారుస్తుంది; `yarn ai-workflow:sync` వాటిని రాస్తుంది. తాజా చెక్‌అవుట్‌లో ముందుగా జనరేటర్‌ను నడపకుండానే నేటివ్ కాన్ఫిగరేషన్ ఉండేలా, రూపొందించిన ఫైల్‌లను వాటి సోర్స్‌లతో పాటే కమిట్ చేయండి. ఒక సోర్స్‌ను తొలగించిన తర్వాత, దాని నుండి రూపొందిన పాత అవుట్‌పుట్‌లను స్పష్టంగా తొలగించండి; వాలిడేటర్ ఫైల్‌లను నిశ్శబ్దంగా తొలగించకుండా వాటిని నివేదిస్తుంది.

## నేటివ్ డిస్కవరీ మార్గాలు

2026-09-12న అధికారిక డాక్యుమెంటేషన్‌తో పోల్చి ధృవీకరించబడింది:

| యాప్        | ప్రాజెక్ట్ సూచనలు                                                                                  | ఈ రిపాజిటరీ వాడే నైపుణ్యాలు                  | ఈ రిపాజిటరీ వాడే కస్టమ్ ఏజెంట్లు        |
| ----------- | -------------------------------------------------------------------------------------------------- | -------------------------------------------- | --------------------------------------- |
| Codex       | `AGENTS.md`                                                                                        | `.agents/skills/<name>/SKILL.md`             | రూపొందించిన `.codex/agents/<name>.toml` |
| Cursor      | `AGENTS.md`; Cursor-నిర్దిష్ట షరతులతో కూడిన నియమాల కోసం `.cursor/rules/*.mdc` అందుబాటులోనే ఉంటుంది | `.agents/skills/<name>/SKILL.md`             | రూపొందించిన `.cursor/agents/<name>.md`  |
| Claude Code | `CLAUDE.md` `@AGENTS.md`ను ఇంపోర్ట్ చేస్తుంది                                                      | రూపొందించిన `.claude/skills/<name>/SKILL.md` | రూపొందించిన `.claude/agents/<name>.md`  |

మూలాలు: [Codex నైపుణ్యాలు](https://learn.chatgpt.com/docs/build-skills), [Codex సబ్‌ఏజెంట్లు](https://learn.chatgpt.com/docs/agent-configuration/subagents), [Cursor నియమాలు](https://cursor.com/docs/rules), [Cursor నైపుణ్యాలు](https://cursor.com/docs/skills), [Cursor సబ్‌ఏజెంట్లు](https://cursor.com/docs/subagents), [Claude మెమరీ](https://code.claude.com/docs/en/memory), [Claude నైపుణ్యాలు](https://code.claude.com/docs/en/skills), [Claude సబ్‌ఏజెంట్లు](https://code.claude.com/docs/en/sub-agents).

నేటివ్ ఏజెంట్ డైరెక్టరీలను `.agents/roles`తో భర్తీ చేయవద్దు, Claude `.agents/skills`ను కనుగొంటుందని ఊహించవద్దు. అక్కడ సూచించిన ఫైల్‌ను Claude సాధారణ ప్రాజెక్ట్ కాంటెక్స్ట్‌గా ఇప్పటికీ చదవగలదు. అనుకూలత కోసం Cursor `.claude/skills`ను కూడా కనుగొంటుంది; కాపీలు సింక్‌లోనే ఉంటాయి, కానీ దాని ప్రచురిత నైపుణ్యాల గైడ్ ఈ రూట్ డైరెక్టరీల మధ్య నకిలీల తొలగింపు గురించి పేర్కొనలేదు. నకిలీ ఎంట్రీలు కనిపించవని హామీ ఇవ్వకుండా, ఇన్‌స్టాల్ చేసిన యాప్ నైపుణ్యాల కేటలాగ్‌ను తనిఖీ చేయండి.

రూపొందించిన టెక్స్ట్ అన్ని ప్లాట్‌ఫామ్‌లలో ఒకేలా ఉండేలా AI డైరెక్టరీలు `.gitattributes` ద్వారా LF లైన్ ఎండింగ్‌లను వాడతాయి. నైపుణ్యాల సహాయక అసెట్‌లు బైట్‌లుగా యథాతథంగా కాపీ అవుతాయి.

## రోల్‌లు మరియు మోడల్‌లు

`browser-check`, `profiler`, `test-apk`, `translator`, `reviewer` కోసం కస్టమ్ రోల్‌లను ఉంచండి. సాధారణ అమలు, కోడ్ డిస్కవరీ కోసం హార్నెస్‌లో అంతర్నిర్మితంగా ఉన్న worker/general-purpose లేదా explorer రోల్‌ను వాడండి. పేరెంట్ అంగీకార ప్రమాణాలను, యాజమాన్యాన్ని కేటాయిస్తుంది; భారీ తనిఖీలను ఒకే యజమాని నడుపుతారు.

Codex ఏజెంట్ ఫైల్‌లలో `name`, `description`, `developer_instructions` ఉంటాయి. `.codex/config.toml` `max_concurrent_threads_per_session`ను ఉపయోగించి ఏకకాలంలో నడిచే చైల్డ్ ఏజెంట్ల సంఖ్యను నాలుగుకు పరిమితం చేస్తుంది. భాగస్వామ్య రోల్ మెటాడేటాలో పేరు, వివరణ, ఐచ్ఛిక శాండ్‌బాక్స్ మోడ్ ఉంటాయి; అందులో ఉద్దేశపూర్వకంగానే మోడల్ ఫీల్డ్‌లు లేవు.

మూడు యాప్‌లలోనూ కమిట్ చేసిన నైపుణ్యాలు, కస్టమ్ ఏజెంట్ల నుండి మోడల్, రీజనింగ్ ఫీల్డ్‌లను వదిలేయండి. దీనివల్ల ప్రతి యాప్ డాక్యుమెంట్ చేసిన ప్రాధాన్యత క్రమం ప్రకారం రన్‌టైమ్ ఇన్‌వోకేషన్ ఎంపికలు, వినియోగదారు డిఫాల్ట్‌లు, పేరెంట్ నుండి వారసత్వం పనిచేస్తాయి. Claude ఫ్యామిలీ అలియాస్‌లు వెర్షన్ నిర్వహణను తగ్గిస్తాయి కానీ ఇప్పటికీ ఒక ఫ్యామిలీని ఎంచుకుంటాయి; వెర్షన్ ఉన్న Cursor మోడల్‌కు భవిష్యత్తులో నవీకరణలు అవసరం. అవసరమైనప్పుడు అలాంటి ఎంపికలను వినియోగదారు/సెషన్ సెట్టింగ్‌లలో ఉంచండి. వారసత్వం ప్రస్తుత అత్యుత్తమ మోడల్‌ను ఆటోమేటిక్‌గా ఎంచుకుంటుందని హామీ ఇవ్వదు. `latest` అలియాస్‌ను కల్పించవద్దు, సాధారణ పనులకు మోడల్-కేటలాగ్ పరిశోధనను జోడించవద్దు. [Codex ఎంపిక](https://learn.chatgpt.com/docs/agent-configuration/subagents), [Claude ఎంపిక](https://code.claude.com/docs/en/sub-agents#choose-a-model), [Cursor ఎంపిక](https://cursor.com/docs/subagents#model-configuration) చూడండి.

`sandbox-mode: read-only` Codex శాండ్‌బాక్స్‌కు, Cursor యొక్క `readonly`కు మ్యాప్ అవుతుంది; Claude విషయంలో టూల్ జాబితా, రోల్ సూచనలు దాని రివ్యూ వర్క్‌ఫ్లోను పరిమితం చేస్తాయి, కానీ Bash యాక్సెస్ OS-స్థాయి శాండ్‌బాక్స్ కాదు.

వర్తించే చోట, వినియోగదారు పిలిచే వర్క్‌ఫ్లోల కోసం భాగస్వామ్య నైపుణ్యాల ఫ్రంట్‌మ్యాటర్ `disable-model-invocation: true`ను వాడుతుంది. Codexలో దీనికి సమానమైన సెట్టింగ్ `agents/openai.yaml`లో `policy.allow_implicit_invocation: false`గా ఉంటుంది; వాలిడేటర్ రెండింటినీ తప్పనిసరి చేస్తుంది. ఇన్‌వోకేషన్ మెటాడేటా స్పష్టమైన అనుమతి నియమాలకు అనుబంధం మాత్రమే; ఒక నైపుణ్యంలో ప్రచురణ దశలు ఉన్నంత మాత్రాన రివ్యూ అభ్యర్థన ప్రచురణకు ఎప్పుడూ అనుమతి ఇవ్వదు.

## తనిఖీలు మరియు డిస్కవరీ

- `yarn ai-workflow:sync` ఇన్‌స్టాల్ చేసిన `js-yaml`, `smol-toml`లను వాడి అనుకూలత అవుట్‌పుట్‌లను మళ్లీ రూపొందిస్తుంది.
- `yarn ai-workflow:check` సోర్స్/ఫ్రంట్‌మ్యాటర్/కాన్ఫిగ్‌లను పార్స్ చేసి, రూపొందించిన అవుట్‌పుట్‌లు, ఇన్‌వోకేషన్ మెటాడేటా, మోడల్-ఫీల్డ్ స్థానం, ఫార్మాటర్-మాత్రమే హుక్ వైరింగ్‌ను తనిఖీ చేస్తుంది. ఇది మోడల్ ఐడెంటిఫైయర్‌లను ప్రొవైడర్ కేటలాగ్‌తో సరిపోల్చదు.
- `yarn ai-workflow:test` హుక్ పేలోడ్‌లు, వర్క్‌ఫ్లో జనరేషన్/వాలిడేషన్ కోసం వేరుగా ఉండే Node ఫిక్స్చర్‌లను నడుపుతుంది.
- ఒక ఏజెంట్ అప్లికేషన్‌ను అప్‌గ్రేడ్ చేసిన తర్వాత, ఆ అప్లికేషన్‌లో నైపుణ్యం/రోల్ డిస్కవరీని ధృవీకరించండి. సింటాక్స్/పారిటీ తనిఖీలు లోడర్ తనిఖీకి ప్రత్యామ్నాయం కావు. ఇప్పటికే ఉన్న సెషన్ పాత కేటలాగ్‌నే ఉంచుకుంటే అప్లికేషన్‌ను రీలోడ్ చేయండి.
- హుక్‌లకు హార్నెస్ ప్రాజెక్ట్ ట్రస్ట్, హుక్ సమీక్ష అవసరం; ఒక తనిఖీని పాస్ చేయించడం కోసం ట్రస్ట్‌ను దాటవేయవద్దు. [hooks-setup.md](hooks-setup.md) చూడండి.

## ఉపయోగకరమైన సూచనలను నిర్వహించడం

[నైపుణ్యాలు, ప్రాంప్ట్‌లపై OpenAI మార్గదర్శకాలను](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) (2026-09-12న సమీక్షించబడింది) అనుసరించండి: వివరణలను కచ్చితంగా ఉంచండి, సంబంధితమైనప్పుడు మాత్రమే వివరాలను లోడ్ చేయండి, వినియోగదారు అభ్యర్థించిన పరిధిని కాపాడండి. భాగస్వామ్య నైపుణ్యాలు వేర్వేరు మోడల్‌లకు ఉపయోగపడతాయి; సాధారణ అమలు ఎంపికలను అనుమతిస్తూనే ప్రాజెక్ట్-నిర్దిష్ట స్థిర నియమాలను కాపాడండి.

ఒక నైపుణ్యం ప్రయోజనం, నిర్ణయ సరిహద్దులు, ముఖ్యమైన పరిమితులను `SKILL.md`లో ఉంచండి. విస్తృతమైన మోడ్-నిర్దిష్ట ఆదేశాలను లేదా ఉదాహరణలను ఐచ్ఛిక రిఫరెన్స్‌లుగా లింక్ చేయండి. చిన్న వివరణలలో ట్రిగ్గర్ షరతులను ముందుగానే ఉంచండి; సరిపోలే కీవర్డ్ ఒక్కటే పనిని విస్తరించకూడదు. ఇప్పటికే ఉన్న ఇన్‌వోకేషన్ మెటాడేటా ప్రవర్తనను ఉద్దేశపూర్వకంగా మారుస్తున్నప్పుడు తప్ప దాన్ని అలాగే ఉంచండి.

సూచనలలో గణనీయమైన మార్పు తర్వాత, కొన్ని ప్రాతినిధ్య చిన్న, పెద్ద అభ్యర్థనలతో పరీక్షించండి. ఏ నైపుణ్యాలు/రిఫరెన్స్‌లు ఎంపికయ్యాయో, చర్యలు పరిధిలోనే ఉన్నాయో లేదో, ధృవీకరణ మార్పుకు తగినట్లుగా ఉందో లేదో, అనుమతి పొందిన పని పూర్తయిందో లేదో తనిఖీ చేయండి. స్కీమా, ఫిక్స్చర్ పరీక్షలు టూలింగ్ సరైనదని నిర్ధారిస్తాయి, ఏజెంట్ నిర్ణయాల నాణ్యతను కాదు.

## సాధనాలు మరియు బ్రౌజర్ యాజమాన్యం

ఇప్పటికే ఉన్న నైపుణ్యాలు/సాధనాల కేటలాగ్‌కు, ఇన్‌స్టాల్ చేసిన ప్రాజెక్ట్ CLIలకు ప్రాధాన్యం ఇవ్వండి. GitHub కోసం `gh`, బ్రౌజర్ ధృవీకరణ కోసం `playwright-cli` వాడండి; లైబ్రరీ ప్రవర్తన ముఖ్యమైనప్పుడు అధికారిక/వెర్షన్-నిర్దిష్ట డాక్యుమెంటేషన్‌ను వాడండి. ఇప్పటికే ఉన్న ఫార్మాటర్‌ను నడపడం కోసమే నకిలీ నైపుణ్యాలను ఇన్‌స్టాల్ చేయడం లేదా పిన్ చేయని ప్యాకేజీని తెచ్చుకోవడం మానుకోండి.

MCP ఓవర్‌హెడ్ హార్నెస్‌పై ఆధారపడి ఉంటుంది: వాయిదా వేసిన టూల్ లోడింగ్ ప్రతి స్కీమాను ముందుగానే లోడ్ చేయకుండా నివారించగలదు. MCPనే పాతబడినదిగా భావించకుండా, ఇంటిగ్రేషన్‌లను సంబంధితంగా ఉంచండి. పునరుత్పాదకత, వనరుల నియంత్రణ కోసం ఇప్పటికే ఉన్న CLI ఎంపికలు ఉపయోగకరంగానే ఉంటాయి.

అన్ని బ్రౌజర్ సెషన్‌లు `./scripts/pw-session.sh`ను వాడతాయి; ఇది యంత్రం మొత్తంలో ఒకేసారి ఒకే చురుకైన బ్రౌజర్ ఉండేలా అమలు చేస్తుంది. డిఫాల్ట్‌గా తాజా, వేరుగా ఉండే సెషన్‌ను వాడండి. ప్రస్తుత వ్యక్తిగత బ్రౌజర్‌ను యాక్సెస్ చేయడానికి స్పష్టమైన అనుమతి అవసరం; తదుపరి దశలలో ఆ అనుమతిని తిరిగి వాడండి. ప్రభావిత ప్రవర్తనకు తగిన బ్రౌజర్‌లు/వ్యూపోర్ట్‌లను ఎంచుకోండి, ఎంచుకున్న ఇంజిన్‌లను ఒకదాని తర్వాత ఒకటి నడపండి, క్లీనప్‌లో కచ్చితమైన పేరున్న సెషన్‌ను మూసివేయండి, `close-all`/`kill-all`ను ఎప్పుడూ వాడవద్దు. `playwright-cli` నైపుణ్యాన్ని, [verification.md](https://github.com/bitsocialnet/bitsocial-web/blob/master/docs/agent-playbooks/verification.md)ను చూడండి.
