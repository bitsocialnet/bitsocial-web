# దీర్ఘకాలిక ఏజెంట్ పని

పనిని మళ్లీ కొనసాగించాల్సి వచ్చినప్పుడు లేదా హ్యాండ్‌ఆఫ్ అవసరమైనప్పుడు, లేదా కాంటెక్స్ట్ కంపాక్షన్ వల్ల మిగిలిన పనిని ట్రాక్ చేయలేకపోయేంత పొడవుగా ఒకే రన్ సాగినప్పుడు మన్నికైన టాస్క్ స్థితిని వాడండి. చిన్న పనులకు బోర్డ్ లేదా ప్రోగ్రెస్ ఫైల్ అవసరం లేదు. భాగస్వామ్య పని కోసం, టాస్క్-నిర్దిష్ట `docs/agent-runs/<slug>/`లో సంక్షిప్తమైన `feature-list.json`, `progress.md`లను ఉంచండి; ఉపయోగపడే చోట ఇప్పటికే ఉన్న టెంప్లేట్‌లను వాడండి.

అభ్యర్థించిన ఫలితం, ప్రస్తుత బ్రాంచ్/వర్క్‌ట్రీ, ఫైల్ యాజమాన్యం, పూర్తైన మార్పులు, ఫలితాలతో సహా తనిఖీలు, మీ యాజమాన్యంలోని ప్రాసెస్‌లు/సెషన్‌లు, ఇంకా పరిష్కారం కాని తదుపరి దశను నమోదు చేయండి. క్రెడెన్షియల్‌లను లేదా ఇష్టారీతిన సోర్స్ డంప్‌లను నిల్వ చేయవద్దు. ఒక ఫీచర్ అంగీకార ప్రమాణాలు ధృవీకరించబడినప్పుడు మాత్రమే దాన్ని పూర్తైనదిగా గుర్తించండి.

పనిని తిరిగి కొనసాగించేటప్పుడు, సవరించే ముందు Git స్థితిని, తాజా ప్రోగ్రెస్‌ను, సంబంధిత సోర్స్‌ను పరిశీలించండి. మీ యాజమాన్యంలోని అనుకూల వనరులను తిరిగి వాడండి; తదుపరి తనిఖీకి అవసరమైనప్పుడు మాత్రమే డెవ్ సర్వర్‌ను ప్రారంభించండి. మారని పూర్తి పాస్‌ను మళ్లీ నడపకుండా, [verification.md](https://github.com/bitsocialnet/bitsocial-web/blob/master/docs/agent-playbooks/verification.md) ఆధారంగా ప్రభావాన్ని బట్టి తనిఖీలను ఎంచుకోండి.

సంబంధిత అప్పగించిన పనిని పరిమిత పరిధిలో, ఒకదానితో ఒకటి అతివ్యాప్తి చెందకుండా ఉంచండి. భారీ తనిఖీలు, బ్రౌజర్ సెషన్‌ల బాధ్యత ఒకే ఏజెంట్‌ది. పూర్తైన స్లైస్, బ్లాకర్ లేదా హ్యాండ్‌ఆఫ్ తదుపరి కంట్రిబ్యూటర్ తెలుసుకోవాల్సిన విషయాన్ని మార్చినప్పుడు మన్నికైన స్థితిని నవీకరించండి; ప్రతి ఆదేశాన్నీ యాంత్రికంగా లాగ్ చేయవద్దు.
