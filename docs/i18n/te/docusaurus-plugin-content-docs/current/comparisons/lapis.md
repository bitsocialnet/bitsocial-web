# Bitsocial మరియు Lapis Net

[Lapis Net](https://net.lapisproject.dev/) అనేది JVM కోసం Kotlinలో రాసిన పీర్-టు-పీర్ సోషల్
నెట్‌వర్క్ ప్రోటోకాల్. ఇది స్వతంత్రంగా Bitsocialకు దగ్గరగా ఉండే పునాదులకు చేరుకుంది: కీ జత
గుర్తింపులు, IPFS తరహా కంటెంట్ నిల్వ, libp2p gossipsub. స్పామ్ ఫిల్టరింగ్, క్యూరేషన్‌ను ఎక్కడ
ఉంచుతాయన్న విషయంలో ఈ రెండూ భిన్నంగా ఉంటాయి. Lapis ప్రతి పాఠకుడికీ వ్యక్తిగత ట్రస్ట్ గ్రాఫ్‌ను
ఇస్తుంది, Bitcoin, Lightning చెల్లింపులు విజిబిలిటీని పెంచేందుకు అనుమతిస్తుంది; ఏమి ప్రచురించవచ్చో
ప్రతి కమ్యూనిటీ నిర్ణయించుకునేలా Bitsocial అనుమతిస్తుంది.

Lapis పనిచేసే ఒక ప్రోటోటైప్. దాని [రిపోజిటరీ](https://github.com/lapisproject-dev/Lapis-Net)
ప్రకారం, 2026 అక్టోబర్ నాటికి దానికి ఇంకా పబ్లిక్ నెట్‌వర్క్ లేదు, రెండు నోడ్‌లను కనెక్ట్ చేయడం
మాన్యువల్‌గా చేయాల్సిన పని.

## Lapis ఎలా పనిచేస్తుంది

- **గుర్తింపులు.** ప్రతి గుర్తింపు Bitcoin కీలతో అనుకూలమైన ఒక secp256k1 కీ జత; libp2p పీర్ ID కోసం
  దానికి ఒక Ed25519 కీ బంధించబడి ఉంటుంది.
- **నిల్వ, వ్యాప్తి.** కంటెంట్ libp2p (DHT, Bitswap)పై ఉన్న IPFS ఇంప్లిమెంటేషన్ అయిన Nabuతో నిల్వ
  అవుతుంది, libp2p gossipsubతో వ్యాపిస్తుంది.
- **స్కోరింగ్.** క్యూరేషన్ విషయంలో తటస్థంగా ఉండే కోర్ పైన నాలుగు ఐచ్ఛిక స్కోర్‌లు ఉంటాయి:
  - Veritas, ప్రతి పాఠకుడి సొంత ట్రస్ట్ గ్రాఫ్ నుండి లెక్కించే వెబ్ ఆఫ్ ట్రస్ట్
  - Virtus, కాలక్రమేణా క్షీణించే ఆన్-చెయిన్ లేదా Lightning చెల్లింపు రుజువుల ఆధారంగా వచ్చే
    విజిబిలిటీ
  - Karma, Veritas బరువుతో కూడిన ఉచిత లైక్‌లు
  - Madli, నోడ్‌లు ఒకదాని ప్రవర్తన గురించి మరొకటి ఉంచుకునే రెప్యుటేషన్ స్కోర్
- **మెసేజింగ్.** ఎండ్-టు-ఎండ్ ఎన్‌క్రిప్టెడ్ డైరెక్ట్ మెసేజ్‌లు, ఒకరితో ఒకరు వాయిస్ కాల్‌లు, ఈమెయిల్
  లాంటి అసింక్రనస్ సందేశ వ్యవస్థ ఈ ప్రాజెక్ట్‌లో భాగం.
- **క్లయింట్‌లు.** ప్రతి వినియోగదారు ఒక JVM నోడ్‌ను నడుపుతారు. రిఫరెన్స్ క్లయింట్ ఆ స్థానిక నోడ్
  అందించే వెబ్ ఇంటర్‌ఫేస్.

## అవి ఎక్కడ భిన్నంగా ఉంటాయి

### స్పామ్‌ను ఎవరు ఫిల్టర్ చేస్తారు

Lapis పాఠకుడి వద్ద ఫిల్టర్ చేస్తుంది. కంటెంట్ వ్యాపిస్తుంది, ఆ తర్వాత ప్రతి పాఠకుడి ట్రస్ట్ గ్రాఫ్,
వారు వాడే యాప్ చెల్లింపు నియమాలు ఏది పైకి వస్తుందో నిర్ణయిస్తాయి. Bitsocial కమ్యూనిటీ వద్ద ఫిల్టర్
చేస్తుంది: కమ్యూనిటీ నోడ్ ఒక పోస్ట్‌ను ఆమోదించే ముందు అది కమ్యూనిటీ ఛాలెంజ్‌ను దాటాలి, కాబట్టి
తిరస్కరించిన స్పామ్ ఎప్పటికీ కమ్యూనిటీలో భాగం కాదు.
[కస్టమ్ యాంటీ-స్పామ్ సవాళ్లు](/custom-challenges/) చూడండి.

### అధికారం ఎవరి చేతిలో ఉంది

Lapisలో ప్రతి పాఠకుడూ ఎవరిని నమ్మాలో నిర్ణయిస్తారు, ప్రతి యాప్ ఆపరేటర్ అక్కడ చెల్లింపు విజిబిలిటీ
ఎలా పనిచేయాలో నిర్ణయిస్తారు. Bitsocialలో కమ్యూనిటీ యజమాని ఆ ఒక్క కమ్యూనిటీకి నియమాలు పెడతారు, ఏమి
చూపించాలో యాప్‌లు ఎంచుకుంటాయి. రెండింటిలోనూ ప్రోటోకాల్ స్థాయి అడ్మినిస్ట్రేటర్ లేరు.

### ఆర్థిక వ్యవస్థ

Lapis తన విజిబిలిటీ స్కోర్‌లోనే Bitcoin, Lightning చెల్లింపు రుజువులను చేర్చుతుంది. Bitsocial
ప్రోటోకాల్‌లో చెల్లింపు లేయర్ లేదు; ఒక కమ్యూనిటీ తన ఛాలెంజ్ ద్వారా చెల్లింపును లేదా టోకెన్‌ను
కోరవచ్చు.

### బ్రౌజర్

Bitsocial యాప్‌లు సాధారణ బ్రౌజర్ ట్యాబ్‌లోనే పీర్-టు-పీర్ నోడ్‌ను నడపగలవు.
[బ్రౌజర్ పీర్-టు-పీర్](/browser-p2p/) చూడండి. Lapis బ్రౌజర్ ఇంటర్‌ఫేస్ వినియోగదారు JVM నోడ్ అందించే
స్థానిక పేజీ.

### పరిధి

Lapis డైరెక్ట్ మెసేజ్‌లు, వాయిస్ కాల్‌లు, మెయిల్‌ను కలిపి అందిస్తుంది. Bitsocial పబ్లిక్
కమ్యూనిటీలపై దృష్టి పెడుతుంది, దానికి ఇంకా నేటివ్ డైరెక్ట్ మెసేజ్‌లు లేవు.

## అవి కలిసి పనిచేయగలవా?

Bitsocial ఛాలెంజ్‌లు ఏకపక్ష కోడ్, కాబట్టి Lapis తరహా ట్రస్ట్ స్కోర్ కూడా ఒక ఛాలెంజ్ కావచ్చు.
అంతర్నిర్మిత `whitelist` ఛాలెంజ్ ఇప్పటికే URLల నుండి అనుమతించిన చిరునామాల జాబితాలను చదవగలదు. ఒక
Veritas గ్రాఫ్ నమ్మే Bitsocial చిరునామాలను ప్రచురించే సేవ, ఆ రచయితలు ఒక కమ్యూనిటీలో CAPTCHAను
దాటవేయడానికి అనుమతించగలదు. దీనికి Lapis గుర్తింపును Bitsocial చిరునామాతో అనుసంధానించే మార్గం అవసరం,
అలాంటిది ఈరోజు ఏదీ లేదు.
