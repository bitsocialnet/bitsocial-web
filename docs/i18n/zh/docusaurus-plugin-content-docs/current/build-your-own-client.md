# 构建你自己的 Bitsocial 客户端

Bitsocial 不靠为每一种用途提供一个官方应用来取胜。它取胜的方式是：让众多客户端共享同一套协议，同时在界面、文化、发现、默认设置和商业模式上互相竞争。

5chan 和 Seedit 是早期的验证，而不是天花板。任何开发者都应该能够发布新的图版、论坛、个人资料客户端、移动优先的社交应用、小众社区工具，或者一个底层使用 Bitsocial 的中心化客户端，而无需向某个平台所有者申请许可。

## 开发者可以改变什么

一个 Bitsocial 客户端无需分叉整个网络，就能在产品决策上展开竞争：

- 界面与视觉语言
- 上手流程
- 社区默认设置
- 审核界面
- 发现模型
- 媒体体验
- 移动端、桌面端或低带宽环境的限制
- 变现与商业模式

共同的一层是协议。产品那一层则开放给竞争。

## 最快的入门方式

从已经存在的应用开始：

- 试用 [5chan](https://5chan.app)，体验匿名图版社区。
- 试用 [Seedit](https://seedit.app)，体验 Reddit 风格的讨论。
- 阅读 [Bitsocial React hooks](https://hooks.bitsocial.net/docs/quickstart/) 文档，了解客户端集成方式。
- 阅读 [Bitsocial CLI](/developer-tools/cli/) 文档，了解节点与社区运维。

如果你想快速推进，可以先给现有应用做贡献。如果你想要的界面、文化或社区模式无法在其中实现，再另外构建一个客户端。

## 把第一版做得足够窄

最好的第一版不是一个通用社交应用，而是一个受众明确、存在理由充分的客户端。

不错的起点包括：

- 面向某一特定文化的、更清爽的图版客户端
- 移动优先的论坛客户端
- 默认设置严格的单社区应用
- 面向创作者社区的客户端
- 只读的发现型客户端
- 审核或运维控制台
- 针对某种语言、地区或设备类别优化的客户端

小客户端之所以有价值，是因为 Bitsocial 让它们能够长入同一个网络，而不是把用户困在一个私有数据库里。

## 实现路径

实际可行的路径有三条：

1. 当你的想法接近 5chan 或 Seedit 时，分叉一个现有客户端。
2. 用 [Bitsocial React hooks](https://hooks.bitsocial.net/) 构建一个新的 React 客户端。
3. 在节点 API 和公共 RPC 基础设施之上构建你自己的集成。

公共 RPC 应该会让第三条路径实用得多。用户可以先通过由他人运营、但不代管密钥的 RPC 服务起步，之后再迁移到自建节点或另一家提供方。

## 设计原则

为你的社区构建那个本该存在的客户端，然后让互相兼容的客户端在公开环境中竞争。
