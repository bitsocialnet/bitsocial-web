# Bitsocial Chain

Bitsocial Chain 是为 Bitsocial 应用提议的 Ethereum L2 应用链（appchain）经济层。目前该链自己的站点是
[chain.bitsocial.net](https://chain.bitsocial.net)。

点对点社交层让社区、身份和内容得以脱离中心化平台的数据库。Bitsocial Chain 要补上的，是共享的命名、变现
与支付原语，让这些应用更难在资金上被拖垮。

## 它要支撑什么

- 去中心化的 Bitsocial 域名，例如 `.bso`
- 奖励与打赏
- 持久的变现通道
- 跨应用的共享流动性
- 银行或平台更难掐断的金融结构
- 不依赖任何一家公司拥有整个技术栈的网络效应

目标不是把代币机制摆在最前面，而是让有用的社交应用更持久、更容易获得资金，也更少依赖中心化的支付或命名
服务商。

## 当前的概念验证

Bitsocial Chain 的第一个概念验证聚焦于原生 `.bso` 名称。它要证明的是：名称注册表可以从 Ethereum L1 的历史
中推导出来，而不必把社交内容放到链上：

- 用户通过普通的 Ethereum L1 交易提交注册、更新、转移和撤销意图
- 任何人都可以运行推导节点，重建出同一份 `.bso` 注册表状态
- 解析器把 `.bso` 名称映射到客户端已经在点对点协议上使用的 Bitsocial 公钥
- 帖子、投票、审核、信息流和社区内容都留在链下，保持点对点

这个概念验证并不是生产级的 Stage 2 上线。它目前还没有证明系统、挑战博弈、经过审计的代码、正式部署、最终
定价或最终治理方案。它的长期定位是默认透明、并在设计上兼容隐私：核心链是公开的，而未来的打赏、支付、奖励
与流动性功能应当避免在社交身份与钱包历史之间强行建立永久关联。

## 为什么这很重要

让社区和身份去中心化是必要的，但仅靠这一点还不足以让所有社交媒体都去中心化。

如果社交应用仍然依赖少数几条中心化的经济通道，它们就依然容易被施压、被切断服务，或者在资金上被拖垮。
Bitsocial Chain 就是针对这第二层依赖提出的答案。

## 与应用的关系

Bitsocial Chain 应当位于 Bitsocial 应用之下，而不是取代它们。

面向公众的结果应当是：

- 社区保持点对点
- 应用保持各自的差异化
- 用户获得实用的命名和变现功能
- 创作者和社区可以跨客户端收到支持
- 价值可以在整个生态系统中流动，而不必重新造出一个中心化的平台所有者

## 为什么它排在 Twitter/X 替代品之后

当前的总体规划把 Bitsocial Chain 放在 Twitter/X 替代品之后，因为那个应用并不需要这条链。个人资料通过非托管 RPC 以个人资料节点的形式运行，而 `.bso` 名称可以先在 Ethereum 主网上的临时注册表（[BSIP-13](https://bsips.bitsocial.net/bsip-13)）中启用，之后再迁移到链上。

Bitsocial Chain 不应为了更早上线而牺牲去中心化。它不应在 Ethereum 本身之外增加任何信任假设：没有升级密钥，没有安全委员会，也没有能够审查或停止它的运营者。实现这一点的首选设计是原生 rollup，它依赖一次尚未排期的 Ethereum 升级。在链能够达到这一标准之前，Twitter/X 替代品会先培养这条链将要服务的用户群。

## 设计原则

由于 Bitsocial Chain 仍然是提议中的基础设施，而不是已经上线的产品，这份计划应当保持克制：

- 应用和社区优先。网络层应当让真实的社交产品变得更强。
- 实用功能优先。名称、奖励、打赏和支付比抽象的金融架构更容易讲清楚。
- 真实贡献高于炒作。经济原语应当奖励参与、建设和对社区的支持。
- 允许策展。应用可以调整排名、默认设置和发现机制，向能长久存续的社区倾斜。
- 具体机制仍未定案。本页解释的是 Bitsocial Chain 的角色，而不是对最终经济模型的锁定承诺。
