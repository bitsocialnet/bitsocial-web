# Bitsocial 与 Mirage

[Mirage](https://mirage.foundation/) 是一个 Reddit 式的讨论网络，有社区、楼中楼式的帖子和投票。它不使用公司数据库，而是运行在自己的区块链上，即一条采用 CometBFT 共识的 Cosmos SDK 链。Bitsocial 最接近的产品是 [Seedit](/apps/seedit/)，一款运行在 Bitsocial 网络上的 Reddit 式应用，因此这里的对比主要关于两者如何托管、拥有和审核社区。

## Mirage 的工作原理

- **节点。** 一个 Mirage 节点就是一个 Docker 容器，里面包含验证者、PostgreSQL 数据库、索引器、HTTP API 和网页前端。每个节点同时也是验证者。据[部署指南](https://github.com/MirageFoundation/mirage-node/blob/dev/docs/guides/deploy.md)，运行节点需要一台 amd64 架构的 Ubuntu 服务器，运营者账户中还需持有 10,000,000 个 MIRAGE 代币。
- **发帖。** 浏览器用用户的 secp256k1 密钥为每个操作签名，免费用户还要计算一个小型工作量证明。节点把操作封装成链上交易并支付费用。
- **读取。** 每个节点的索引器把链上数据复制到自己的数据库，并通过 HTTP API 提供信息流。节点只保留约一周的区块，因此长期的帖子历史存放在各节点的数据库中，新节点启动时不包含其同步点之前的历史。
- **账号。** 账号是由 12 个单词的助记词派生出的密钥，同一组助记词在任何节点上都能使用。用户名记录在链上，在全网唯一。
- **社区。** 每个有效名称本身就是一个社区，而且没有人拥有它。由最多十名用户组成的付费策展团队各自维护一个社区的审核视图；读者可以选择某个团队的视图、节点的默认视图或未经审查的视图。参见 [Mirage FAQ](https://mirage.talk/faq)。
- **代币。** MIRAGE 代币用于支付订阅、奖励作者和节点，并赋予验证者治理权重。订阅者无需计算工作量证明，并享有更高的限额。

## 两者的区别

### 谁拥有社区

在 Seedit 中，社区的创建者持有其密钥对，自己运行或委托他人运行其节点，并负责审核。在 Mirage 中，没有人拥有社区：相互竞争的策展团队为同一个名称提供各自的审核视图，默认视图则是付费订阅者选择人数最多的那个团队。

### 垃圾信息控制

Mirage 对全网采用同一条规则：免费用户以工作量证明付出代价，其难度随流入量调整，订阅者则可跳过。在 Bitsocial 中，每个社区自行选择挑战，从验证码到白名单再到付费。参见[自定义反垃圾邮件挑战](/custom-challenges/)。

### 基础设施

Mirage 需要一条区块链。验证者对每个操作达成共识，每个节点都要运行完整的服务器栈，并持有大量代币质押。Bitsocial 没有链：社区节点可以通过桌面应用或 `bitsocial-cli` 在消费级硬件上运行，读者也能帮忙分享内容。

### 全网控制权

Mirage 设有按验证者质押加权的链上治理。治理可以修改难度、价格和代币发行量，增发或销毁代币，并任命管理员，而参考索引器会把这些管理员的删除操作应用到任何帖子上。链上代码还允许治理[删除账号](https://github.com/MirageFoundation/mirage-node/blob/142a2e4e2542b6a3c9cc6d71591c282e5e5a9503/blockchain/x/core/module/module.go#L2572-L2573)和[从任意地址转出代币](https://github.com/MirageFoundation/mirage-node/blob/142a2e4e2542b6a3c9cc6d71591c282e5e5a9503/blockchain/x/core/module/module.go#L2656)。2026 年 10 月，该链的区块由四个验证者生产，而这四个验证者都由项目自己的运维手册管理。

Bitsocial 没有协议层面的管理员。社区所有者审核自己的社区，应用自行决定显示什么。参见[本地审核，而非全局封禁](/local-moderation/)。

### 浏览器

Mirage 的网页客户端是某个节点的 HTTP 客户端：浏览器为操作签名，但不加入点对点网络。Bitsocial 应用可以在浏览器标签页内运行点对点节点。参见[浏览器点对点网络](/browser-p2p/)。

## 对比

| 问题           | Mirage                                                                     | Bitsocial                                              |
| -------------- | -------------------------------------------------------------------------- | ------------------------------------------------------ |
| 类别           | 运行在自有区块链上的论坛（Cosmos SDK）                                     | 点对点社区网络                                         |
| 身份           | 由 12 个单词助记词派生的 secp256k1 密钥，配有链上用户名                    | 用户和社区各自使用 Ed25519 密钥对                      |
| 帖子存放在哪里 | 链上交易，然后是各节点的 PostgreSQL 数据库                                 | 社区所有者的节点，以及读取并为其做种的对等点           |
| 谁让它保持在线 | 验证者节点，每个持有 10,000,000 MIRAGE                                     | 社区所有者的节点，加上协助做种的节点                   |
| 社区           | 无主名称，由相互竞争的付费策展团队维护                                     | 归一个密钥对所有；由所有者的节点接受或拒绝帖子         |
| 垃圾信息控制   | 全网统一的工作量证明；订阅者可跳过                                         | 帖子被接受之前须通过所在社区的挑战                     |
| 审核           | 策展团队视图、个人过滤、治理任命的管理员                                   | 社区所有者审核自己的社区；应用自行决定显示什么         |
| 经济机制       | MIRAGE 代币用于订阅、奖励和验证者质押                                      | 协议中没有；挑战可以要求付费或代币                     |
| 浏览器         | 节点的 HTTP 客户端                                                         | 普通浏览器标签页中的点对点节点                         |
| 主要取舍       | 单一共享的有序状态，注册也方便，但验证者集合很小，且存在全网范围的治理权力 | 不需要链或质押，但没有全局顺序，旧内容也不保证永久留存 |
