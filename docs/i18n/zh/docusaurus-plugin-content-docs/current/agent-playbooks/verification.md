# 验证

根据变更的行为和剩余的不确定性来选择检查。对于同一最终状态，可以复用已经成功的证据；在相关编辑或失败之后要重新运行。CI、发布或用户明确提出的要求依然适用。

| 变更                             | 合适的检查                                                                                                    |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 仅涉及文字/注释/格式             | diff、引用、相关生成器；不需要构建应用                                                                        |
| AI 工作流源文件/配置             | `yarn ai-workflow:sync`、`yarn ai-workflow:check`、`yarn ai-workflow:test`；上下文发生变化时重新生成 LLM 索引 |
| 独立的辅助工具或脚本             | 有针对性的调用/fixture，以及针对受影响代码的语法或类型/lint 检查                                              |
| 共享运行时、依赖、构建、集成变更 | 有针对性的受影响检查，加上下文列出的相关构建/类型/lint 检查                                                   |
| 仅涉及 CSS/主题/布局             | 在选定浏览器中检查受影响的路由/视口/主题；导入、资源或 CSS 处理发生变化时进行构建                             |
| React 状态/副作用/性能           | 受影响的行为以及适用的 React 指南；当诊断能解答某个具体疑虑时运行 Doctor                                      |

## 项目检查

- `yarn build:verify` 会选择受影响的工作区。范围已知时，使用 `yarn build:about`、`yarn build:chain`、`yarn build:stats-monitor` 或 `yarn docs:build:verify`。
- `yarn build` 有意运行完整的 about/docs 生产构建，包括所有文档语言。在需要覆盖整个发布范围的验证，或改动确实需要这一范围时使用它。
- `yarn lint`、`yarn typecheck` 和 `yarn format:check` 覆盖仓库现有的关卡；对于范围很窄的脚本编辑，先使用针对它的语法/fixture/格式检查。
- 清单/锁文件变更需要运行 `corepack yarn install`、`yarn deps:check-pinned` 和 `yarn deps:check-hardened`。`yarn knip` 对依赖/导入仅作参考。
- 文档翻译检查见 [translations.md](translations.md)；做有针对性的文档改动时，不要运行批量翻译写入器。

## 浏览器证据与归属

小而独立的浏览器改动用 Chrome 即可。涉及共享 CSS/布局/响应式、对浏览器敏感的 API、大范围交互、发布，或明确的跨浏览器验收标准时，再加上 Firefox 和 WebKit。要覆盖受影响的移动端布局/触控行为。仅仅调整视口尺寸并不等于触控模拟。根据源码选择实际存在的路由和内容，不要假定示例一定可用。

通过 `./scripts/pw-session.sh` 使用 `playwright-cli`。全机器同一时间只有一个活动浏览器；选定的引擎依次运行，每个确切归属的会话即使在失败之后也会被关闭。可以复用调用方拥有且已获授权的会话，但不要关闭它。绝不要使用全局浏览器清理，也不要停止归属不明的服务器。纯文档工作不需要浏览器或服务器。

做性能工作时，要在相同的视口、内容、网络/CPU 设置、构建模式和测量开销下比较同一流程。区分观察到的现象与推测的原因。当这些测量能回答实际请求时，使用 profile 技能。

## 最终证据

由一个代理负责重量级验证。检查当前活动的工作负载，并把安装、构建/完整测试套件、Doctor、Android/Electron 工作以及浏览器性能分析串行进行。报告运行过的命令/结果以及具体的局限；缺失的数据或被跳过的引擎不算通过。工具的 fixture 验证的是格式和机制，而不是端到端的应用发现或模型决策质量。

## 自动 React 检查

`yarn agent:verify` 会先运行选定的构建，然后运行 `yarn doctor:check` 和 `yarn perf:check`。`perf:check` 包含采集器兼容性和故意回归的自检，因此无论是 CI 还是代理验证路径，都不需要单独再跑一遍 `perf:test`。用 `yarn perf:install` 一次性安装固定版本的浏览器工具（在 Linux CI 中加上 `--with-deps`）。在完整的相关检查跑过一遍之后，使用目标/场景过滤器做有针对性的重跑。场景预算在 `scripts/react-perf/config.mjs` 中明确设定；在考虑有理有据地调整基线之前，先保留证据并修复回归。普通生产构建不包含 Bippy；单独的 `build:profile:*` 命令提供官方的 React 性能分析插桩。

about 站点的 `apps-search` 场景按已提交的、逐字符的 URL/输入值控制节奏。它的通过结果只覆盖这一已提交的查询序列，并不代表快速输入时的响应能力。评估字符丢失或输入响应能力时，请使用单独的快速输入复现。
