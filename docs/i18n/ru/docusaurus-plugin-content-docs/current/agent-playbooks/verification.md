# Проверка

Выбирайте проверки исходя из изменённого поведения и оставшейся неопределённости. Если итоговое состояние не изменилось, переиспользуйте уже полученные успешные результаты; после значимых правок или сбоев запускайте проверки заново. Явные требования CI, релиза или пользователя по-прежнему действуют.

| Изменение                                                      | Подходящие проверки                                                                                                              |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Только текст, комментарии или форматирование                   | Дифф, ссылки, соответствующие генераторы; без сборки приложения                                                                  |
| Исходники или конфигурация рабочего процесса ИИ-агентов        | `yarn ai-workflow:sync`, `yarn ai-workflow:check`, `yarn ai-workflow:test`; перегенерируйте LLM-индексы, если изменился контекст |
| Изолированный хелпер или скрипт                                | Точечный запуск или фикстуры и проверки синтаксиса либо типов и линта для затронутого кода                                       |
| Изменение общего рантайма, зависимостей, сборки или интеграции | Точечные проверки затронутого кода плюс соответствующие проверки сборки, типов и линта из списка ниже                            |
| Только CSS, тема или вёрстка                                   | Затронутые маршруты, вьюпорты и темы в выбранных браузерах; сборка, если изменились импорты, ассеты или обработка CSS            |
| Состояние, эффекты или производительность React                | Затронутое поведение и применимые рекомендации по React; Doctor, если его диагностика помогает разрешить конкретное сомнение     |

## Проверки проекта

- `yarn build:verify` сам выбирает затронутый workspace. Если область известна, используйте `yarn build:about`, `yarn build:chain`, `yarn build:stats-monitor` или `yarn docs:build:verify`.
- `yarn build` намеренно запускает полную продакшен-сборку about и документации, включая все локали документации. Используйте его для проверки всего релиза или для изменений, которые действительно требуют такого охвата.
- `yarn lint`, `yarn typecheck` и `yarn format:check` покрывают существующие обязательные проверки репозитория; при узкой правке скрипта сначала запускайте его собственные точечные проверки синтаксиса, фикстур и форматирования.
- Изменения манифеста или lock-файла требуют `corepack yarn install`, `yarn deps:check-pinned` и `yarn deps:check-hardened`. `yarn knip` для зависимостей и импортов носит рекомендательный характер.
- Проверки переводов документации описаны в [translations.md](translations.md); не запускайте скрипт массовой записи переводов ради точечного изменения документации.

## Проверка в браузере и владение сессиями

Для небольших изолированных изменений в браузере используйте Chrome. Добавляйте Firefox и WebKit для общих CSS, вёрстки и адаптивности, браузерно-зависимых API, широких сценариев взаимодействия, релизов или явных кросс-браузерных критериев. Проверяйте и затронутые мобильные раскладки и поведение касаний. Изменение размера вьюпорта само по себе не эмулирует касания. Выбирайте реальные маршруты и контент по исходникам, а не рассчитывайте, что примеры будут доступны.

Используйте `playwright-cli` через `./scripts/pw-session.sh`. На всей машине одновременно активен только один браузер; выбранные движки запускаются последовательно, и каждая принадлежащая вам сессия закрывается по точному имени даже после сбоя. Авторизованную сессию, которой владеет вызывающая сторона, переиспользуйте, не закрывая её. Никогда не используйте глобальную очистку браузеров и не останавливайте сервер, владелец которого неясен. Для работы только с документацией браузер и сервер не нужны.

При работе над производительностью сравнивайте один и тот же сценарий при одинаковых вьюпорте, контенте, настройках сети и CPU, режиме сборки и накладных расходах на измерение. Отделяйте наблюдения от предполагаемых причин. Используйте навык профилирования, когда эти измерения отвечают на исходный запрос.

## Итоговые результаты

Тяжёлую проверку выполняет один агент. Проверяйте, какие нагрузки уже запущены, и выполняйте последовательно установки, сборки и полные наборы тестов, Doctor, работу с Android и Electron и профилирование в браузере. Сообщайте команды с их результатами и конкретные ограничения; отсутствующие данные или пропущенный движок — это не успешный результат. Фикстуры инструментов проверяют форматы и механику, а не сквозное обнаружение в самих приложениях и не качество решений модели.

## Автоматические проверки React

`yarn agent:verify` запускает выбранные сборки, а затем `yarn doctor:check` и `yarn perf:check`. `perf:check` включает самопроверку совместимости сборщика метрик и намеренно внесённой регрессии, поэтому ни CI, ни путь проверки агента не требуют отдельного прогона `perf:test`. Один раз установите закреплённые браузерные инструменты командой `yarn perf:install` (`--with-deps` в Linux CI). Для точечных перезапусков после полного соответствующего прогона используйте фильтры по целям и сценариям. Бюджеты сценариев явно заданы в `scripts/react-perf/config.mjs`; сохраняйте свидетельства и исправляйте регрессию, прежде чем рассматривать обоснованное изменение базовой линии. Обычные продакшен-сборки не включают Bippy; официальную инструментацию профилирования React подключают отдельные команды `build:profile:*`.

Сценарий about `apps-search` задаёт темп по зафиксированным значениям URL и поля ввода для каждого символа. Его успешный результат покрывает именно эту последовательность зафиксированных запросов, а не отзывчивость при быстром наборе. Чтобы оценить потерю символов или отзывчивость ввода, используйте отдельное воспроизведение с быстрым вводом.
