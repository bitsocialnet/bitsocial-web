# Длительная работа агентов

Используйте долговременное состояние задачи, когда работу нужно будет возобновить или передать другому исполнителю, либо когда один прогон настолько длинный, что при сжатии контекста можно потерять из виду оставшуюся работу. Небольшим задачам не нужны ни доска, ни файл прогресса. Для общей работы ведите краткие `feature-list.json` и `progress.md` в отдельном для задачи каталоге `docs/agent-runs/<slug>/`, при необходимости опираясь на существующие шаблоны.

Записывайте запрошенный результат, текущую ветку или worktree, владение файлами, завершённые изменения, проверки с их результатами, принадлежащие вам процессы и сессии и следующий нерешённый шаг. Не храните учётные данные и произвольные дампы исходников. Отмечайте функцию как завершённую, только когда её критерии приёмки проверены.

При возобновлении работы изучите состояние Git, последнюю запись о прогрессе и соответствующие исходники, прежде чем что-либо править. Переиспользуйте совместимые ресурсы, которыми вы владеете; запускайте дев-сервер, только если он нужен для следующей проверки. Выбирайте проверки по степени влияния, руководствуясь [verification.md](https://github.com/bitsocialnet/bitsocial-web/blob/master/docs/agent-playbooks/verification.md), а не повторяйте полный прогон, если ничего не изменилось.

Держите связанную делегированную работу в чётких рамках и без пересечений. Тяжёлые проверки и браузерные сессии принадлежат одному агенту. Обновляйте долговременное состояние, когда завершённый фрагмент, блокер или передача работы меняют то, что нужно знать следующему участнику; не записывайте механически каждую команду.
