# लंबे समय तक चलने वाला एजेंट काम

टिकाऊ टास्क स्थिति तब इस्तेमाल करें जब काम को बाद में फिर से शुरू करना हो या किसी और को सौंपना हो, या जब एक ही रन इतना लंबा हो कि कॉन्टेक्स्ट कम्पैक्शन में बचे हुए काम का हिसाब खो सकता हो। छोटे कामों के लिए किसी बोर्ड या प्रगति फ़ाइल की ज़रूरत नहीं होती। साझा काम के लिए किसी टास्क-विशिष्ट `docs/agent-runs/<slug>/` में एक संक्षिप्त `feature-list.json` और `progress.md` रखें, और जहाँ मददगार हो वहाँ मौजूदा टेम्पलेट इस्तेमाल करें।

अनुरोधित परिणाम, मौजूदा ब्रांच/वर्कट्री, फ़ाइलों का स्वामित्व, पूरे हो चुके बदलाव, परिणामों सहित जाँचें, अपने स्वामित्व वाली प्रक्रियाएँ/सेशन, और अगला अनसुलझा कदम दर्ज करें। क्रेडेंशियल या मनमाने सोर्स डंप न रखें। किसी फ़ीचर को पूरा तभी चिह्नित करें जब उसके स्वीकृति मानदंड सत्यापित हो चुके हों।

काम फिर से शुरू करते समय, संपादन से पहले Git की स्थिति, नवीनतम प्रगति और प्रासंगिक सोर्स जाँचें। अपने स्वामित्व वाले संगत संसाधन दोबारा इस्तेमाल करें; डेव सर्वर तभी शुरू करें जब अगली जाँच को उसकी ज़रूरत हो। बिना बदले पूरे पास को दोहराने के बजाय [verification.md](https://github.com/bitsocialnet/bitsocial-web/blob/master/docs/agent-playbooks/verification.md) की मदद से असर के आधार पर जाँचें चुनें।

संबंधित सौंपे गए काम को सीमित दायरे में और एक-दूसरे से न टकराने वाला रखें। भारी जाँचों और ब्राउज़र सेशनों का स्वामी एक ही एजेंट होता है। टिकाऊ स्थिति तब अपडेट करें जब कोई पूरा हुआ स्लाइस, ब्लॉकर या हैंडऑफ़ यह बदल दे कि अगले योगदानकर्ता को क्या जानना चाहिए; हर कमांड को यंत्रवत लॉग न करें।
