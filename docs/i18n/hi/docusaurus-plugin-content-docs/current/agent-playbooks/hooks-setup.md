# एजेंट हुक

कमिट किए गए लाइफ़साइकल हुक केवल इतना करते हैं: सफलतापूर्वक संपादित JavaScript/TypeScript फ़ाइलों को इंस्टॉल किए गए oxfmt से फ़ॉर्मैट करना। साझा लॉजिक `scripts/agent-hooks/format.mjs` में है; हर नेटिव रैपर काम उसी को सौंपता है।

| ऐप | नेटिव कॉन्फ़िगरेशन | इवेंट |
|---|---|---|
| Codex | `.codex/hooks.json` | `PostToolUse`, `apply_patch` |
| Claude Code | `.claude/settings.json` | `PostToolUse`, `Edit|Write|MultiEdit` |
| Cursor | `.cursor/hooks.json` | `afterFileEdit` |

Claude किसी अलग `.claude/hooks.json` को नहीं पढ़ता। प्रोजेक्ट ट्रस्ट और हुक सक्षम हैं या नहीं, यह अब भी हर ऐप खुद नियंत्रित करता है; ट्रस्ट को बायपास करने के बजाय उसकी मौजूदा सेटिंग्स जाँचें। `.codex/config.toml` रिपॉज़िटरी कॉन्फ़िगरेशन है, हुक कमांडों की रजिस्ट्री नहीं।

फ़ॉर्मैटर इवेंट/पेलोड, संपादन की सफलता, फ़ाइल एक्सटेंशन, और सिमलिंक सहित फ़ाइल के रिपॉज़िटरी के भीतर होने की पुष्टि करता है। डिपेंडेंसी न होने पर या अप्रासंगिक इनपुट मिलने पर कुछ नहीं होता। कमांड आर्ग्युमेंट ऐरे इस्तेमाल करते हैं और Corepack की नेटवर्क पहुँच बंद रहती है; हुक डिपेंडेंसी इंस्टॉल नहीं करते, बिल्ड/रिव्यू नहीं चलाते, और Git में कोई बदलाव नहीं करते।

जाँचें [verification.md](https://github.com/bitsocialnet/bitsocial-web/blob/master/docs/agent-playbooks/verification.md) के अनुसार स्पष्ट रूप से चलाएँ। वर्कफ़्लो बदलने के बाद `yarn ai-workflow:sync`, `yarn ai-workflow:check` और `yarn ai-workflow:test` चलाएँ। फ़िक्स्चर डिस्पोज़ेबल फ़ाइलें और नकली फ़ॉर्मैटर इनवोकेशन इस्तेमाल करते हैं; वे यह साबित नहीं करते कि हर ऐप ने अपना कॉन्फ़िगरेशन लोड किया। अपग्रेड के बाद ऐप को रीलोड करें और उसका कैटलॉग जाँचें।

Impeccable डिज़ाइन स्किल और उसके एक्ज़ीक्यूटेबल हेल्पर ज़रूरत पड़ने पर `.agents/skills/impeccable` के अंतर्गत उपलब्ध रहते हैं। उसका पुराना Codex हुक एक अनुपस्थित डायरेक्टरी की ओर इशारा करता था; अब डिज़ाइन वर्कफ़्लो तभी चलता है जब उसकी स्किल चुनी जाए, और कोई हमेशा-चालू डिज़ाइन हुक नहीं है। स्किल डिज़ाइन के काम के दौरान चलते-चलते प्रोजेक्ट हुक दोबारा कॉन्फ़िगर न करे।
