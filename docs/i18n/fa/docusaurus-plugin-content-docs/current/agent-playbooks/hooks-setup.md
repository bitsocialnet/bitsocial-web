# هوک‌های ایجنت

هوک‌های چرخه عمر که در مخزن کامیت شده‌اند فقط یک کار می‌کنند: فایل‌های JavaScript/TypeScript را که با موفقیت ویرایش شده‌اند، با oxfmt نصب‌شده قالب‌بندی می‌کنند. منطق مشترک در `scripts/agent-hooks/format.mjs` قرار دارد؛ هر پوشش بومی کار را به آن واگذار می‌کند.

| اپ | پیکربندی بومی | رویداد |
|---|---|---|
| Codex | `.codex/hooks.json` | `PostToolUse`, `apply_patch` |
| Claude Code | `.claude/settings.json` | `PostToolUse`, `Edit|Write|MultiEdit` |
| Cursor | `.cursor/hooks.json` | `afterFileEdit` |

Claude فایل مستقل `.claude/hooks.json` را نمی‌خواند. هر اپ همچنان خودش اعتماد به پروژه و فعال بودن هوک‌ها را کنترل می‌کند؛ به جای دور زدن اعتماد، تنظیمات فعلی آن اپ را بررسی کنید. `.codex/config.toml` پیکربندی مخزن است، نه فهرست ثبت فرمان‌های هوک.

قالب‌بند رویداد و محموله، موفقیت ویرایش، پسوند فایل و قرار داشتن فایل درون مخزن را، با در نظر گرفتن پیوندهای نمادین، اعتبارسنجی می‌کند. اگر وابستگی‌ها نصب نباشند یا ورودی بی‌ربط باشد، هیچ کاری انجام نمی‌شود. فرمان‌ها با آرایه آرگومان‌ها اجرا می‌شوند و دسترسی Corepack به شبکه غیرفعال است؛ هوک‌ها وابستگی نصب نمی‌کنند، ساخت یا بازبینی اجرا نمی‌کنند و Git را تغییر نمی‌دهند.

بررسی‌ها را صراحتاً و طبق [verification.md](https://github.com/bitsocialnet/bitsocial-web/blob/master/docs/agent-playbooks/verification.md) اجرا کنید. پس از تغییر گردش کار، `yarn ai-workflow:sync`، `yarn ai-workflow:check` و `yarn ai-workflow:test` را اجرا کنید. فیکسچرها از فایل‌های یک‌بارمصرف و فراخوانی‌های ساختگی قالب‌بند استفاده می‌کنند؛ ثابت نمی‌کنند که هر اپ پیکربندی خودش را بارگذاری کرده است. پس از ارتقا، اپ را دوباره بارگذاری کنید و کاتالوگ آن را بررسی کنید.

مهارت طراحی Impeccable و ابزارهای کمکی اجرایی آن همچنان زیر `.agents/skills/impeccable` و در صورت نیاز در دسترس‌اند. هوک قبلی Codex برای این مهارت به پوشه‌ای ناموجود اشاره می‌کرد؛ اکنون گردش کار طراحی وقتی اجرا می‌شود که مهارتش انتخاب شود و هیچ هوک طراحیِ همیشه‌فعالی وجود ندارد. این مهارت نباید به‌عنوان یک گام فرعی در کار طراحی، هوک‌های پروژه را دوباره پیکربندی کند.
