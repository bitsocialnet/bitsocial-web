# کلاینت Bitsocial خودتان را بسازید

Bitsocial با داشتن یک اپ رسمی برای هر کاربرد برنده نمی‌شود. وقتی برنده می‌شود که کلاینت‌های متعددی
بتوانند از یک پروتکل مشترک استفاده کنند و در همان حال بر سر رابط کاربری، فرهنگ، کشف محتوا،
پیش‌فرض‌ها و مدل کسب‌وکار با هم رقابت کنند.

5chan و Seedit نمونه‌های اولیه‌ی اثبات این ایده‌اند، نه سقف آن. یک سازنده باید بتواند بدون اجازه گرفتن
از مالک یک پلتفرم، یک ایمیج‌بورد تازه، یک انجمن، یک کلاینت پروفایل‌محور، یک اپ اجتماعی موبایل‌محور،
ابزاری برای یک جامعه‌ی خاص، یا حتی یک کلاینت متمرکز که زیر پوسته از Bitsocial استفاده می‌کند عرضه کند.

## سازندگان چه چیزهایی را می‌توانند تغییر دهند

یک کلاینت Bitsocial می‌تواند بدون فورک کردن کل شبکه، بر سر تصمیم‌های محصولی رقابت کند:

- رابط کاربری و زبان بصری
- مسیر آشنایی و ورود کاربر تازه
- پیش‌فرض‌های جامعه
- سطوح نظارت بر محتوا
- مدل کشف محتوا
- تجربه‌ی رسانه
- محدودیت‌های موبایل، دسکتاپ یا پهنای باند پایین
- کسب درآمد و مدل کسب‌وکار

لایه‌ی مشترک، پروتکل است. لایه‌ی محصول برای رقابت باز است.

## سریع‌ترین راه یادگیری

از اپ‌هایی شروع کنید که همین حالا وجود دارند:

- [5chan](https://5chan.app) را برای جوامع ایمیج‌بورد ناشناس امتحان کنید.
- [Seedit](https://seedit.app) را برای گفت‌وگو به سبک Reddit امتحان کنید.
- مستندات [هوک‌های React مربوط به Bitsocial](https://hooks.bitsocial.net/docs/quickstart/) را برای یکپارچه‌سازی سمت کلاینت بخوانید.
- مستندات [Bitsocial CLI](/developer-tools/cli/) را برای کار با گره‌ها و جوامع بخوانید.

اگر می‌خواهید سریع پیش بروید، اول به یکی از اپ‌های موجود کمک کنید. اگر رابط کاربری، فرهنگ یا مدل
جامعه‌ای که در ذهن دارید با آن‌ها جور در نمی‌آید، یک کلاینت جداگانه بسازید.

## یک نسخه‌ی اول محدود انتخاب کنید

بهترین نسخه‌ی اول، یک اپ اجتماعی همه‌کاره نیست. کلاینتی است با یک مخاطب مشخص و یک دلیل قوی برای
وجود داشتن.

نقطه‌های شروع خوب عبارت‌اند از:

- کلاینت ایمیج‌بورد تمیزتری برای یک فرهنگ مشخص
- کلاینت انجمنی با اولویت موبایل
- اپی برای یک جامعه‌ی واحد با پیش‌فرض‌های سخت‌گیرانه
- کلاینتی برای جوامع سازندگان محتوا
- کلاینتی فقط‌خواندنی برای کشف محتوا
- کنسولی برای نظارت یا اپراتوری
- کلاینتی بهینه‌شده برای یک زبان، منطقه یا دسته‌ای از دستگاه‌ها

کلاینت‌های کوچک ارزشمندند، چون Bitsocial به آن‌ها اجازه می‌دهد درون همان شبکه رشد کنند، به‌جای اینکه
کاربرانشان را در یک پایگاه‌داده‌ی خصوصی حبس کنند.

## مسیرهای پیاده‌سازی

سه مسیر عملی وجود دارد:

1. وقتی ایده‌تان به 5chan یا Seedit نزدیک است، یک کلاینت موجود را فورک کنید.
2. یک کلاینت React تازه با [هوک‌های React مربوط به Bitsocial](https://hooks.bitsocial.net/) بسازید.
3. یکپارچه‌سازی خودتان را روی APIهای گره و زیرساخت RPC عمومی بسازید.

RPC عمومی باید مسیر سوم را بسیار عملی‌تر کند. کاربر می‌تواند کار را با یک ارائه‌دهنده‌ی RPC
میزبانی‌شده و غیرامانی آغاز کند و بعداً به میزبانی شخصی یا یک ارائه‌دهنده‌ی رقیب کوچ کند.

## اصل طراحی

کلاینتی را بسازید که جامعه‌ی شما به آن نیاز دارد، و بعد بگذارید کلاینت‌های سازگار در فضای عمومی با
هم رقابت کنند.
