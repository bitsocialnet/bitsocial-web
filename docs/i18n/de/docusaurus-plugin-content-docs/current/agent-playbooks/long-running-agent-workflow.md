# Langlaufende Agentenarbeit

Verwenden Sie dauerhaften Aufgabenzustand, wenn Arbeit fortgesetzt oder übergeben werden muss oder wenn ein einzelner Lauf so lange dauert, dass bei der Kontextverdichtung der Überblick über die verbleibende Arbeit verloren gehen könnte. Kleine Aufgaben brauchen weder ein Board noch eine Fortschrittsdatei. Halten Sie bei gemeinsamer Arbeit eine knappe `feature-list.json` und `progress.md` in einem aufgabenspezifischen `docs/agent-runs/<slug>/` und nutzen Sie die vorhandenen Vorlagen, wo sie helfen.

Halten Sie das angefragte Ergebnis fest, den aktuellen Branch bzw. Worktree, die Zuständigkeit für Dateien, abgeschlossene Änderungen, Prüfungen samt Ergebnissen, eigene Prozesse und Sitzungen sowie den nächsten offenen Schritt. Speichern Sie keine Zugangsdaten und keine beliebigen Quellcode-Dumps. Markieren Sie ein Feature erst als abgeschlossen, wenn seine Akzeptanzkriterien verifiziert sind.

Prüfen Sie bei der Wiederaufnahme vor dem Bearbeiten den Git-Zustand, den neuesten Fortschritt und den relevanten Quellcode. Verwenden Sie kompatible eigene Ressourcen wieder; starten Sie einen Dev-Server nur, wenn die nächste Prüfung einen braucht. Wählen Sie Prüfungen nach ihrer Auswirkung anhand von [verification.md](https://github.com/bitsocialnet/bitsocial-web/blob/master/docs/agent-playbooks/verification.md) aus, statt einen unveränderten vollständigen Durchlauf zu wiederholen.

Halten Sie zusammenhängende delegierte Arbeit klar abgegrenzt und überschneidungsfrei. Ein einziger Agent ist für aufwendige Prüfungen und Browser-Sitzungen zuständig. Aktualisieren Sie den dauerhaften Zustand, wenn ein abgeschlossener Teilabschnitt, ein Blocker oder eine Übergabe ändert, was die nächste beitragende Person wissen muss; protokollieren Sie nicht mechanisch jeden Befehl.
