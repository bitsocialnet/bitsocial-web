# אימות

בחר בדיקות לפי ההתנהגות שהשתנתה ולפי אי-הוודאות שנותרה. עשה שימוש חוזר בראיות מוצלחות עבור אותו מצב סופי; הרץ שוב אחרי עריכות רלוונטיות או כשלים. דרישות מפורשות של CI, של שחרור גרסה או של המשתמש עדיין חלות.

| שינוי                                                 | בדיקות מתאימות                                                                                                      |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| פרוזה/הערות/פורמט בלבד                                | דיף, הפניות, מחוללים רלוונטיים; ללא בניית אפליקציה                                                                  |
| מקורות/תצורה של זרימת העבודה של AI                    | `yarn ai-workflow:sync`, `yarn ai-workflow:check`, `yarn ai-workflow:test`; צור מחדש את אינדקסי ה-LLM כשההקשר השתנה |
| עזר או סקריפט מבודד                                   | הפעלה/fixtures ממוקדים ובדיקות תחביר או טיפוסים/lint לקוד המושפע                                                    |
| שינוי בסביבת ריצה משותפת, בתלות, בבנייה או באינטגרציה | בדיקות ממוקדות של מה שהושפע, ובנוסף בדיקות הבנייה/טיפוסים/lint הרלוונטיות שלהלן                                     |
| CSS/ערכת נושא/פריסה בלבד                              | נתיבים/גדלי תצוגה/ערכות נושא מושפעים בדפדפנים נבחרים; בנייה כשייבואים, נכסים או עיבוד CSS השתנו                     |
| מצב/אפקטים/ביצועים של React                           | ההתנהגות המושפעת והנחיות React הרלוונטיות; Doctor כשהאבחון שלו מכריע בחשש קונקרטי                                   |

## בדיקות הפרויקט

- `yarn build:verify` בוחר את סביבת העבודה המושפעת. עבור היקף ידוע השתמש ב-`yarn build:about`, ב-`yarn build:chain`, ב-`yarn build:stats-monitor` או ב-`yarn docs:build:verify`.
- `yarn build` מריץ בכוונה את בניית הפרודקשן המלאה של about ושל התיעוד, כולל כל לוקאלי התיעוד. השתמש בו לאימות ברמת שחרור הגרסה כולו או לשינויים שמצדיקים היקף כזה.
- `yarn lint`, `yarn typecheck` ו-`yarn format:check` מכסים את שערי הבדיקה הקיימים של המאגר; בעריכה צרה של סקריפט השתמש קודם בבדיקות התחביר/fixtures/פורמט הממוקדות שלו.
- שינויים במניפסט או ב-lockfile מחייבים `corepack yarn install`, `yarn deps:check-pinned` ו-`yarn deps:check-hardened`. `yarn knip` הוא בגדר המלצה בלבד לגבי תלויות וייבואים.
- בדיקות תרגום התיעוד מפורטות ב-[translations.md](translations.md); אל תריץ את כותב התרגומים הגורף עבור שינוי ממוקד בתיעוד.

## ראיות דפדפן ובעלות

השתמש ב-Chrome לשינויי דפדפן קטנים ומבודדים. הוסף את Firefox ואת WebKit עבור CSS/פריסה/רספונסיביות משותפים, ממשקי API רגישים לדפדפן, אינטראקציות רחבות, שחרורי גרסאות או קריטריונים מפורשים של תאימות בין דפדפנים. כלול פריסות נייד והתנהגות מגע שהושפעו. שינוי גודל של אזור התצוגה לבדו אינו אמולציית מגע. בחר נתיבים ותוכן אמיתיים מתוך קוד המקור במקום להניח שדוגמאות זמינות.

השתמש ב-`playwright-cli` דרך `./scripts/pw-session.sh`. רק דפדפן אחד פעיל בכל המחשב; המנועים הנבחרים רצים בזה אחר זה, וכל סשן שבבעלותך נסגר לפי שמו המדויק גם אחרי כשל. עשה שימוש חוזר בסשן מורשה שבבעלות הגורם הקורא בלי לסגור אותו. לעולם אל תשתמש בניקוי דפדפנים גלובלי ואל תעצור שרת שהבעלות עליו אינה ברורה. עבודה על תיעוד בלבד אינה דורשת דפדפן או שרת.

בעבודת ביצועים, השווה את אותה זרימה עם גודל תצוגה, תוכן, הגדרות רשת/מעבד, מצב בנייה ותקורת מדידה שקולים. הבחן בין תצפיות לבין סיבות חשודות. השתמש ב-skill הפרופיילינג כשהמדידות האלה עונות על הבקשה בפועל.

## ראיות סופיות

סוכן אחד אחראי על האימות הכבד. בדוק את עומסי העבודה הפעילים, והרץ באופן סדרתי התקנות, בניות/חבילות בדיקה מלאות, Doctor, עבודת Android/Electron ופרופיילינג של הדפדפן. דווח על הפקודות ועל התוצאות ועל מגבלות ספציפיות; נתונים חסרים או מנוע שדולג אינם תוצאה עוברת. ה-fixtures של הכלים מאמתים פורמטים ומכניקה, לא את הגילוי בפועל בתוך האפליקציה מקצה לקצה ולא את איכות ההחלטות של המודל.

## בדיקות React אוטומטיות

`yarn agent:verify` מריץ את הבניות שנבחרו ואחריהן את `yarn doctor:check` ואת `yarn perf:check`. `perf:check` כולל את הבדיקה העצמית של תאימות רכיב האיסוף ושל רגרסיה מכוונת, כך שלא CI ולא מסלול האימות של הסוכן זקוקים למעבר `perf:test` נפרד. התקן את כלי הדפדפן המוצמדים פעם אחת עם `yarn perf:install` (`--with-deps` ב-CI של Linux). השתמש במסנני יעד/תרחיש להרצות חוזרות ממוקדות אחרי המעבר המלא הרלוונטי. תקציבי התרחישים מוגדרים במפורש ב-`scripts/react-perf/config.mjs`; שמור את הראיות ותקן רגרסיה לפני שתשקול שינוי מוצדק של קו הבסיס. בניות פרודקשן רגילות אינן כוללות את Bippy; פקודות `build:profile:*` נפרדות מספקות את מכשור הפרופיילינג הרשמי של React.

התרחיש `apps-search` של about מתקדם בקצב של ערכי ה-URL/הקלט שהוחלו בפועל עבור כל תו. תוצאה עוברת שלו מכסה את רצף השאילתות שהוחלו בפועל, לא את ההיענות להקלדה מהירה. השתמש בשחזור נפרד של קלט מהיר כשאתה בודק אובדן תווים או את היענות הקלט.
