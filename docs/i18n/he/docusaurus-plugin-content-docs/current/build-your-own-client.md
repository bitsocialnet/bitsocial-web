# בנו לקוח Bitsocial משלכם

Bitsocial לא מנצחת בזכות אפליקציה רשמית אחת לכל תרחיש שימוש. היא מנצחת כאשר לקוחות רבים יכולים
לחלוק את אותו פרוטוקול ובה בעת להתחרות זה בזה על ממשק, תרבות, גילוי, ברירות מחדל ומודל עסקי.

5chan ו-Seedit הם הוכחות היתכנות מוקדמות, לא תקרה. כל בונה צריך להיות מסוגל להשיק לוח תמונות חדש,
פורום, לקוח פרופילים, אפליקציה חברתית שנבנית קודם כול לנייד, כלי לקהילת נישה או לקוח ריכוזי שמשתמש
ב-Bitsocial מתחת לפני השטח, בלי לבקש רשות מבעלים של פלטפורמה.

## מה בונים יכולים לשנות

לקוח Bitsocial יכול להתחרות על החלטות מוצר בלי לפצל את הרשת כולה:

- ממשק ושפה חזותית
- תהליך ההצטרפות
- ברירות המחדל של הקהילה
- משטחי הניהול
- מודל הגילוי
- חוויית המדיה
- אילוצים של נייד, שולחן עבודה או רוחב פס נמוך
- הפקת הכנסות ומודל עסקי

השכבה המשותפת היא הפרוטוקול. שכבת המוצר פתוחה לתחרות.

## הדרך המהירה ביותר ללמוד

התחילו מהאפליקציות שכבר קיימות:

- נסו את [5chan](https://5chan.app) לקהילות לוח תמונות אנונימיות.
- נסו את [Seedit](https://seedit.app) לדיונים בסגנון Reddit.
- קראו את התיעוד של [Bitsocial React hooks](https://hooks.bitsocial.net/docs/quickstart/) לשילוב בצד הלקוח.
- קראו את התיעוד של [Bitsocial CLI](/developer-tools/cli/) לתפעול צמתים וקהילות.

אם אתם רוצים להתקדם מהר, תרמו קודם לאפליקציה קיימת. אם הממשק, התרבות או מודל הקהילה שאתם רוצים לא
מתאימים לה, בנו לקוח נפרד.

## בחרו גרסה ראשונה צרה

הגרסה הראשונה הטובה ביותר אינה אפליקציה חברתית אוניברסלית. זהו לקוח עם קהל אחד ברור וסיבה חזקה אחת
להתקיים.

נקודות פתיחה טובות כוללות:

- לקוח לוח תמונות נקי יותר עבור תרבות מסוימת אחת
- לקוח פורום שנבנה קודם כול לנייד
- אפליקציה לקהילה בודדת עם ברירות מחדל נוקשות
- לקוח לקהילת יוצרים
- לקוח גילוי לקריאה בלבד
- מסוף ניהול או תפעול
- לקוח שממוטב לשפה, לאזור או לסוג מכשיר

לקוחות קטנים שימושיים משום ש-Bitsocial מאפשרת להם לצמוח לתוך אותה רשת, במקום לכלוא את המשתמשים שלהם
במסד נתונים פרטי.

## מסלולי מימוש

יש שלושה מסלולים מעשיים:

1. פצלו לקוח קיים כשהרעיון שלכם קרוב ל-5chan או ל-Seedit.
2. בנו לקוח React חדש עם [Bitsocial React hooks](https://hooks.bitsocial.net/).
3. בנו שילוב משלכם מעל ממשקי ה-API של הצומת ומעל תשתית RPC ציבורית.

RPC ציבורי אמור להפוך את המסלול השלישי למעשי הרבה יותר. משתמש יכול להתחיל דרך ספק RPC מתארח ולא
משמורתי, ולעבור מאוחר יותר לאירוח עצמי או לספק מתחרה.

## עקרון מנחה

בנו את הלקוח שצריך להתקיים עבור הקהילה שלכם, ואז תנו ללקוחות תואמים להתחרות בפומבי.
